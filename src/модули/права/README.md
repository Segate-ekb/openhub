# права

Что можно принципалу: роли и точечные гранты на хабе, пуле и пакете, группы как носители прав,
право записи в GitHub-репозиторий как ещё один источник права и гварды, которые спрашивают право
на маршрутах. Кто пришёл, решает `вход`; страницы отказа печатает `интерфейс`.

## Публичный интерфейс

| Класс | Для чего | Методы |
| --- | --- | --- |
| `СервисПрав` | действующее право — объединение роли, гранта, группы и GitHub; роли и их ранги; снимок прав на выдачу | `РазрешеноДействие`, `МожетЧитать`, `МожетПисать`, `МожетАдминистрировать`, `МожетСоздаватьПул`, `МожетУдалятьПул`, `МожетНазначатьОсновнойПул`, `РольНаОбъекте`, `РольНаПул`, `РольНеНиже`, `ВыданнаяРольНеНиже`, `ОбластиИзменения`, `СнимокПрав`, `РазрешёнPush`, `ИсточникПраваPush`, `ПользовательАдмин`, `ПулПубличный`, `ОбъектХаб/Пул/Пакет`, `ОписаниеОбъекта`, `Роль*`, `НаборРоли`, `ТипСубъектаПользователь`, `ТипСубъектаГруппа`, `СнятьРолиСубъекта` |
| `СервисПравДоступа` | выдача, отзыв и чтение грантов; объект гранта сверяется с реестром | `ВыдатьРоль`, `ВыдатьГрант`, `ОтозватьГрант`, `ОтозватьГрантыСубъекта`, `ЗафиксироватьГрант`, `МожетВыдаватьГрант`, `ГрантыНаОбъект`, `ГрантыСубъекта`, `РольЗаписи` |
| `ВидимостьОбъектовПрав` | виден ли смотрящему объект строки прав | `Описание`, `Описания`, `Виден` |
| `СервисГрупп` | группы и членство (`local`, `oidc`) | `СоздатьГруппу`, `НайтиГруппу`, `ПоИдентификатору(ам)`, `ВсеГруппы`, `ДобавитьУчастника`, `УдалитьУчастника`, `УчастникиГруппы`, `СоставГруппы`, `ЧислоУчастниковГрупп`, `ГруппыПользователя`, `СнятьЧленстваПользователя` |
| `СлужбаГрупп` | заведение группы и удаление вместе с грантами, ролями и сопоставлениями | `Создать`, `Удалить` |
| `СервисСопоставленийГрупп` | правила «клейм провайдера → группа» и синхронизация членства на входе | `ДобавитьСопоставление`, `УдалитьСопоставление`, `СопоставленияПровайдера`, `ВсеСопоставления`, `СинхронизироватьЧленство`, `ПолитикаВыпавших`, `УстановитьПолитикуВыпавших`, `СинхронизированаВ` |
| `ГвардДоступаКПулу` | вправе ли запрос видеть пул, какие пулы ему называть, открыт ли пул изменению | `Проверить`, `ЧитаемыйПул`, `ЧитаемыеИзНабора`, `ПулДляИзменения`, `ЧитаемыеПулы`, `НазванныеПулы` |
| `ГвардКвотыПула` | квоту пула назначает только администратор хаба | `МожетМенятьКвоту`, `ПричинаОтказа`, `КодОтказа` |
| `ВердиктГварда` | форма ответа гварда | `Пропуск`, `Отказ`, `ПоляПринципала` |
| `УчёткаПринципала` | учётка за принципалом запроса | `Пользователь`, `ЭтоКлюч` |
| `ДопускЗапроса` (контракт) | принципал запроса и рамки его ключа для гварда пула; реализует `вход` | `Принципал`, `КлючЧитает`, `КлючТрогает` |
| `ОпознаниеGitHub` (контракт) | человек на GitHub: логин и имя владельца токена, имя по логину из публичного профиля; реализация `ОпознаниеGitHubHTTP`, спрашивают `публикация` (владелец токена) и `подписки` (имя публикатора) | `Владелец`, `Имя` |

Кто судит что: гварды модуля отвечают правом — `ГвардДоступаКПулу` видимостью пула и дверью его
изменения, `ГвардКвотыПула` правом назначать квоту. Кто стоит за запросом и куда его пускают рамки
ключа, гвард пула спрашивает контрактом `ДопускЗапроса` — судит `вход` (`ДопускЗапросаКПулу`).
Страницу отказа печатают гварды экранов в `интерфейс`.

Реализации чужих контрактов: `ПраваНаУдаляемое` (`ПоследствияУдаленияПула`, `ПоследствияУдаленияПакета`
реестра), `ИменаОбъектовПрав` (`ИменаОбъектовАудита`), `ОписанияСобытийПрав` (`ОписанияСобытий`).

## Зависимости

Использует: `основа`, `данные`, `сеть`, `события`, `аудит`, `настройки`, `реестр` (`СервисПулов`,
`СервисПакетов`); библиотеки `autumn-data`, `url`.
Используется: `api`, `вход`, `зеркала`, `интерфейс`, `кабинет`, `подписки`, `поиск`, `публикация`,
`состояние`; реализации контрактов собирают `реестр`, `аудит`, `события`.

## Настройки

Своих ключей модуль не объявляет. Проверка права записи в GitHub читает ключи `публикация`:
`oshub.publish.github_legacy` (включён ли путь «GitHub-токен вместо роли») и `oshub.publish.github.org`
(организация зеркала); адрес API — деталька `oshub.publish.github.api` (умолчание `api.github.com`).
Имена пользователей GitHub по логину помнит кэш `именаGitHub` (autumn-cache): без токена GitHub
отвечает одному адресу ограниченное число раз в час; срок записи — `cache.именаGitHub.СрокЖизни`
(умолчание хаба — сутки). После сбоя (сеть, код ответа не 200 и не 404) GitHub пять минут об именах
не спрашивают.

## Где что лежит

| Каталог | Что внутри |
| --- | --- |
| `Классы/модель/` | `СервисПрав`, `СервисПравДоступа`, `ВидимостьОбъектовПрав`, `УчёткаПринципала`; таблицы грантов (`ПравоДоступа`) и ролей на пуле (`УчастникПула`); снятие прав удаляемого пула и пакета; события прав |
| `Классы/группы/` | группы, членство и сопоставления с клеймами провайдера, их таблицы; имена групп для журнала аудита |
| `Классы/гварды/` | гварды пула и квоты, форма их ответа, контракт `ДопускЗапроса` |
| `Классы/github/` | контракты `ПроверяющийGitHub`, `ОпознаниеGitHub` и их реализации поверх GitHub REST |

## Инварианты

- Право только складывается: роль, грант, группа и GitHub объединяются, запрещающих правил нет.
- Гейты спрашивают право (`РазрешеноДействие`, `РольНеНиже`), а не роль учётки.
- Роль администратора хаба — надстройка над выданным: её назначение и снятие строк прав не трогают,
  а автоматика, решая, записать ли человеку право, спрашивает выданное (`ВыданнаяРольНеНиже`), а не
  суперправо. С ролью хаба уходит только суперправо.
- Объект гранта сверяется с реестром: пул пакета берётся из пакета, а не из запроса.
- Гвард пула не различает «пула нет» и «пул не виден»: оба ответа — отказ.
- Уникальность гранта «субъект + объект» держит `СервисПравДоступа`, а не база.
- Опознание GitHub не бросает: сбой даёт пустой логин, а имя по логину — `Неопределено`, которое
  кэш не запоминает.
- Имя из профиля — строка текста: управляющие (C0, DEL, C1), разрывы строк Юникода, смена
  направления письма и прочие символы формата становятся пробелом (ZWJ и ZWNJ остаются — они
  склеивают знаки эмодзи и письма), пробелы схлопываются, длина — не больше ста символов, эмодзи
  на границе не разрезается.
- Тип субъекта в строке права — один на модуль: `СервисПрав.ТипСубъектаПользователь` и
  `ТипСубъектаГруппа`; уход субъекта снимает и его гранты, и роли на пулах.
