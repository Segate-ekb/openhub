# настройки

Настройки инсталляции: реестр ключей, собранный из объявлений модулей, чтение значения по цепочке
«конфигурация → база → умолчание кода», правка прикладных настроек с журналом аудита, раздел дома «Хаб»
для каждого ключа, внешний адрес и статика инсталляции, картинки оформления. Какие ключи бывают,
решают модули-хозяева; экраны настроек печатает `интерфейс`.

## Публичный интерфейс

| Класс | Для чего | Методы |
| --- | --- | --- |
| `СервисНастроек` | действующее значение и его источник, правка и сброс прикладной настройки, карточки для экранов и API | `Целое(Ключ, Дефолт, Минимум)`, `Флаг(Ключ, Дефолт)`, `Текстом(Ключ, Дефолт)`, `Значение`, `Источник`, `ФорсированаКонфигом`, `Установить`, `УстановитьМеханизмом`, `Сбросить`, `Известна`, `Карточка`, `Карточки` |
| `КлючиНастроек` (контракт) | ключи предмета; реализации `КлючиНастроек<Предмет>` у модулей-хозяев, `РеестрНастроек` собирает их массивом | `Объявления()` |
| `ОбъявленияНастроек` | объявления, которыми предмет отвечает на контракт | `Объявить`, `ОбъявитьСекрет`, `ПравитМеханизм`, `Ключи`, `Механизмы` |
| `ВидыПроверок` | декларативные проверки значений для объявлений | `Перечисление`, `Минимум`, `Диапазон`, `Адрес`, `Сети`, `Цвет`, `НеБольшеЧем`, `НеМеньшеЧем` |
| `РеестрНастроек` | описание ключа и имя его переменной окружения | `Описание`, `ПеременнаяОкружения`, `Ключи`, `Есть` |
| `РазделыНастроекХаба` | раздел дома «Хаб», которому принадлежит ключ: его показывают экран и поле `section` в `GET /api/v1/admin/settings` | `РазделКлюча` |
| `ИменаПеременныхОкружения` | имя переменной окружения ключа и закрытый список псевдонимов | `Переменная`, `ПоКонвенции`, `РодноеИмя`, `Псевдонимы`, `ПсевдонимЦели` |
| `АдресИнстанса` | внешний адрес хаба и выведенный из него адрес возврата провайдеров входа | `Базовый`, `Задан`, `АдресВозврата`, `ПутьВозврата`, `Нормализовать`, `Ключ` |
| `ОписаниеПриложения` | имя и версия приложения из `packagedef` | `Имя`, `Версия` |
| `СтатикаХаба` | статика инсталляции — реализация контракта кита `СтатикаИнсталляции` | `Файлы`, `Файл*`, `Тип*`, `Каталог` |
| `СервисБрендовыхАктивов` | картинки оформления, загруженные администратором: знак и иконка сайта | `Ключи`, `Сведения`, `Содержимое`, `ПубличноеИмя`, `КлючПоПубличномуИмени`, `Загрузить`, `Сбросить`, `ПотолокБайт` |

Предмет объявляет свои ключи так:

```bsl
&Прозвище("КлючиНастроек")
&Желудь
Процедура ПриСозданииОбъекта(&Пластилин(Значение = "ВидыПроверок") _Правила,
	&Деталька(Значение = "oshub.incidents.ttl.sec", ЗначениеПоУмолчанию = "") _Срок = "") Экспорт
	Ключи = Новый ОбъявленияНастроек();
	Ключи.Объявить("oshub.incidents.ttl.sec", "целое", 1209600, _Правила.Минимум(60), "bootstrap", _Срок);
КонецПроцедуры
```

## Зависимости

Использует: `основа`, `данные`, `события`, `аудит`; библиотеки `autumn-data`, `entity`, `packageinfo`.
Используется: почти все модули читают значения через `СервисНастроек` и объявляют ключи через
`ОбъявленияНастроек`/`ВидыПроверок`; `api` и `интерфейс` — карточки, разделы и картинки; `запуск` —
имена переменных окружения и описание приложения.

## Настройки

| Ключ | Умолчание | Что делает |
| --- | --- | --- |
| `oshub.instance.url` | пусто | внешний адрес хаба `схема://хост[:порт]`; из него выводятся адреса возврата провайдеров и ссылки писем |
| `oshub.ui.asset.max_bytes` | `1048576` | потолок размера загружаемой картинки оформления |

Класс `bootstrap` меняется только конфигурацией; `прикладная` правится с экрана и API, пока её
не задала конфигурация.

## Где что лежит

| Каталог | Что внутри |
| --- | --- |
| `Классы/` | реестр ключей (контракт, объявления, проверки, валидатор, имена переменных окружения), служба настроек и таблица прикладных настроек, разделы дома «Хаб», адрес и статика инсталляции, описание приложения, картинки оформления и их таблица, ключи и события самого модуля |

`РазделыНастроекХаба` знает ключи всех модулей префиксами: раздел ключа — часть карточки настройки,
которую отдают и экран, и API, поэтому он живёт здесь, а не у экрана. Ярус ключа «над катом / под
катом» нужен только экрану и живёт в `интерфейс`.

## Инварианты

- Ключ объявляет ровно один модуль: дубль роняет сборку реестра; незнакомый ключ читается умолчанием вызывающего с предупреждением в журнал.
- Значение из конфигурации сильнее базы: форсированную настройку экран и API не правят.
- Настройку с механизмом правки пишет только названный механизм (`УстановитьМеханизмом`).
- Секрет наружу — маской: в карточке, журнале и отладке.
- Одна строка таблицы на ключ, ключ в каноне; уникальность держит хранилище, а не база.
- Кэши `СервисНастроек` и `СервисБрендовыхАктивов` делят потоки запросов: поиск, запись и забывание
  записи — под замком, база спрашивается вне его; правка забывает свою запись сразу.
