# зеркала

Плановая репликация чужого хаба в свой пул: запись зеркала, очередь и фоновый рабочий, обход источника
порциями с курсором, перенос версий в пул назначения и причины, по которым версия не приехала; здесь же
регулярный обход здоровья источников пулов и зеркал. Выдача пакета через апстрим пула — модуль `прокси`;
в реестр версии зеркало кладёт той же дверью приёма, что и публикация.

## Публичный интерфейс

| Класс | Для чего | Методы |
| --- | --- | --- |
| `СервисЗеркал` | зеркала пула назначения: заведение, правка, токен, снятие; состояние прогона по записи | `СписокПула(ПулНазначенияИдентификатор)`, `Создать(Пользователь, Пул, АпстримURL, ФильтрJSON, ИнтервалСинкаСек, Токен, Перенос)`, `Переключить(Пользователь, Пул, Идентификатор, Включено)`, `ЗадатьТокен(Пользователь, Пул, Идентификатор, Токен)`, `СнятьТокен(Пользователь, Пул, Идентификатор)`, `Удалить(Пользователь, Пул, Идентификатор)`, `ЗеркалоПула(Пул, Идентификатор)`, `Протокол(Зеркало)`, `СостояниеПрогонаПоЗаписи(Зеркало)`, `ПрогонБрошен(Зеркало)` |
| `ОчередьСинхронизацииЗеркал` | заявки «синхронизировать сейчас» и что очередь знает о зеркале | `Поставить(ЗеркалоИдентификатор, ЗапустилИдентификатор)`, `Состояние(ЗеркалоИдентификатор)`, `СостояниеПоЗаписи(Зеркало)`, `Размер()` |
| `ПричиныЗеркала` | почему текущий обход не привёз версии; бросает на лежащей базе | `Обхода(Зеркало)` |
| `РазборНастроекЗеркала` | канон протоколов источника | `Протокол(Значение)`, `ПротоколOpenHub()`, `ПротоколЛегаси()` |
| `СчётчикиОбхода` | «обработано» и доля обхода по записи зеркала | `ОбработаноПоЗаписи(Зеркало)`, `ДоляОбходаПоЗаписи(Зеркало)` |
| `СрезОбхода` | способ обхода словом: полный либо с момента | `ПоМоменту(СрезС)` |

Только то, что зовут другие модули. Всё остальное — внутреннее.

Реализует контракты: `ЗеркалаПула` (`РаботающиеЗеркалаПула`), `ПоследствияУдаленияПула` (`ЗеркалаУдаляемогоПула`),
`ЗадачаПланировщика` (`ЗадачаСинхронизацииЗеркал` — `синхронизация-зеркал`, `ЗадачаЗдоровьяИсточников` —
`здоровье-источников`), `КлючиНастроек` (`КлючиНастроекЗеркал`), `КодыПроисшествийПодсистемы`
(`КодыПроисшествийЗеркала`, подсистема `зеркало`), `ОписанияСобытий` (`ОписанияСобытийЗеркал`).
Протоколы чтения источника собираются массивом по прозвищу `ИсточникАпстрима` внутри модуля.

## Зависимости

Использует: `основа`, `данные`, `наблюдаемость`, `настройки`, `аудит`, `события`, `происшествия`, `сеть`,
`фоновыеЗадания`, `хранилище`, `права`, `реестр`, `прокси`; библиотеки `ospx-tools`, `url`, `errors`,
`autumn-opentelemetry`.
Используется: `api`, `интерфейс`, `состояние`; `реестр` — через контракты `ЗеркалаПула` и `ПоследствияУдаленияПула`.

## Настройки

Из интерфейса правится только рубильник; остальное — часть развёртывания (`bootstrap`). Пределы приёма
пакета у зеркала свои не заводятся — действуют `oshub.publish.max_*`.

| Ключ | Умолчание | Что делает |
| --- | --- | --- |
| `oshub.mirror.sync_enabled` | `true` | ведёт ли хаб синхронизацию зеркал |
| `oshub.mirror.max_per_pool` | `5` | зеркал на пул |
| `oshub.mirror.default_interval_sec` | `3600` | период синхронизации зеркала, не задавшего свой |
| `oshub.mirror.min_interval_sec` | `60` | нижняя граница периода зеркала |
| `oshub.mirror.run_stale_sec` | `300` | через сколько секунд молчания прогон считается брошенным |
| `oshub.mirror.max_packages_per_cycle` | `25` | имён за один цикл обхода |
| `oshub.mirror.max_cycles_per_run` | `20` | циклов за плановый прогон |
| `oshub.mirror.queue_max` | `100` | потолок очереди заявок |
| `oshub.mirror.cycles_per_turn` | `20` | циклов рабочего за один заход в очередь |
| `oshub.mirror.queue_poll_sec` | `2` | как часто рабочий заглядывает в очередь |
| `oshub.jobs.mirror_sync_interval_sec` | `3600` | период постановки включённых зеркал в очередь |
| `oshub.jobs.upstream_health_interval_sec` | `60` | период обхода здоровья источников |

## Где что лежит

| Каталог | Что внутри |
| --- | --- |
| `настройка/` | сущность и хранилище зеркал, служба зеркал, канон адреса, фильтра, интервала и протоколов, числа из настроек и их объявление, пределы приёма, снятие зеркал удаляемого пула |
| `очередь/` | очередь заявок, фоновый рабочий, плановая задача постановки, подбор прогонов, оборванных прошлым запуском хаба |
| `синхронизация/` | движок обхода, перенос одного элемента, состояние прогона и его захват, дроссель прогресса, снимки пула на порцию, изменяемый слот, счётчики и срез обхода, происшествия и причины, событие о закрытом обходе, коды происшествий и описания событий, ответ реестру «пул наполняется» |
| `апстрим/` | чтение источника: протокол среза изменений OpenHub и легаси-список opm, корень выдачи, разбор привезённого `.ospx` |
| `здоровье-источников/` | регулярная проба включённых апстримов пулов и зеркал, исход — в память `прокси/СтражАпстримов` |

## Инварианты

- Протокол источника определяет проба на каждом обходе — срез изменений, затем легаси-список; не ответил ни один — прогон закрыт ошибкой с причиной.
- Один прогон на зеркало: обход ведёт единственный рабочий очереди, брошенный прогон перехватывается по порогу молчания.
- Невзятая версия называет причину журналу и происшествием; первая причина с кодом в обходе — предупреждение, повторы — отладка.
- Метка обхода — момент его начала; момент вычитки двигается, только когда обход прошёл весь срез без потерь.
- Приезжающая версия идёт через `реестр/ПриёмВерсии` и квоту пула; заменяется только изменяемый слот источника, когда сменились байты.
