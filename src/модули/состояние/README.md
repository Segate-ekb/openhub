# состояние

Что сейчас с хабом: жив ли он, готов ли принимать трафик, сколько работает, что у него внутри
в числах и не вышла ли его новая версия — пробы `/health` и `/ready`, числа хаба, доменные приборы
OpenTelemetry и проверка выпусков у hub.oscript.io. Сценарий
поверх предметов: спрашивает многих, снизу его не зовёт никто. Признак готовности
`ГотовностьХаба`, который нужен предметам, живёт в `наблюдаемость`.

## Публичный интерфейс

| Класс | Для чего | Методы |
| --- | --- | --- |
| `ЖивостьХаба` | тело пробы живости и шапка чисел: статус, версия, аптайм, состояние базы | `Сводка()`, `Шапка()` |
| `ЧислаХаба` | числа работающего хаба одним снимком; несосчитанное число — `-1` | `Снимок()`, `Посчитано(…)` |
| `ВыпускиХаба` | вышла ли версия хаба новее своей: проверка у источника и что известно по последней | `Проверить()`, `Сведения()`, `КлючПроверки()`, `КлючИсточника()`, `ИсточникПоУмолчанию()` |

`ЖивостьХаба` и `ЧислаХаба` зовёт `api` (`/api/v1/health`, `/api/v1/metrics`), `ВыпускиХаба.Сведения` —
`интерфейс` (дом «Хаб»); остальное — внутреннее.

Реализации чужих контрактов: `ЗадачаПроверкиВыпуска` — `ЗадачаПланировщика` (`фоновыеЗадания`),
`КлючиНастроекВыпусков` — `КлючиНастроек` (`настройки`), `ОписанияСобытийВыпусков` — `ОписанияСобытий`
(`события`).

## Зависимости

Использует: `основа`, `сеть`, `данные`, `наблюдаемость`, `настройки`, `события`, `реестр`, `права`, `вход`,
`статистика`, `подписки`, `зеркала`, `фоновыеЗадания`; библиотеки `autumn-data`, `entity`, `opentelemetry`,
`errors`, `semver`.
Используется: `api`, `интерфейс`.

## Настройки

| Ключ | Умолчание | Что делает |
| --- | --- | --- |
| `oshub.updates.check` | `true` | спрашивать ли раз в сутки источник выпусков; хаб без выхода в интернет её выключает |
| `oshub.updates.source` | `https://hub.oscript.io/api/v1/pools/default/packages/openhub` | карточка пакета OpenHub в API хаба пакетов: последняя версия — поле `package.latest_version`, страница для человека — тот же адрес без `/api/v1`; проверка `ВидыПроверок.АдресРесурса` (https/http, хост, путь, без данных пользователя) |

Оба ключа правятся с экрана «Обслуживание» дома «Хаб» и действуют со следующей проверки.

## Где что лежит

| Каталог | Что внутри |
| --- | --- |
| `пробы/` | живость и готовность (`КонтроллерЗдоровья`, `КонтроллерГотовности`, `ЖивостьХаба`), аптайм (`СостояниеХаба`), проба базы без очереди за соединением (`ПробаБазы`), числа хаба (`ЧислаХаба`, `РазмерыПубличногоРеестра`); снаружи — `GET /health`, `GET /ready`, `GET /api/v1/metrics` |
| `телеметрия/` | доменные приборы: датчики снимают числа хаба раз в интервал экспорта, счётчики растут на шине событий (`ПриборыХаба`); снаружи — экспорт метрик в коллектор OTel |
| `выпуски/` | новая версия хаба: источник выпусков (`ИсточникВыпусков` — GET через `ТранспортHTTP`), порядок semver (`НовизнаВыпуска`), отметка последней проверки и её таблица (`ОтметкаВыпуска`, `ХранилищеОтметокВыпуска`), служба (`ВыпускиХаба`), задача планировщика, ключи настроек и событие «Вышла новая версия хаба» |

## Инварианты

- `/health` отвечает 200, пока процесс жив; отказ базы — дело `/ready` (503), а не живости.
- Проба базы не встаёт в очередь за соединением: исчерпанный пул она называет по снимку.
- Адрес чисел и приборы читают один `ЧислаХаба`; сорванное число — `-1`, а не исключение.
- Имён пакетов и версий в метриках нет: их кардинальность ничем не ограничена.
- Источник выпусков спрашивает только задача планировщика: через 300 с после старта и раз в сутки.
  Экран читает отметку и в сеть не ходит.
- Новее — только строго старшая версия semver: пре-релиз младше своего релиза (`0.21.0` новее
  `0.21.0-ui.9`, `0.20.6` — нет), негодная строка новой не бывает.
- О каждой версии событие уходит один раз: объявленная версия лежит в отметке и переживает рестарт;
  отметка пишется до события.
- Отказ источника — причина в отметке и строка в журнале; задача не падает, происшествия нет. Негодный
  адрес (не https/http, без хоста, с данными пользователя, с пробелом) наружу не спрашивается, ответ
  больше 1 МБ не разбирается; в журнале, отметке и на кнопке адрес — без данных пользователя.
- Сбой хранилища отметки перебрасывается: прогон задачи журнал называет упавшим.
