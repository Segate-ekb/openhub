# подписки

Подписка объекта — хаба, пула или пакета — на его события и доставка события адресату: вебхуком
или сообщением в Telegram. Подписка отбирает версии по тегам, а подписку хаба или пула, если её
хозяин разрешил, нижестоящий пул или пакет сужает для себя поправкой. Модуль держит подписки,
поправки, очередь доставок и каналы; сами события публикуют предметы через `события`, а форму
подписки рисует `интерфейс`.

## Публичный интерфейс

| Класс | Для чего | Методы |
| --- | --- | --- |
| `СервисПодписок` | подписки объекта с проверкой права на каждой мутации | `ОбъектХаба`, `ОбъектПула`, `ОбъектПакета`, `ИзвестныеТипы`, `ТипДействияПодписки`, `МожетУправлять`, `Список`, `Создать`, `СоздатьПодписку`, `ЗначенияПравки`, `МожноПравить`, `ОбновитьПодписку`, `МожноПробовать`, `Проверить`, `Переключить`, `Удалить` |
| `РеестрДействийПодписок` | каналы доставки: какие есть, их хранение и форма | `Типы`, `Хранение`, `РендерНастроек`, `ПравкаПоддержана`, `ПробаПоддержана` |
| `КаталогСобытий` | перечень событий хаба словами и параметр подписки на событие | `Запись`, `ПараметрПодписки` |
| `ПараметрыПодписки` | параметр события и общие свойства подписки: название, разрешение сужать снизу, отбор по тегам | `Значение`, `Свойства`, `ПустыеСвойства` |
| `СервисПоправокПодписок` | подписки сверху нижестоящего объекта и его поправки к ним, кто сузил подписку | `ПодпискиСверху`, `ПодпискаСверху`, `ПоправкаОбъекта`, `Поставить`, `Снять`, `ПоправкиПодписки`, `ОставленныеСобытия` |
| `СлужбаДоставкиПодписок` | размер очереди для чисел хаба | `РазмерОчереди` |

Контракты каналов собирает `РеестрДействийПодписок` массивами по прозвищу; форму канала `интерфейс`
строит по `РендерНастроекПодписки`. Новый канал — каталог `обработчики/<канал>/` с тремя
реализациями, ядро при этом не правится:

| Контракт | Методы |
| --- | --- |
| `ОбработчикДоставкиПодписки` | `ТипДействия`, `ПередДоставкой`, `Доставить`; необязательный `Проба` |
| `ХранениеПодписки` | `ТипДействия`, `ПодготовитьНастройки`, `НастройкиДоставки`; необязательная пара `ЗначенияПравки` + `ПодготовитьПравку` |
| `РендерНастроекПодписки` | `ТипДействия`, `КлючПодписи`, `КлючПояснения`, `ОписаниеПолей` |

Реализации чужих контрактов: `ПодпискиНаУдаляемое` — `ПоследствияУдаленияПула` и
`ПоследствияУдаленияПакета` (`реестр`), `КлючиНастроекПодписок` — `КлючиНастроек` (`настройки`),
`ОписанияСобытийПодписок` — `ОписанияСобытий` (`события`).

Только то, что зовут другие модули. Всё остальное — внутреннее.

## Зависимости

Использует: `основа`, `сеть`, `данные`, `наблюдаемость`, `фоновыеЗадания`, `события`, `аудит`,
`настройки`, `реестр`, `права`, `вход`; библиотеки `autumn-data`, `entity`, `pwhash`, `oint`.
Используется: `api`, `интерфейс`, `состояние`, `реестр` (последствия удаления), `настройки`.
Из `реестр` отбор по тегам спрашивает `КаналыПоУмолчанию.КаналыВерсии` и
`СервисТегов.ИмяДопустимо`.

## Настройки

| Ключ | Умолчание | Что делает |
| --- | --- | --- |
| `oshub.webhooks.delivery_enabled` | `true` | рубильник фоновой доставки |
| `oshub.webhooks.allow_insecure` | `false` | принимать адрес вебхука по http |
| `oshub.webhooks.max_queue` | `10000` | предел незавершённых заданий в очереди |
| `oshub.webhooks.max_attempts` | `5` | попыток доставки одного задания |
| `oshub.webhooks.backoff_base_sec` | `10` | основание отсрочки между попытками |
| `oshub.webhooks.delivery_interval_sec` | `5` | как часто фон разбирает очередь |
| `oshub.webhooks.delivery_timeout_sec` | `10` | срок одной отправки вебхука |
| `oshub.webhooks.test_max_per_hour` | `100` | пробных отправок в час на подписку |
| `oshub.webhooks.telegram.proxy.host` | пусто | прокси до Bot API; пусто — напрямую |
| `oshub.webhooks.telegram.proxy.port` | `3128` | порт прокси |
| `oshub.webhooks.telegram.proxy.user` | пусто | учётка прокси |
| `oshub.webhooks.telegram.proxy.password` | пусто | пароль прокси (секрет) |

Ответа Bot API отправка Telegram ждёт общий срок запросов через oint — `oshub.storage.s3.timeout.sec`
(30 с); его ставит на старте рогатка `УстановкаСрокаОтветаOint` модуля `хранилище`.

## Где что лежит

| Каталог | Что внутри |
| --- | --- |
| `подписка/` | сущность подписки и её таблица, `СервисПодписок`, параметры по событиям и общие свойства, `РеестрДействийПодписок`, `КаталогСобытий`, отбор доставки (порог заполнения пула, теги, поправки), снятие подписок и поправок удаляемых пула и пакета |
| `поправка/` | сущность поправки к подписке сверху и её таблица, `СервисПоправокПодписок` |
| `доставка/` | подписчик доменных событий, служба доставки и фоновый цикл, очередь в базе и её таблица, тело события и текст уведомления, имена публикаторов из GitHub, числа доставки |
| `адрес/` | форма адреса вебхука: схема, userinfo, хост |
| `проба/` | потолок пробных отправок и их запись в журнал аудита |
| `обработчики/` | контракты канала: доставка, хранение, форма |
| `обработчики/вебхук/`, `обработчики/telegram/` | канал целиком: доставка, хранение, описание полей формы; у Telegram — транспорт Bot API, тело сообщения, превью ссылки и прокси |
| `общее/` | ключи настроек и описания событий подписок |

## Тело доставки

Тело — JSON одной строкой, одно для вебхука и для текстовых каналов: `тип`, `пул`, `пакет`,
`версия`, `время`, `кто`, `публикатор`, `как`, `автор`, `репозиторий`, `ссылка`, `релиз`,
`отозвана`, `проба`, `процент`. `кто` — публикатор так, как его пишет журнал аудита (логин учётки,
`github:<логин>`, `ci:<репозиторий>`); `публикатор` — человек: «Имя (логин)», без имени — логин;
`как` — «учётка хаба», «токен GitHub» или «доверенная публикация»; `релиз` — страница релиза
GitHub из запуска конвейера, принявшего версию (`реестр`, `СервисЗапусковКонвейеров`), пусто —
версия не из релиза. Тело собирается при постановке задания. Имя того, кто запустил доверенный
конвейер на github.com, событие не знает: его дочитывает `ИменаПубликаторов` у GitHub (контракт
`ОпознаниеGitHub` из `права`) в фоне доставки, после проверки задания и до отправки, — логин
берётся из запуска, принявшего версию тела. Вебхук подписывает и шлёт уже дочитанное тело, текст
Telegram разворачивается по нему же. Запуска на github.com нет, GitHub не ответил или имени
в профиле нет — публикатор назван логином.

В шаблоне текста `{кто}` — `публикатор` тела, а у события без публикатора — `кто`; `{как}` и
`{релиз}` — одноимённые поля. Текст по умолчанию называет публикатора и способ строкой
«Опубликовал: …» и страницу релиза строкой «Релиз: …».

## Инварианты

- Мутация подписки проходит проверку права на объект; чужой объект — отказ.
- Событие доставляется подписке, если проходит её отбор и поправку пула и пакета события:
  поправка только сужает. Флажок «нижестоящие могут сузить» снят — поправки не действуют,
  но хранятся; подписка удалена — её поправки уходят с ней.
- Поправку ставит тот, кто распоряжается подписками нижестоящего объекта; она не даёт права
  на саму подписку, а подписку без разрешения сужать нижестоящий не видит вовсе.
- У пары «подписка — объект» поправка одна: повторная правит прежнюю.
- Отбор по тегам судит только события версии: версия проходит, если в момент события входит
  в состав тега так, как его видит служба тегов; проба доставки отбора не проходит.
- Задание уходит с настройками, снятыми на момент события, а не прочитанными при доставке.
- Публикация не ждёт GitHub: имя публикатора дочитывается в фоне доставки, логин запустившего
  конвейер берётся из запуска, принявшего версию тела (`реестр`), а не из полей тела.
- Проба и боевая доставка идут одним телом и одной отправкой.
- Сообщение Telegram о версии уходит с превью крупной картинкой: адрес — первый годный из
  страницы релиза, страницы версии в хабе (пул открыт гостю и задан внешний адрес хаба)
  и репозитория. Годен только http(s) без данных пользователя, пробелов и управляющих символов.
  Нет ни одного, событие не о версии или это проба — превью выключено явно. Тело вебхука
  превью не касается.
- Секрет вебхука показывается создателю один раз и в ответы и журнал не попадает.
- Очередь живёт в базе и переживает перезапуск; сбой одного задания не останавливает разбор партии.
