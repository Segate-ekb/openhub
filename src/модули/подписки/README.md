# подписки

Подписка объекта — хаба, пула или пакета — на его события и доставка события адресату: вебхуком
или сообщением в Telegram. Подписка пула и пакета отбирает версии по тегам своего объекта; у
подписки хаба или пула есть дерево получателей — пулы и пакеты, о которых она сообщает, — и её
хозяин задаёт каждому пулу режим: весь пул, только выбранные пакеты или никакие;
нижестоящий пул или пакет, если хозяин разрешил, сужает подписку для себя поправкой; пул в поправке
к подписке хаба ещё и снимает галки со своих пакетов. Модуль держит подписки, исключения и выбор
дерева получателей, поправки, очередь доставок и каналы; сами события публикуют предметы
через `события`, а форму подписки рисует `интерфейс`.

строит по `РендерНастроекПодписки`. Новый канал — каталог `обработчики/<канал>/` с тремя
реализациями, ядро при этом не правится:

| Контракт | Методы |
| --- | --- |
| `ОбработчикДоставкиПодписки` | `ТипДействия`, `ПередДоставкой`, `Доставить`; необязательные `Проба` и `Предпросмотр` |
| `ХранениеПодписки` | `ТипДействия`, `ПодготовитьНастройки`, `НастройкиДоставки`; необязательная пара `ЗначенияПравки` + `ПодготовитьПравку` |
| `РендерНастроекПодписки` | `ТипДействия`, `КлючПодписи`, `КлючПояснения`, `ОписаниеПолей` |

Реализации чужих контрактов: `ПодпискиНаУдаляемое` — `ПоследствияУдаленияПула` и
`ПоследствияУдаленияПакета` (`реестр`), `КлючиНастроекПодписок` — `КлючиНастроек` (`настройки`),
`ОписанияСобытийПодписок` — `ОписанияСобытий` (`события`). Рогатка старта `ПереводПолучателейПриСтарте`
переводит пулы «все» с исключёнными пакетами в «выбранные» (`ПеревестиВсеСИсключениями`), каждую подписку —
записью `получатели.переведены` в журнал аудита.

Только то, что зовут другие модули. Всё остальное — внутреннее.

## Зависимости

Использует: `основа`, `сеть`, `данные`, `наблюдаемость`, `фоновыеЗадания`, `события`, `аудит`,
`настройки`, `реестр`, `права`, `вход`; библиотеки `autumn-data`, `entity`, `pwhash`, `oint`.
Используется: `api`, `интерфейс`, `состояние`, `реестр` (последствия удаления), `настройки`.
Из `реестр` отбор по тегам спрашивает `КаналыПоУмолчанию.КаналыВерсии` и
`СервисТегов.ИменаТеговПула`, `ИменаТеговПакета`, дерево получателей — `СервисПулов` и `СервисПакетов`,
образец предпросмотра — `СервисПулов.ПулПоИдентификатору`, `СервисПакетов.ПакетПоИдентификатору`
и `СервисВерсий.ПоследняяВерсия`.

## Настройки

| Ключ | Умолчание | Что делает |
| --- | --- | --- |
| `oshub.webhooks.delivery_enabled` | `true` | рубильник фоновой доставки |
| `oshub.webhooks.allow_insecure` | `false` | принимать адрес вебхука по http |
| `oshub.webhooks.max_queue` | `10000` | предел незавершённых заданий в очереди |
| `oshub.webhooks.max_attempts` | `5` | попыток доставки одного задания |
| `oshub.webhooks.backoff_base_sec` | `10` | основание отсрочки между попытками |
| `oshub.webhooks.delivery_interval_sec` | `5` | как часто фон разбирает очередь |
| `oshub.webhooks.delivery_timeout_sec` | `10` | срок одной отправки вебхука |
| `oshub.webhooks.test_max_per_hour` | `100` | пробных отправок в час на подписку; у незаведённой — на автора и объект |
| `oshub.webhooks.telegram.proxy.host` | пусто | прокси до Bot API; пусто — напрямую |
| `oshub.webhooks.telegram.proxy.port` | `3128` | порт прокси |
| `oshub.webhooks.telegram.proxy.user` | пусто | учётка прокси |
| `oshub.webhooks.telegram.proxy.password` | пусто | пароль прокси (секрет) |

Ответа Bot API отправка Telegram ждёт общий срок запросов через oint — `oshub.storage.s3.timeout.sec`
(30 с); его ставит на старте рогатка `УстановкаСрокаОтветаOint` модуля `хранилище`.

## Заголовки вебхука

POST вебхука несёт `X-OpenHub-Event` — код события, `X-OpenHub-Delivery` — идентификатор
доставки (один у всех повторов задания) и `X-OpenHub-Signature: sha256=<HMAC-SHA256 тела по
секрету подписки>`. Коды событий:

| Код | Событие (`тип` в теле) |
| --- | --- |
| `version.published` | версия опубликована (`версия.опубликована`) |
| `version.yanked` | версия отозвана (`версия.отозвана`) |
| `version.restored` | отзыв снят (`версия.восстановлена`) |
| `pool.filling` | пул заполняется (`пул.заполнен`) |
| `hub.version.released` | вышла новая версия хаба (`хаб.версия.вышла`) — только у подписки хаба |

Пробная доставка с экрана уходит с кодом события образца и `"проба": true` в теле.

Код объявляет предмет рядом с событием (`ОбъявленияСобытий.ОбъявитьПодписочное`); у подписочного
события он обязателен, коды в каталоге не повторяются.

## Тело доставки

Тело — JSON одной строкой, одно для вебхука и для текстовых каналов: `тип`, `пул`, `пакет`,
`версия`, `текущая`, `время`, `кто`, `публикатор`, `как`, `автор`, `репозиторий`, `ссылка`, `релиз`,
`отозвана`, `проба`, `процент`. У новой версии хаба пула, пакета и публикатора нет: `версия` —
вышедшая, `текущая` — версия этого хаба, `ссылка` — страница пакета у источника выпусков
(`состояние/ВыпускиХаба`); у остальных событий `текущая` пуста. `кто` — публикатор так, как его пишет журнал аудита (логин учётки,
`github:<логин>`, `ci:<репозиторий>`); `публикатор` — человек: «Имя (логин)», без имени — логин;
`как` — «учётка хаба», «токен GitHub» или «доверенная публикация»; `релиз` — страница релиза
GitHub из запуска конвейера, принявшего версию (`реестр`, `СервисЗапусковКонвейеров`), пусто —
версия не из релиза. Тело собирается при постановке задания. Имя того, кто запустил доверенный
конвейер на github.com, событие не знает: его дочитывает `ИменаПубликаторов` у GitHub (контракт
`ОпознаниеGitHub` из `права`) в фоне доставки, после проверки задания и до отправки, — логин
берётся из запуска, принявшего версию тела. Вебхук подписывает и шлёт уже дочитанное тело, текст
Telegram разворачивается по нему же. Запуска на github.com нет, GitHub не ответил или имени
в профиле нет — публикатор назван логином.

В шаблоне текста `{кто}` — `публикатор` тела, а у события без публикатора — `кто`; `{как}` и
`{релиз}` — одноимённые поля. Перечень вставок — `ШаблонУведомления.Вставки`: имя, что подставится,
и поле тела, из которого берётся значение; из него и проверка шаблона, и разворот, и список под полем формы. Текст по умолчанию — шаблон
`ШаблонУведомления.ПоУмолчанию` (его же форма показывает в пустом поле): событие, координата
пакета, «Доступна <версия>, у вас <текущая>», «Опубликовал: <кто>, <как>», время, страница пакета
и «Релиз: <адрес>». В шаблоне из
нескольких строк строка, где пуста хоть одна вставка, не приходит; однострочный разворачивается
целиком; шаблон, от которого после разворота не осталось текста, даёт текст по умолчанию.

## Инварианты

- Мутация подписки проходит проверку права на объект; чужой объект — отказ.
- Событие самого хаба (`ОбъявленияСобытий.ОбъявитьПодписочноеХаба`, сейчас — новая версия хаба)
  выбирает только подписка хаба: подписке пула и пакета флажка нет, а заведение и правка с ним
  отказывают (API — 422; справочник называет такие события полем `hub_only`). У новой подписки хаба
  его флажок не отмечен — выбирают по желанию. Событие без пула и пакета получают только подписки
  хаба, если это событие хаба; событие пула или пакета без них не получает никто. Нижестоящим событие
  хаба не достаётся: в «Подписках сверху» его нет, поправка его не снимает и не гасит.
- Дерево получателей строится само: у подписки хаба — все пулы хаба, включая приватные, и их
  пакеты, у подписки пула — пакеты пула, у подписки пакета дерева нет. У каждого пула режим:
  «все» — весь пул, новый пакет попадает сам; «выбранные» — только выбранные пакеты, новый не
  попадает; «никакие» — пул исключён целиком со своими пакетами и событиями. Новый пул попадает
  в дерево в режиме «все». Свой пул подписка пула не исключает: у неё режимы «все» и «выбранные».
  У пары «подписка — узел» исключение одно и выбор один.
- Режим «все» исключений не держит. Режим «выбранные» начинается с того, что пулу доставалось: из «все» —
  весь пул, из «никакие» — ничего; с основой (`Применить`, параметр `Основы`) — весь пул или ничего, даже
  если пул уже «выбранные». Названный правкой режим «все» — весь пул и тогда, когда пул уже «все»;
  «никакие» снимает выбор. Правка дерева — режимы, затем галки пакетов в режиме их пула: галка, которая
  меняет пул «все» (снятая) или «никакие» (поставленная), переводит его в «выбранные» с тем, что ему
  доставалось, и ложится выбором. На сервер приходят только правки, а чего в дереве нет, пропускается
  молча и одинаково. Галка пула (`Отметить`): снятый пул — «никакие», возвращённый — «все». Замена
  (`Заменить`) записывает картину целиком: пул, названный исключённым, — «никакие», пул «выбранные»
  выбирает свои пакеты, кроме названных, пул без режима с исключёнными пакетами — «выбранные» без них,
  без исключённых — «все»; пул «все» с исключёнными пакетами — отказ. Прочитанное дерево записывается
  обратно без перемен.
- Пулы «все» с исключёнными пакетами — прежняя запись: на старте хаб переводит их в «выбранные» с тем же
  набором пакетов (новые пакеты таких пулов подписке больше не приходят — их ставят галкой), исключения
  пакетов уходят, перевод подписки — запись `получатели.переведены` в журнале аудита от имени хаба. Перевод
  идёт фоновой рогаткой под гейтом готовности `подписки.перевод`, после гейта `audit.служба`; без слушателя
  журнала он откладывается до следующего старта, не трогая данных. Записи — выбор пакетов, строка пула
  «выбранные», снятие исключений: оборванный перевод доставку не расширяет, следующий старт его доделывает.
- Событие пула (заполнение) в режиме «выбранные» доставляется: пул остаётся получателем.
- Отметки дерева видит и меняет только тот, кто распоряжается подпиской; подписка, удалённая
  или удалённый пул и пакет, уносят свои исключения и выбор.
- Пул в поправке к подписке хаба исключает свои пакеты деревом того же вида; пакет, снятый
  хозяином подписки (исключённый или не выбранный), в нём снят и закрыт — галка снизу на него не ложится. Исключения пакетов —
  часть поправки пула: снятый флажок гасит их и хранит, сброс поправки снимает, поправка с одними
  исключениями пакетов не снимается; у пары «подписка — пакет» исключение одно.
- Событие доставляется подписке, если дерево отдаёт его узел (пул не «никакие», пакет выбран в режиме
  «выбранные»), оно проходит её отбор и поправку пула и пакета
  события (пакет не исключён поправкой пула): поправка только сужает. Отметки дерева и поправки
  читаются один раз на событие. Флажок «нижестоящие могут сузить»
  снят — поправки не действуют, но хранятся; подписка удалена — её поправки уходят с ней.
- Поправку ставит тот, кто распоряжается подписками нижестоящего объекта; она не даёт права
  на саму подписку, а подписку без разрешения сужать нижестоящий не видит вовсе.
- Узел, которому дерево получателей подписки не достаётся или который исключён поправкой своего
  пула, её не видит и поправку к ней не ставит: пул «никакие» — ни сам, ни своими пакетами;
  невыбранный пакет пула «выбранные» — сам. Вернули узел —
  подписка снова видна, прежняя поправка снова действует.
- У пары «подписка — объект» поправка одна: повторная правит прежнюю.
- Отбор по тегам выбирают из тегов объекта: у подписки и поправки пула — теги пула, которые
  наследуют его пакеты, у пакета — его теги вместе с унаследованными, без выключенных; имя не
  из них отклоняется на сохранении. У подписки хаба отбора нет — её сужают пул и пакет поправкой.
- Отбор действует тем, что из сохранённого есть у объекта в момент события: удалённый или
  выключенный тег выпадает, отбор без тегов доставляет все версии.
- Отбор по тегам судит только события версии: версия проходит, если в момент события входит
  в состав тега так, как его видит служба тегов; проба доставки отбора не проходит.
- Задание уходит с настройками, снятыми на момент события, а не прочитанными при доставке.
- Публикация не ждёт GitHub: имя публикатора дочитывается в фоне доставки, логин запустившего
  конвейер берётся из запуска, принявшего версию тела (`реестр`), а не из полей тела.
- Проба и боевая доставка идут одним телом и одной отправкой. Проба — образец события объекта
  (`ОбразецСобытия`) о первом событии подписки, без отмеченных — о публикации версии, с признаком
  `проба` в теле: тот же текст и та же карточка ссылки, что предпросмотр показывает для этих
  настроек.
- Заголовки вебхука — только ASCII: `X-OpenHub-Event` — латинский код события из его
  объявления, `X-OpenHub-Delivery` — шестнадцатеричный идентификатор доставки (у пробы —
  `test-<uuid>`). Событие без кода вебхуком не уходит — отказ задания, а не пустой заголовок.
- Проба настройками формы — заведения или правки — ничего не заводит и не меняет: она идёт
  временной подпиской в памяти, ввод правки ложится поверх сохранённой подписки по правилам её
  хранения (пустое секретное поле — сохранённый секрет). Потолок незаведённой подписки считается
  на автора и объект, правки — на саму подписку; в аудит проба пишется так же, без секретов.
- Предпросмотр разворачивает шаблон из формы тем же путём, что боевая доставка, на образце:
  пул, пакет и его последняя версия — объекта подписки; вставки, которые событие несёт в бою,
  заполнены тестовыми данными: публикатор — смотрящий, способ — учётка хаба, автор — из манифеста,
  а без него — «OpenHub», репозиторий `https://github.com/Segate-ekb/openhub`, релиз
  `https://github.com/Segate-ekb/openhub/releases/latest`, ссылка на пакет — от внешнего адреса
  хаба, без него — от `https://openhub.example`. У заполнения пула пакета, версии и публикатора
  нет, у отзыва и восстановления — способа публикации, как и в бою. У новой версии хаба версия —
  образцовая, `текущая` — версия этого хаба, ссылка — страница OpenHub на hub.oscript.io. Под текстом — адрес
  карточки ссылки, тот же, что ушёл бы в Bot API: без ссылки в тексте карточки нет и здесь.
  Пустое поле шаблона — текст по умолчанию. Он ничего не отправляет и не сохраняет;
  неизвестное имя в шаблоне — тот же отказ, что на сохранении; секретные поля формы в него
  не попадают.
- Карточка-превью сообщения Telegram есть, только если в тексте есть ссылка http(s), и
  берётся из того, что в тексте (`ПревьюTelegram.Адрес(Тело, Текст)`), первым годным шагом:
  страница релиза; страница версии в хабе, когда в тексте страница пакета (пул открыт гостю
  и задан внешний адрес хаба; у каждой версии свой адрес); репозиторий; своя ссылка текста.
  Годен только http(s) без данных пользователя, пробелов и управляющих символов. Годной ссылки
  в тексте нет — превью выключено явно. Карточка крупной картинкой; тело вебхука превью
  не касается.
- Секрет вебхука показывается создателю один раз и в ответы и журнал не попадает.
- Очередь живёт в базе и переживает перезапуск; сбой одного задания не останавливает разбор партии.
