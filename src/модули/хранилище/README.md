# хранилище

Артефакты версий — `.ospx` и файлы описаний — на диске хаба либо в корзине S3: запись со сверкой
суммы, выдача, опись и снос области пула, потолок объёма и память о том, отвечает ли хранилище.
Что такое версия и когда артефакт можно удалить, решает `реестр`; модуль хранит байты по координатам.

## Публичный интерфейс

| Класс | Для чего | Методы |
| --- | --- | --- |
| `ХранилищеАртефактов` (контракт) | хранилище инсталляции; желудь собирает фабрика `КонфигурацияХранилища` по `oshub.storage.backend` | `Сохранить(Координаты, Источник)`, `Получить(Координаты, ОжидаемыйSha256)`, `ОсвободитьВыдачу(Путь)`, `ПолучитьДанные(Координаты, ОжидаемыйSha256)`, `ОткрытьПоток(Координаты, ОжидаемыйSha256)`, `СкачатьВФайл(Координаты, Путь, СрокОтветаСек)`, `Существует(Координаты)`, `Удалить(Координаты)`, `Размер(Координаты, СрокОтветаСек)`, `ОбъёмПула(ИмяПула)`, `ОбъёмыПулов()`, `Опись(ИмяПула)`, `УдалитьФайл(ИмяПула, ИмяПакета, ИмяФайла)`, `УдалитьОбластьПула(ИмяПула)`, `Бэкенд()` |
| `КоординатыАртефакта` | адрес артефакта: пул, пакет, версия, имя файла; негодный сегмент отвергается при создании | `Новый КоординатыАртефакта(Пул, Пакет, Версия, ИмяФайла)`, `Пул()`, `Пакет()`, `Версия()`, `ИмяФайла()`, `Представление()` |
| `КэшАртефактов` | содержимое артефакта для выдачи потоком, закэшированное по sha256 версии; локальное хранилище — мимо кэша; промах не ждёт хранилища: артефакт качается фоном в файл, который выдача читает по ходу | `Содержимое(Sha256, Координаты)`, `Загрузка(Sha256)` |
| `ВместимостьКвоты` | правило «влезает ли новое в предел» — общее с квотой пула | `Помещается(Занято, Освобождается, Новое, Предел)` |
| `ПотолокХранилища` | действующий потолок объёма | `ПотолокБайт()` |
| `СтражХранилища` | что хаб знает о доступности хранилища прямо сейчас | `Состояние()`, `СрокПамятиСек()` |

Только то, что зовут другие модули. Всё остальное — внутреннее.

Реализует контракты: `ЗадачаПланировщика` (`ЗадачаЗдоровьяХранилища`, задача `здоровье-хранилища`;
`ЗадачаУборкиЗагрузокАртефактов`, задача `уборка-загрузок-артефактов`), `КлючиНастроек`
(`КлючиНастроекХранилища`), `КодыПроисшествийПодсистемы` (`КодыПроисшествийХранилища`, подсистема
`хранилище`: `storage_unreachable`, `storage_denied`).

## Зависимости

Использует: `основа`, `настройки`, `происшествия`, `фоновыеЗадания` (контракт задачи); библиотеки `oint`
(S3), `errors`, `autumn-cache`, `autumn-opentelemetry`.
Используется: `реестр`, `публикация`, `зеркала`, `прокси`, `описания`, `интерфейс`.

## Настройки

Все ключи — часть развёртывания (`bootstrap`): их задаёт тот, кто поднимает хаб.

| Ключ | Умолчание | Что делает |
| --- | --- | --- |
| `oshub.storage.backend` | `file` | где лежат артефакты: `file` — на диске хаба, `s3` — в корзине |
| `oshub.storage.root` | `./data` | корень файлового хранилища |
| `oshub.storage.quota.bytes` | `0` | потолок объёма, байты; `0` — без ограничения |
| `oshub.storage.health.ttl.sec` | `300` | сколько вердикт стража считается свежим |
| `oshub.storage.health.timeout.sec` | `10` | сколько проба ждёт ответа |
| `oshub.jobs.storage_health_interval_sec` | `60` | как часто планировщик зовёт пробу |
| `oshub.storage.s3.endpoint` | — | адрес S3-сервиса |
| `oshub.storage.s3.bucket` | — | корзина |
| `oshub.storage.s3.region` | `us-east-1` | регион корзины |
| `oshub.storage.s3.prefix` | — | префикс ключей инсталляции внутри корзины |
| `oshub.storage.s3.force_path_style` | `true` | адресация корзины путём, а не поддоменом |
| `oshub.storage.s3.access_key`, `…access_key_file` | — | ключ доступа значением либо файлом секрета; значение сильнее |
| `oshub.storage.s3.secret_key`, `…secret_key_file` | — | секретный ключ значением либо файлом секрета |

Кэш артефактов читает и ключ веб-сервера `winow.ТаймаутОжиданияФайла` (мс, `30000`) — сколько выдача
ждёт новых байтов растущего файла: столько же промах ждёт ответа корзины на размер и скачивание
и терпит застой файла, а готовый файл живёт после загрузки два таких срока.

## Где что лежит

| Каталог | Что внутри |
| --- | --- |
| `артефакты/` | контракт `ХранилищеАртефактов` и фабрика `КонфигурацияХранилища`, координаты, общий помощник бэкендов (проверка источника, sha256, отказ сверки), тип содержимого по имени файла, кэш содержимого для выдачи и плановая уборка его временных файлов |
| `файловое/` | бэкенд на диске хаба и раскладка путей `{корень}/pools/{пул}/{пакет}/{файл}` |
| `s3/` | бэкенд на корзине S3: шов `КлиентS3` и его реализация на oint, параметры подключения, адреса объектов, раскладка ключей `{префикс}pools/{пул}/{пакет}/{файл}`, приговор по ответу корзины |
| `квота/` | потолок объёма и правило «влезает ли» |
| `здоровье/` | страж доступности, обёртка `ХранилищеПодСтражем`, через которую страж слышит каждый вызов, плановая проба и коды происшествий |
| `общее/` | объявление ключей настроек |

## Инварианты

- Артефакт адресуется только координатами; выход за корень отсекают дважды — координаты и раскладка бэкенда.
- Новый артефакт появляется атомарно: на диске — через временный файл, в корзине — одной загрузкой объекта (тела больше 5 МиБ — multipart частями по 5 МиБ).
- `ОткрытьПоток` файлового бэкенда читает файл хранилища без копии и без подъёма в память; у S3 содержимое читается во временную копию частями по 5 МиБ и держится в памяти до конца потока, копия удаляется сразу.
- Кэш выдачи при S3 держит сверенные артефакты файлами записей: попадание открывает поток над файлом записи без чтения в память. Промах не ждёт загрузки: артефакт качается заданием `ЗапускВФоне` одним GET прямо во временный файл `артефакт-*.ospx`, `Загрузка(Sha256)` называет его путь и полный размер, готовый файл со сверенной суммой копируется в запись кэша. Без `ЗапускВФоне` в контейнере промах копирует поток хранилища в запись синхронно.
- Промах ждёт ответа корзины на размер и скачивание не дольше таймаута читателя; файл, недокачанный и не менявшийся дольше него, снимается с реестра, и следующий промах качает заново, а вернувшийся поздно вызов в кэш не кладёт и новую загрузку не трогает. Сбой старта загрузки (файл, постановка в фон) регистрации не оставляет и доходит до выдачи как сбой чтения.
- Временный файл живёт после снятия загрузки два таймаута читателя и убирается следующей загрузкой либо задачей `уборка-загрузок-артефактов` раз в минуту; задача же убирает `артефакт-*.ospx`, которые пережили паузу без хозяина, — в том числе оставленные прежним процессом.
- Отказ называется машинным кодом `errors`: «артефакта нет» — `resource.not_found`, «хранилище не смогло» — `dependency.unavailable`, «сумма не совпала» — `data.corrupt`.
- Путь из `Получить` освобождается `ОсвободитьВыдачу` на любом пути выхода: S3 отдаёт временную копию.
- Экран спрашивает стража, а не хранилище; свежий боевой отказ успех пробы не отменяет.

## Тесты

`scripts/тесты.sh хранилище` — наборы `tests/хранилище/`; контракт обоих бэкендов стережёт один набор
`ХранилищеАртефактов_Тесты`, срок размера и скачивания клиента S3 — `КлиентS3Oint_Тесты` против слушателя на свободном
порту. Живых наборов у модуля нет; S3 против MinIO — `tests/внешние/S3СмоукMinIO_Тесты.os`
(`scripts/тесты.sh --внешние` с `OSHUB_S3_SMOKE`). Фикстуры модуля — `tests/хранилище/фикстуры/`, фейк шва
S3 — общая фикстура `ФейкКлиентS3`.
