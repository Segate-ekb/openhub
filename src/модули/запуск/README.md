# запуск

Как хаб поднимается: настройки собираются до контейнера, контейнер ОСени — из них, порт
открывается после стартовых задач. Точка входа — `src/main.os`; этот модуль — всё, что ей нужно
кроме самих предметов. Что делают предметы на старте, решают их рогатки, а не запуск.

## Порядок старта

| Шаг | Кто | Что происходит |
| --- | --- | --- |
| 1 | `main.os` | подключает классы журнала (`наблюдаемость/журнал`) и загрузки настроек: logos и загрузка работают раньше, чем ОСень разложит классы |
| 2 | `ЗагрузкаНастроек.Совет()` | configor читает файлы настроек и окружение; поверх — правила хаба: окружение сильнее файла, псевдонимы переменных, узлы базы и провайдеров входа из листьев, устройство winow и журнала, умолчания хаба для чужих ключей (предел тела запроса сервера поднимается до предела загрузки `oshub.publish.max_upload_bytes` с четвертью сверху, но не ниже действующего; в описание API — только адреса под `/api/`); итог ложится в Совет провайдером строителя ОСени старше файла и окружения; негодный узел базы — исключение здесь же |
| 3 | `ЗагрузкаНастроек.СоздатьКаталогиДанных()` | корень данных и каталог файловой базы |
| 4 | `Новый Поделка(Совет)` | контейнер ОСени; winow собирает контроллеры из `src/модули` |
| 5 | `main.os` | замечания и сведения загрузки — в журнал `oshub.запуск` |
| 6 | `Поделка.ЗапуститьПриложение()` | стартовые рогатки модулей при закрытом порте; упавшая синхронная роняет процесс |
| 7 | `ОткрытиеПорта.Открыть()` | отмечает старт завершённым (`ГотовностьХаба`), запускает задачи при готовности (`ЗапускЗадачПриГотовности`) и открывает порт; вызов блокирующий |
| 8 | `ЗапускЗадачПриГотовности` | фоновое задание ждёт готовности хаба (`/ready`) и исполняет задачи контракта `ЗадачаПриГотовности` по очереди; хаб не готов за `oshub.start.ready_wait_sec` — задачи не исполняются; `ОсвобождениеМетаданныхЖелудей` отпускает таблицы рефлексии ОСени, нужные только на сборке контейнера |

## Публичный интерфейс

| Класс | Для чего | Методы |
| --- | --- | --- |
| `ЗагрузкаНастроек` | Совет ОСени из файлов и окружения; им же собирают контейнер `admin-cli` и сидеры | `Совет(…)`, `ДеталькиПоверх(…)`, `Значение(…)`, `КореньДанных()`, `СоздатьКаталогиДанных()`, `Замечания()`, `Сведения()`, `НапечататьЗамечанияИСведения()`, `КэшиЧтенийИзБазы()` |
| `ЗапускЗадачПриГотовности` | запуск задач контракта `ЗадачаПриГотовности` после готовности хаба; его зовёт `ОткрытиеПорта` | `Запустить()` |

## Зависимости

Использует: `основа`, `наблюдаемость`, `настройки`, `фоновыеЗадания` (`ЗапускВФоне`, контракт `ЗадачаПриГотовности`),
`api` (`ПаспортОписанияAPI`); библиотеки `autumn`, `configor`, `winow`, `autumn-logos`, `reflector`.
Используется: `src/main.os`, `scripts/admin-cli.os`, сидеры `scripts/сидеры/`.

## Настройки

| Ключ | Умолчание | Что делает |
| --- | --- | --- |
| `winow.Порт` | `3333` | порт HTTP-сервера |
| `oshub.start.ready_wait_sec` | `600` | сколько задачи при готовности ждут готовности хаба |
| `oshub.start.release_bean_metadata` | `true` | после готовности отпускать таблицы рефлексии ОСени (память контейнера) |
| `oshub.jobs.enabled` | `true` | фоновые задачи по расписанию |
| `oshub.jobs.tick_interval_ms` | `1000` | шаг тика планировщика |
| `oshub.jobs.registry_gc_interval_sec` | `60` | уборка реестра фоновых заданий платформы |
| `otel.enabled` | `false` | телеметрия OpenTelemetry: трассы, метрики, журнал |
| `otel.exporter.otlp.endpoint`, `otel.exporter.otlp.protocol` | `http://localhost:4318`, `http/protobuf` | коллектор |
| `otel.exporter.otlp.timeout`, `otel.exporter.otlp.insecure` | `10000`, `false` | выгрузка в коллектор |
| `otel.service.name` | `openhub` | имя службы |
| `otel.traces.sampler`, `otel.traces.sampler.arg` | `parentbased_traceidratio`, `1.0` | отбор трасс и его доля |
| `otel.bsp.schedule.delay`, `otel.bsp.max.queue.size` | `5000`, `2048` | выгрузка спанов |
| `otel.metric.export.interval` | `60000` | срез метрик |
| `otel.traces.exporter`, `otel.metrics.exporter`, `otel.logs.exporter` | `otlp` | `none` выключает сигнал |
| `otel.entity.enabled`, `otel.entity.repository.enabled`, `otel.entity.query-text` | как `otel.enabled`, как `otel.enabled`, `false` | сигналы базы данных |

Все ключи — карточки «управляется конфигурацией»: читаются при старте процесса.

## Где что лежит

| Каталог | Что внутри |
| --- | --- |
| `Классы/` | модуль плоский: загрузка настроек (`ЗагрузкаНастроек`, `ИсточникиНастроек`, `РасположениеДанных`), `ОткрытиеПорта`, задачи при готовности (`ЗапускЗадачПриГотовности`, `ОсвобождениеМетаданныхЖелудей`), объявления ключей запуска, фоновых заданий и телеметрии |

## Инварианты

- Настройки хаба собираются одним Советом: окружение сильнее файла, программная деталька сильнее всего.
- Порт открывается только после стартовых рогаток (`winow.АвтоСтарт` = `Ложь`).
- Тело JSON-запроса winow разбирает в `Соответствие` (`winow.АвтоматическиПриводитьОбъектыКСтруктуре` =
  `Ложь`): ключ, который не годится в имя поля структуры (`пул.заполнен`), запрос не роняет.
- Предел тела запроса сервера только поднимается: до предела загрузки с четвертью сверху, но не ниже `Kestrel__Limits__MaxRequestBodySize` оператора либо 30 МБ веб-сервера; явная деталька `winow.МаксимальныйРазмерТелаЗапроса` сильнее всего.
- Узел базы, с которым хаб не поднимется, — ошибка старта, а не каскад на первом запросе.
- Освобождение метаданных желудей сверяет устройство ОСени целиком до первого изменения: не сошлось или упало —
  предупреждение в журнал, контейнер не меняется. Таблицы-владельцы строк завязи отпускаются у всех определений,
  поля определений сбрасываются только у одиночек: компанейские желуди читают их на каждом создании.
