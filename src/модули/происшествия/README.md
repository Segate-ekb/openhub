# Происшествия

Происшествие — это работа, которую хаб не сделал: пропущенная зеркалом версия, лежащее
хранилище, молчащий источник. Модуль помнит их вместо журнала контейнера и отвечает
на четыре вопроса сразу: **над чем**, **что именно**, **почему** и **когда в последний
раз**. Память ограничена по числу и по сроку и секретов не носит.

| Класс | Что делает | Бросает ли наружу |
| --- | --- | --- |
| `ОбъектыПроисшествий` | адрес объекта: форма плюс обезличивание | да — негодный адрес это ошибка вызывающего |
| `КодыПроисшествий` | словарь машинных кодов и признак «пройдёт само» | да — необъявленный код это опечатка |
| `ЛетописьПроисшествий` | запись со свёрткой, снятие, уборка по сроку | **нет** у `Записать`/`Снять`/`НачатьПрогон`; **да** у `УбратьУстаревшие` |
| `ЧитательПроисшествий` | снимки для экранов и API: по одному объекту (`ПроисшествияОбъекта`, `ЕстьПроисшествия`, `ЧислоПроисшествий`) и сразу по списку объектов (`ПроисшествияОбъектов`) | **да**: лежащая база даёт экрану ошибку, а не «происшествий нет» |

Видно всё это на экранах хранилища, состояния зеркала и источников пула — и теми же
данными карточками API.

Таблица происшествий живёт в `данные/Классы/служебное` (`Происшествие`,
`ЗапросыПроисшествий`, `ХранилищеПроисшествий`) — как и всё остальное, к чему хаб ходит
через autumn-data. Убирает устаревшее `фоновыеЗадания/ЗадачаЧисткиПроисшествий`.

## Как этим пользоваться

Адрес объекта собирают **только** через `ОбъектыПроисшествий` — ни руками, ни через
`ИмяОбъектаАудита` напрямую: у источника туда же сложено обезличивание, и адрес
с токеном просто не собирается.

```bsl
// адрес объекта — четыре формы на выбор
Объекты.Зеркало(Зеркало.Идентификатор);          // «зеркало/17»
Объекты.ХранилищеS3(Конфиг.Бакет());             // «хранилище/s3://openhub»
Объекты.ХранилищеФайлами(Конфиг.Корень());       // «хранилище/./data»
Объекты.Источник(Зеркало.АпстримURL);            // «источник/https://hub.example/…»

// весь блок ниже — ОДНА подсистема: писать зеркалом, а снимать хранилищем по тому же
// объекту значит снять не то, что писал
Подсистема = Коды.ПодсистемаЗеркало();
Объект = Объекты.Зеркало(Зеркало.Идентификатор);

Летопись.НачатьПрогон(Подсистема, Объект, Прогон);                 // обход начался
Летопись.Записать(Подсистема, Объект, "oint@1.2.3",
	Коды.БольшеПределаПриёма(), "Пакет 40 МБ больше предела приёма 25 МБ",
	Прогон, Зеркало.ТокенДоступа);
Летопись.Снять(Подсистема, Объект);                                // происшествий больше нет

Для Каждого Происшествие Из Читатель.ПроисшествияОбъекта(Подсистема, Объект, Прогон) Цикл
	// Подсистема · Объект · Предмет · Код · Причина · Количество · Впервые · Последний
	// · Прогон · Устранимо
КонецЦикла;

// экран СПИСКА объектов спрашивает их все разом: одно обращение вместо обращения на строку
Написанное = Читатель.ПроисшествияОбъектов(Подсистема, МассивОбъектов);  // объект → массив снимков
```

Пишет и снимает **только** `ЛетописьПроисшествий`, читает **только**
`ЧитательПроисшествий`: снятие — это запись, и держать его у читателя значило бы
соврать именем.

**Подсистема — часть ключа везде.** И потолок, и снятие, и чтение работают по паре
подсистема + объект, потому что один объект бывает общим: в `источник/<адрес>` пишут
и проба источника пула (подсистема `источник`, прогон пустой), и обход зеркала
(подсистема `зеркало`, прогон с меткой). Без подсистемы в ключе `НачатьПрогон` зеркала
сносил бы причины пробы, а `Снять` пробы — причины пропусков зеркала.

**Прогон — метка ОБХОДА, а не цикла:** она обязана пережить порции и перезапуск хаба.
У зеркала это `ПрогонНачат` захваченной записи — `ПрогонЗеркала.Занять` ставит его
только тогда, когда курсор пуст, то есть один раз на обход. «Очевидные» реализации
(новый GUID на порцию, время старта порции) сносят причины предыдущих порций молча.

**Секрет называют явно.** У кого он есть — токен источника, пароль прокси — передаёт
его седьмым параметром `Записать`: вычёркивание идёт через `основа/ТекстОшибки.БезСекрета`.
Запрет «не клади секрет в причину» без механизма держится только до первого невнимательного
автора.

## Что осталось за пределами модуля и почему

- **адрес объекта** решает `аудит/ИмяОбъектаАудита` — он один на хаб, и происшествие называет
  объект ровно так же, как журнал аудита. `ОбъектыПроисшествий` его не подменяет, а складывает
  с обезличиванием;
- **обезличивание** живёт в `наблюдаемость/журнал/ОбезличиваниеЖурнала`: копии правила
  здесь нет, иначе сторож защищал бы не ту копию;
- **числа инсталляции** (`oshub.incidents.max_per_object`, `oshub.incidents.ttl.sec`)
  читаются дверью `СервисНастроек.Целое` — своего файла настроек у модуля нет;
- **экраны и API** происшествий не здесь: модуль отдаёт снимки, разметку печатают `интерфейс`
  и `api`;
- **журнал аудита** происшествиями не задет: он про «кто что сделал», происшествия — про «что
  не получилось у самого хаба».

## Мины этого слоя

- **Почему летопись молчит, а читатель нет** (таблица классов выше — контракт, здесь
  причина). Зеркало, уронившееся из-за летописи, — это объяснение неудачи, ставшее
  неудачей; поэтому `Записать`, `Снять` и `НачатьПрогон` пишут предупреждение в журнал
  и возвращают управление. `УбратьУстаревшие` наоборот: её зовёт планировщик, и молча
  вернуть ноль значило бы показать оператору вечно чистую таблицу. Читатель тоже
  бросает: пустая выдача обязана означать «происшествий нет», иначе экран врёт ровно тогда,
  когда он нужнее всего.
- **Свёртка целиком под замком.** `НайтиКлюч → Количество + 1 → Сохранить` — это
  read-modify-write, и без `БлокировкаРесурса` два пишущих заводят дубль ключа, теряют
  инкремент и перешагивают потолок. Пишущих с первого дня двое: в `хранилище/…` пишут
  и фоновая проба, и поток запроса. Под тем же замком — снятие и уборка по сроку.
- **Одна запись — одно чтение и одна запись в базу.** Свёртка берёт срез пары
  подсистема + объект целиком (он ограничен потолком) и ищет ключ, считает занятое
  и находит сводку переполнения уже в памяти. Второго запроса ради счётчика нет:
  под замком он был бы глобально сериализованным сканом.
- **Потолок считается по паре подсистема + объект**, и последний свободный слот
  зарезервирован за «прочим»: обычных ключей помещается «потолок минус один».
  Переполнение никогда не молчит — если сводки этого прогона нет и места нет,
  счёт идёт любой сводке пары.
- **Постраничности у читателя нет, и она не нужна.** Пара не держит больше
  `oshub.incidents.max_per_object` записей (по умолчанию 50), а это меньше потолка
  выдачи API `oshub.api.page_max` (200). Ручке, которой нужна форма страницы,
  готовый массив заворачивает `api/СтраницыAPI.Перечень`. У пакетного `ПроисшествияОбъектов`
  выдача ограничена тем же потолком, помноженным на число спрошенных объектов: список
  объектов задаёт спрашивающий, и это его экран, а не вся таблица. Отбор по списку делает
  база (`Объект В …`), пустой список до неё не доезжает вовсе.
- **Секрет снимается из названного значения и из адресов внутри причины.** Обезличивается
  то, что выглядит адресом (`://`): строка запроса с подписью `X-Amz-*` и учётные данные
  authority. Голый токен, вписанный в текст сбоя без адреса и НЕ переданный параметром
  `Секрет`, распознать нечем.
- **Причина обрезается по `ПределПричины()`** (500 символов): происшествие объясняет
  неудачу, а не возит в базе чужую портянку.
