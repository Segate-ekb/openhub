# кабинет

Сценарии кабинета поверх входа, прав и реестра: заведение, назначение и удаление пула с правом
на это, выдача прав на объекты, «чем человек управляет» и личные пространства хаба. Своих таблиц
нет; экраны кабинета рисует `интерфейс`, маршруты `/api/v1` — `api`.

## Публичный интерфейс

| Класс | Для чего | Методы |
| --- | --- | --- |
| `СлужбаДоступа` | пул и права на объекты от имени человека: порог операции проверяется здесь, пул объекта права берётся из сущности, удаление пула пишется в журнал аудита | `СоздатьПул(…)`, `НазначитьОсновнойПул(…)`, `УдалитьПул(…)`, `ВыдатьРоль(…)`, `ОтозватьГрант(…)`, `МожетВыдаватьГрант(…)`, `ГрантыНаОбъект(…)`, `ГрантыСубъекта(…)`, `РольЗаписи(…)`, `ТипОбъектаПоддерживается(…)` |
| `СлужбаКабинета` | чем человек управляет: пакеты и пулы по правам и по своим публикациям, в детерминированном порядке | `МожетУправлять(…)`, `ПакетыВУправлении(…)`, `ПулыВРаспоряжении(…)` |
| `СлужбаЛичныхПространств` | оба перехода настройки «Личные пространства»: снос всех личных пулов и раздача пространства каждой учётке | `СводкаУдаления()`, `УдалитьВсе(…)`, `РаздатьВсем(…)` |

`ОписанияСобытийКабинета` — объявление события «личные пространства изменены» для перечня
событий хаба (контракт `ОписанияСобытий`).

## Зависимости

Использует: `основа`, `события`, `аудит`, `вход`, `права`, `реестр`.
Используется: `api`, `интерфейс`.

## Где что лежит

| Каталог | Что внутри |
| --- | --- |
| `Классы/` | три службы-сценария и объявление события |

## Инварианты

- Пул объекта права берётся из сущности, а не из запроса.
- Удаление пула и оба перехода личных пространств оставляют запись в журнале аудита; без модуля
  событий операции идут, а журнала нет.
- Сбой сноса одного личного пространства не обрывает снос остальных: он считается в числах итога.
