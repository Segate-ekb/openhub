# Интерфейс

Здесь лежит всё, что пользователь хаба видит в браузере. Каталоги названы тем, что показано:
`каталог/` — страница каталога пакетов, `настройки/пул/` — настройки пула. Контроллер
страницы, модель её экрана и адаптеры лежат рядом, потому что вместе они и есть страница.
Искать здесь стоит по тому, что человек открыл, а не по виду класса. Что именно показывают
эти экраны — пулы, пакеты, версии, теги — описано в [корневом README](../../../README.md).

Кнопки, таблицы, поля, тему и каркас страницы даёт библиотека компонентов `oscript-ui` —
отдельный пакет, который о пакетах и пулах ничего не знает. Словарь предметной области
хаба — значки пула и версии, карточка пакета, теги релиза — остаётся здесь и передаётся
библиотеке моделью.

## Разделы

| Каталог | Что показывает | Где видно |
| --- | --- | --- |
| `общее/` | каркас страницы хаба — шапка, подвал, бренд, тема, статика, — словарь текстов и адаптеры, нужные нескольким разделам | `POST /ui/theme` · `/static/{файл}` · `/brand/{файл}` |
| `главная/` | лендинг | `/` |
| `каталог/` | каталог пакетов: поиск, отборы по пулу и «в моём управлении», постраничность | `/packages` · `/packages/search` |
| `пакет/` | страница пакета: шапка, готовая команда установки, вкладки версий и зависимостей | `/{пул}/{пакет}` · `…/versions` · `…/deps` · `/package/{имя}` |
| `пул/` | страница пула | `/{пул}` |
| `вход/` | вход паролем и через провайдера, регистрация, восстановление пароля, подтверждение адреса, мастер первого запуска, приглашение, подтверждение входа из CLI | `/login` · `/logout` · `/register` · `/setup` · `/invite` · `/forgot-password` · `/confirm-email` · `/cli/login` · `/login/oidc/{провайдер}` · `/oidc/callback` |
| `кабинет/` | личное пространство, входящие, лента уведомлений, проводник первых шагов | `/me` · `/me/inbox` · `/me/notifications` · `/tour` |
| `переезды/` | перенаправления со старых адресов кабинета | `/office/*` |
| `настройки/общее/` | общий каркас всех пяти разделов настроек и подраздел «Подписки на события», одинаковый у пула, пакета и хаба | — |
| `настройки/аккаунт/` | настройки аккаунта: профиль, безопасность, токены доступа, привязки OIDC, «мои права», вид и язык | `/me/settings/*` |
| `настройки/группа/` | настройки группы: участники, связка с OIDC, права доступа группы | `/groups/{группа}/settings/*` |
| `настройки/пул/` | настройки пула: общие, видимость и доступ, права доступа, резерв имён, входящие, теги, апстримы, зеркала, подписки на события, квота, опасная зона | `/{пул}/settings/*` |
| `настройки/пакет/` | настройки пакета: карточка, права доступа, теги и конструктор тега, версии и метки, подписки на события, доверенная публикация, опасная зона | `/{пул}/{пакет}/settings/*` |
| `настройки/хаб/` | настройки хаба: базовые настройки, брендирование, вход и регистрация, провайдеры входа, политика пароля, люди, пулы, легаси-флоу, хранилище, доверенная публикация, почта, зеркалирование, подписки на события, прокси апстрима, аудит, обслуживание | `/hub/settings/*` · сводка зеркал всех пулов `/office/mirrors` |
| `настройки/хаб/журнал/` | экран раздела «Аудит»; сам журнал ведёт модуль `аудит` | `/hub/settings/audit` |

## Связи с соседями

Модуль ничего не отдаёт наружу: им никто не пользуется, он пользуется всеми. Данные ему
дают доменные модули — `реестр`, `права`, `публикация`, `зеркала`, `подписки`, `связь`;
описание пакета приходит из `описания` уже готовым HTML; настройки инсталляции и статику —
из `настройки`.

Обратной зависимости быть не должно: класс, который понадобился `api` или доменному модулю,
здесь не живёт. По той же причине разметку печатают только этот модуль и библиотека
компонентов — в доменных службах HTML-тегов нет.
