# интерфейс

Всё, что человек видит в браузере: страницы хаба, их контроллеры и модели экранов, разделы
настроек, каркас страницы и словарь текстов. Правил предметов здесь нет — экран спрашивает
службы модулей; кнопки, таблицы, поля, тему и корень страницы даёт библиотека компонентов
`oscript-ui` (кит), которая о пакетах и пулах ничего не знает.

## Публичный интерфейс

По имени классы модуля не зовёт никто: наружу он отдаёт маршруты winow и реализации контрактов.

| Класс | Для чего | Методы |
| --- | --- | --- |
| `СтраницаСбояХаба` (контракт `основа/СбойХабаСловами`) | сбой запроса словами хаба: фраза в ответ машине, страница человеку | `Фраза(КодСбоя)`, `Страница(КодСбоя, Статус, КодЗапроса, КукиЗапроса)` |
| `СтраницаНеизвестногоАдреса` (контракт `основа/НеизвестныйАдресСловами`) | адрес без маршрута | `Фраза()`, `Страница(ЗаголовкиЗапроса, КукиЗапроса, ПутьЗапроса)` |
| `СловарьТекстов` (контракт кита `СловарьИнтерфейса`, `&Верховный`) | тексты экранов по ключам; его читает `ТекстыИнтерфейса` кита | `НайтиТекст(Ключ)`, `Ключи()` |
| `ОбрамлениеХаба` (контракт кита `ОбрамлениеИнсталляции`, `&Верховный`) | шапка с единым меню и подвал вокруг страницы кита | `Обрамление(Контекст)` |
| `ОформлениеХаба` (контракт кита `ОформлениеИнсталляции`, `&Верховный`) | тема, пресет и акцент инсталляции | `Оформление()`, `ИмяCookieОформления()` |
| `КлючиНастроекИнтерфейса` (контракт `настройки/КлючиНастроек`) | ключи оформления, хаба по умолчанию для opm и страницы журнала аудита | `Объявления()` |

Всё остальное — внутреннее.

## Зависимости

Использует: `основа`, `вход`, `права`, `реестр`, `настройки`, `публикация`, `зеркала`,
`подписки`, `кабинет`, `прокси`, `аудит`, `статистика`, `происшествия`, `хранилище`, `поиск`,
`описания`, `протоколAPI`, `гео`, `почта`, `уведомления`, `состояние` (и внешние библиотеки:
`oscript-ui`, `oscript-md`, `winow`, `autumn`, `url`).
Используется: `вход` — через контракты `основа/СбойХабаСловами`, `основа/НеизвестныйАдресСловами`;
`настройки` — ключи собирает `РеестрНастроек`.

## Настройки

| Ключ | Умолчание | Что делает |
| --- | --- | --- |
| `oshub.instance.opm_default_hub` | `false` | хаб — тот, которым opm пользуется без настройки: команды установки на страницах короче |
| `oshub.ui.theme` | `тёмная` | тема инсталляции по умолчанию; посетитель выбирает свою |
| `oshub.ui.preset` | `material` | пресет темы инсталляции: `classic` («Как было»), `material` («Новая»), `oscript`; свой акцент ложится поверх |
| `oshub.ui.accent` | пусто | цвет акцента `#rrggbb`; пусто — акцент пресета |
| `oshub.ui.brand` | пусто | название хаба в шапке, заголовке вкладки и подвале |
| `oshub.ui.tagline` | пусто | подпись в подвале |
| `oshub.ui.show_name` | `true` | печатать ли название рядом со знаком |
| `oshub.ui.audit_page_size` | `20` | записей на странице журнала аудита |

## Где что лежит

Сверху — каркас, общий для всех страниц; панели, которые одинаково показывают один предмет
на разных экранах; и четыре района экранов. Районы между собой связаны только адресами
и домами настроек (`ДомПула`, `ДомПакета`, `ДомАккаунта`, `ДомГруппы`, `ДомХаба`).
Тексты района или панели лежат в его корне (`СловарьКабинета`, `СловарьПодписок`…) и реализуют
контракт `общее/ЧастьСловаряТекстов`; общий `общее/СловарьТекстов` держит тексты каркаса и получает
части от контейнера массивом.

## Инварианты

- Текст для человека — ключ словаря, а не литерал в экране.
- Один стиль: интерфейс печатает экраны только деревом узлов кита — страница собирается одним
  `Кит.Холст(…)` для `Каркас.Страница`, части экрана отдают узлы, а не напечатанные строки. Прежним
  входом компонентов (`НаборКомпонентов.X().Отрисовать(…)`) экраны не печатаются; служебное — тоже
  словами кита (`Кит.АдресСтраницы`, `Кит.РазобратьПравкиДерева`, `Кит.РазмерСтраницыДерева`).
  Чужой документ (README пакета) — узел `Кит.Проза(Html)`, подсветка его кода —
  `Кит.Скрипт().Модуль(MarkdownПодсветка.ТегСкрипта())`; сырого `Кит.Готовое` в интерфейсе нет.
- Экран спрашивает службу модуля-хозяина, а не его `Хранилище*`.
- Контроллер обслуживает один дом настроек.
- Группа разделов дома в шторке меню подписана общим именем дома (`Дом.Заголовок()`: «Настройки
  аккаунта», «Настройки пула»), а не заголовком страницы — логин и имя объекта в шторке уже есть.
  Рубрику, которая называет сам объект («Аккаунт», «Хаб»), дом объявляет сам — словом `РубрикаОбъекта()`,
  отдавая её четвёртым аргументом `СборкаДомаНастроек.РазделыДома`: её разделы идут первыми без рубрики —
  и в колонке, и в шторке. По словам рубрику не угадывают.
- Формы списка пакетов пула печатаются мейнтейнеру пула и только по сессии; порог формы
  сервер проверяет сам, до разбора. Снятие резерва — всегда отдельным шагом подтверждения,
  который повторяет имя; вопрос задаётся только о пакете без единой версии.
- Гвард экрана печатает отказ сам и лежит рядом со своим экраном.
- Значок — только из набора кита: глиф или логотип `бренд:<ключ>`, своих svg у экранов нет. Значок,
  который выбирает человек (тег, провайдер входа), — поле `.ВыборЗначка()` кита, значение — имя значка.
  Значок провайдера входа — одно правило в два шага: домен `вход` (`вход/провайдером/ЗначокПровайдераВхода`)
  хранит и отдаёт имя бренда кита `бренд:<ключ>` или пусто, прежний голый ключ (`github`, общий `key`) он
  же и приводит; экран печатает `общее/ЗначокПровайдера.Имя(Провайдер)` словом `Иконка`/`Значок` (кнопки
  входа, список провайдеров, привязки учётки). Файл `/static/<ключ>.svg` (`АдресаСтатики.АдресЗначка`,
  подмена инсталляцией под тем же именем) провайдеры входа не печатают — им пользуется только значок
  CI-провайдера доверенной публикации; логотип, которого у кита нет, — бренд в ките, не файл в обход.
- Опасная зона пакета пустой не бывает: раздел есть в дереве и открывается по адресу, только когда
  у смотрящего есть необратимое действие — удаление пакета без версий мейнтейнером пула;
  иначе адрес раздела отвечает 404. Удавшееся удаление уводит на страницу пула.
- Карточку ссылки (`og:*`) несёт только страница пакета публичного пула. Страница с версией
  в запросе (`?version=`) — страница версии: показ тот же, карточка называет версию и ведёт
  на свой адрес; неизвестная версия даёт карточку пакета. Адреса карточки абсолютные,
  от внешнего адреса хаба: без него нет ни `og:url`, ни знака хаба картинкой. Картинка —
  социальная карточка репозитория на GitHub, иначе растровый знак хаба; загруженная SVG-иконка
  оставляет карточку без картинки.
- Блоки кода README с языком раскрашивает в браузере встроенный модуль подсветки `oscript-md`
  (`Кит.Скрипт().Модуль(MarkdownПодсветка.ТегСкрипта())`): он стоит в карточке описания один раз и только когда
  такие блоки есть, движок подсветки грузит с `esm.sh` — единственный внешний адрес страниц
  хаба; страница описания API `/swagger-ui.html` — страница winow, не хаба. Цвета обеих тем выбирает браузер по `color-scheme` темы хаба; фон блока — хабовый.
- Окно «Получатели» (`?окно=получатели-{id}`) — дерево галок кита. Пул — строка с сегментами режима
  (`ДеревоГалок.Режимы(…)`): у подписки хаба «Все / Выбранные / Никто», пулы свёрнуты, пакеты
  приезжают страницами (размер страницы — кита) по адресу двери окна; у подписки пула — её пул
  раскрытой веткой, «Никто» не печатается. Режим — массовая отметка кита: в «Все» пакеты отмечены
  и заперты (новые попадают сами), в «Никто» — сняты и заперты, «Выбранные» начинаются с того, что
  было видно, и правятся галками; без скрипта страница ветки (`?ветка=&страница=`) печатается целиком
  словом `Ветка(ключ, страница, всего, режим)` — строка пула с сегментами в той же форме. Сервер
  толкует ветку по `Кит.ПравкиВеткиДерева`: «выбранные» после «все» — весь пул минус снятые (основа
  домена), после «никакие» — только отмеченные, без основы — хранимый выбор с правками; галки пакетов
  пула, который остаётся «все» или «никакие», не правят ничего, в найденном они заперты.
  Поиск спрашивает ту же дверь (`?найти=`, с двух знаков). Правки против напечатанного считает кит
  на обеих дорогах (`ТолькоПравки`, `ПравкиБезСкрипта` — поле `показано`), сводка правок — у кнопок
  (`СводкаПравок`); выбранное, которого на странице нет, — рядом плашек над деревом (`Отмеченные`,
  первые 20 и хвост «ещё N» — `ПределОтмеченных`), крестик — правка того узла и без скрипта; имена
  полей формы — `Кит.ИменаПолейДерева()`. Адрес двери собирает одно место —
  `ОкноПолучателей.АдресДвери`. Одна и та же форма сохраняется одинаково со скриптом и без.
  Окна «Получатели» и «Пакеты пула» закрываются словом кита `АдресЗакрытия(<раздел без ?окно>)`
  (крестик и «Отмена»; без скрипта — ссылка на раздел, со скриптом — на месте), как все окна по адресу.
  Удача — 303 обратно в окно (с поиском — на дверь с `?найти=`); поле, которого окно не печатает, или
  режим «все, кроме» — форма старой вкладки: 400 «Страница устарела», ничего не меняется.
  Пакет, появившийся после отрисовки, у включённого пула остаётся включённым.
- Предпросмотр и проба окна подписки работают и без скрипта: место предпросмотра скрыто, кнопки шлют
  форму окна на свой адрес, и страница возвращает окно открытым на шаге «Текст» с сообщением или итогом.
  Скрипт шлёт поля формы на адрес из `data-sub-preview` и `data-sub-trial` и вставляет узел
  `[data-sub-result]` ответа; место в закрытом окне оживает, когда окно открыли или в его форме набирают;
  секретные поля (`data-sub-omit`) в предпросмотр не уходят, сообщение собирает только сервер. В окне
  новой подписки текст канала стоит на шаге «Текст» панелью его сегмента (`Кит.ПанельСегмента`): видна
  панель отмеченного канала, и без скрипта; новый способ доставки с текстом встаёт сам. Текст сообщения —
  данные пользователя: печатается `Кит.Текст`, а не строкой на месте ребёнка узла.
- Окна подписки (новая и правка) уходят обычной отправкой, без `БезПерезагрузки()`: ответ на них может
  нести секрет подписи, а секрет показывается окном страницы ответа и в адрес не попадает (п. 9 рецепта).
  Форма правки не несёт включённость — её меняет тумблер записи; форма старой вкладки с полем `включить`
  на адресе правки — 400 «Страница устарела» без изменений. Прочие формы старой вкладки безвредны и
  проходят как новые: старая форма заведения заводит подписку тем, что в ней набрано, старая проба шлёт
  пробное сохранёнными настройками, старая форма поправки ставит поправку целиком — намерение формы
  и мутация совпадают.
- Записи реестра домен о каждой подписке не спрашивают: `СрезПодписок` собирает на страницу поправки,
  сводки исключений и поправки пула, пакеты, снятые поправками, имена сузивших и теги объектов отбора
  разом (`СервисПоправокПодписок.ПоправкиПодписок`, `ПоправкиОбъекта`, `ИсключённыеПакетыПоправок`,
  `СводкиПоправок`, `СервисИсключенийПодписок.СводкиИсключений`) — цену раздела стережёт
  `ДешевизнаЭкранов_Тесты.ЦенаРазделаПодписокНеРастётСЧисломПодписок`.
- Настройки доставки пишет одна дверь — `…/webhooks/delivery` (форма спойлера и сброс введённого руками);
  адрес блока `/hub/settings/delivery` только читается: GET уводит на экран подписок, POST — 405.
- Брендирование печатает значения полями с именами без точек (`brand`, `tagline`, `show_name`,
  `theme`, `accent`): под этими именами их зеркалит образец шапки (`data-mirror`; ряд акцента
  перекрашивает кит по зеркалу поля `accent`); форма с ключами реестра вместо имён — старая
  вкладка, отказ 400 без записи. Источник темы — словом кита у сегментов (`Сегменты.Источник`).
  Картинка — своя форма своего адреса, отказ загрузки — строкой отказа её слота (`СлотКартинки.Ошибка`);
  образцы акцента — палитра кита (`Поле.ОбразцыТемы`), одна на аккаунт и хаб. Кнопка образца формы не
  отправляет (`Кнопка.БезОтправки`). Название и подпись хаба в образце — данные администратора, узлом `Кит.Текст`.
- Поле текста уведомления печатается по декларации канала (`ПоляПодписки`): пустое поле
  показывает готовый текст декларации — у Telegram шаблон по умолчанию, — а под полем свёрнут
  перечень вставок списком «`{имя}` — что подставится» из той же декларации. Поля канала стоят
  в наборе его сегмента, обязательность наборов проверяет сервер (отказ — под полем), поля чужих
  наборов не читаются.

## Экран списка

Экран списка записей — провайдеры входа, зеркала, апстримы, токены, подписки, таблицы людей,
групп и пулов — собирается из пяти частей: секция с кнопкой «Добавить», список, действия записи,
окно добавления и правки, подтверждение удаления. Образец — `хаб/провайдеры-входа/`
(`ВитринаПровайдеровВхода`, `ОкноПровайдера`, `ОкноСтранПровайдера`, `ПультПровайдеровВхода`,
`КонтроллерПровайдеровВхода`), его сторож — `tests/интерфейс/ЭкранПровайдеровВхода_Тесты.os`.

### Витрина

1. Секция — узел `Кит.Секция(Заголовок, …)` в массиве `Секции` дома: `.Лид(…)` — одна строка,
   `.Действия(Кит.Кнопка("Добавить …").Основная().Иконка("плюс").Открывает(ОкноНовой))` — кнопка
   справа в шапке секции (на телефоне — под лидом во всю ширину). У окна новой записи есть адрес
   (пункт 3), поэтому кнопка печатается ссылкой: без скрипта она ведёт на страницу с открытым окном,
   со скриптом открывает окно на месте; `Кит.ОкноПоАдресу` для кнопки «Добавить» не нужен.
2. Немного записей — `Кит.Реестр(Кит.ЗаписьРеестра(Имя, Кит.Свойства(…)))`: свёрнутая строка —
   `.Значок`/`.Картинка`, `.Плашка`, `.Подпись`; тело — свойства, копируемые значения словом
   `.Копируемое()`.
   - Справа — `.Действия(Кит.Форма("<ключ>/toggle", Кит.Тумблер(…).СохранятьСразу()).БезПерезагрузки())`.
     Своей кнопки у формы нет: без скрипта её шлёт запасная кнопка-значок кита (словарь `toggle.save`),
     где скрипт есть, лист её прячет. Запись, которую править нельзя, получает тумблер `.Заблокировано()`.
   - `.Кнопки(…)` — все действия записи одним набором: кит печатает из него и меню ⚙ свёрнутой
     записи, и кнопки внизу раскрытой. В наборе — только `Кит.ОкноПоАдресу(Окна.Адрес(АдресРаздела,
     "<вид>", Ключ), Подпись)` и кнопки-ссылки, форм в наборе нет — кроме формы из одной кнопки
     для действия без окна (заявка «Синхронизировать»). Удаление — окно по адресу
     `.Опасная()`.
   - Много записей — `Кит.Таблица` с `Кит.ФормаОтбора` и `Кит.Пагинация`, действия строки —
     `Кит.Меню` в ячейке, удаление — тоже окно по адресу.
     Образцы — `хаб/люди/` (`ВитринаУчёток`, `ВитринаГруппХаба`) и `хаб/пулы/` (`ВитринаПулов`),
     сторожа — `tests/интерфейс/ЭкранЛюдей_Тесты.os`, `tests/интерфейс/ЭкранПуловХаба_Тесты.os`:
     - таблица из данных `.Вид("карточками")`, первая колонка `.Заглавная()`, колонка меню и плашек
       `.БезПодписиВЗаписи()`; своей строке меню нет, если правка себя — само-локаут;
     - отбор и страница живут в адресе (`ОтборЛюдей`: `ИзАдреса`, `Адрес`, `Страница`, `Пагинация`),
       форма отбора и шаги страниц — `.БезПерезагрузки()`, незнакомое значение отбора отбрасывается;
     - в меню строки обратимое действие — форма из одной кнопки `Кит.Форма(…).Вид("меню")` с желаемым
       состоянием в поле (повтор отправки его не переворачивает), остальное — `Кит.ОкноПоАдресу`;
     - формы строк и окон несут отбор скрытыми полями (`ОтборЛюдей.Поля`), адреса окон строятся от
       адреса списка с отбором: правка и подтверждение возвращают к тому же списку;
     - раздел, у которого кроме таблицы есть значения реестра настроек (`pools`), заводит свой литерал
       маршрута и сам печатает раздел секциями дома (`ВитринаДомаХаба.Секции`); окно новой записи
       несёт скрытую операцию, а формы значений раздела (без операции, сброс, свои переходы пультов)
       контроллер передаёт общей двери дома (`КонтроллерДомаХаба.Раздел`); незнакомая операция —
       400 «Страница устарела». Отказ значения общая дверь печатает под его полем с набранным на
       месте (`ПультЗначенийНастроек.Применить` называет поле, `ВитринаНастроек` и `ПоляНастроек`
       берут отбитую форму вида `ВидОтбитыхЗначений`), над разделом — что из формы уже применено.
       Своим пультом значения пишет только брендирование: имена его полей без точек (их зеркалит
       образец) и форма записывается целиком или никак.
3. Окно новой записи печатается на странице всегда: `Кит.Окно(Заголовок, …).Форма("")
   .Адрес(Окна.Адрес(АдресРаздела, "новый")).БезПерезагрузки().Открыто(Окна.Открыто(Состояние, "новый"))`. Длинная форма — `Кит.Шаги`,
   правка той же записи — те же шаги `.Вид("вкладки")`. Исключение — окно, чей ответ несёт секрет
   (п. 9).
4. Окно правки, малые окна записи и подтверждение удаления приходят только по адресу. Витрина
   объявляет виды своих окон (`ВидыОкон()`, например «новый,изменить,удалить»), сама находит
   запись по ключу состояния и печатает её окно `.Открыто()`. Записи нет либо окно ей не
   положено — окна нет; это же витрина отвечает контроллеру функцией `ЕстьОкно(Состояние)`.
   Каждое окно и подтверждение закрывается словом кита `.АдресЗакрытия(АдресРаздела)` — адрес раздела
   без `?окно` (с отбором списка, если он есть): крестик и «Отмена» (у окна без формы — «Закрыть»;
   у окна шагами — первой в ряду кнопок шагов) кит печатает ссылками туда. Без скрипта окно закрывает
   переход, со скриптом — закрытие на месте (`data-closes`). Своих «Отмена» и «Закрыть» у окна нет.
   Окно сброса картинки брендирования — слово того же имени у слота: `Кит.СлотКартинки(…).АдресЗакрытия(…)`.
   Окно секрета, которое приходит ответом формы (токен, ссылка установки пароля, секрет подписи),
   закрывать на месте нельзя — секрет остался бы на странице, а вкладка на ответе формы, — поэтому
   оно закрывается только переходом: `.АдресЗакрытия(АдресРаздела).Переходом()` — крестик, «Закрыть»
   и Esc уводят на раздел без секрета и со скриптом.
5. Окна и подтверждения кладут в секцию соседями списка, а не в тело записи.
6. Значения полей окна — `Окна.Значение(Состояние, Имя, Действующее)`, флажки —
   `Окна.Отмечено(…)`, отказ под полем — `.Ошибка(Окна.Отказ(Состояние, Имя))`, отказ не к полю
   (`Окна.Ошибка(Состояние)`) — `Кит.Уведомление(…).Вид("err")` над полями. Правила поля — словами
   (`.Обязательное`, `.Шаблон`, `.Длина`, `.ТипЗначения("url")`), и правило не строже домена:
   что домен примет, браузер не отбивает. Длинное пояснение — `.Справка()`, строка под полем —
   `.Подсказка()`. Секрет обратно в поле не печатают.
7. Поля, которые нужны одному варианту выбора, кладут в набор его сегмента:
   `Кит.Сегмент(Значение, Подпись, поля…)`. На экране остаются поля выбранного варианта, и без
   скрипта тоже. Спрятанные поля уходят с формой со своими умолчаниями: пульт читает только
   поля пришедшего варианта, поля чужих наборов не читаются (отбивать их нельзя — отбилась бы
   любая отправка). Имена полей в разных наборах не повторяют — у одноимённых полей разбор берёт
   первое; поле, нужное нескольким вариантам, в каждом наборе получает своё имя. Одноимённое поле,
   которое видит домен (адрес, издатель, точки), домен проверяет по пришедшему варианту.
8. Адрес формы записи — относительный к разделу, ключ записи в нём кодирован:
   `КодироватьСтроку(Ключ, СпособКодированияСтроки.КодировкаURL) + "/save"`.
9. Ответ, который несёт секрет (выпуск токена), — не перенаправление, а страница раздела с окном
   секрета `.Открыто()`: секрет показан один раз и в адрес не попадает. Форма такого окна может
   уйти и тихой отправкой: ответ 2xx, который печатает другое окно открытым, кит закрывает окно
   формы и поднимает окно ответа сам. Обычная отправка, без `.БезПерезагрузки()`, — только там,
   где после ответа нужен переход на свежую страницу (окна подписки).
   Образцы — `аккаунт/настройки/` (`ОкноВыпускаТокена`, `КонтроллерТокеновКабинета`) и ссылка установки
   пароля в `хаб/люди/` (`ОкноУчётки.Выпуск`: после заведения учётки и после сброса пароля).
10. Выбор из многих объектов (пулы токена) — `Кит.ДеревоГалок(Узлы).Поиск(Адрес)` в наборе
   сегмента. Окно, которое стоит на странице всегда, печатает в дереве только первые узлы
   (у пулов токена — 20) и строку «показаны N из M», остальное находит поиск: разметка страницы
   не растёт с числом объектов. Адрес поиска отвечает той же страницей с открытым окном
   и деревом `.Найдено(…)`; отмеченные, которых на окне нет, едут скрытыми полями и названы
   словами («Уже отмечены: …»).
11. Дерево на сотни и тысячи узлов с режимом ветки (получатели подписки) —
   `Кит.ДеревоГалок(Пулы).Адрес(Дверь).Поиск(Дверь).Режимы(набор).ТолькоПравки().ПравкиБезСкрипта()
   .СводкаПравок().Отмеченные(ВнеПоказанного, Подпись).ПределОтмеченных(Предел, Всего, Адрес)` (у окна «Получатели» предел — 20)
   в окне по адресу: одна дверь на GET отвечает страницей раздела с окном на странице ветки
   (`?ветка=&страница=`, словом `.Ветка(ключ, страница, всего, режим)` — целиком, с сегментами режима)
   или на найденном (`?найти=`) — их берёт скрипт кита, без скрипта они стоят в том же окне; на POST —
   правки ветки `Кит.ПравкиВеткиДерева(Кит.РазобратьПравкиДерева(Тело), Ветка, Дети)` на обеих дорогах
   (режим, основа массовой отметки, включённые и снятые), удача — 303 обратно в окно. Отмеченное
   вне показанного — словом `Отмеченные`, чтобы его было видно и снять без скрипта. Образец —
   `панели/подписки/` (`ОкноПолучателей`, `ПравилоДереваПолучателей`).

### Пульт и контроллер

Исход каждой операции пульта — структура `Успех, Код, Сообщение, Отказы`: `Сообщение` — причина
словами, заполнена у любого отказа; `Отказы` — имя поля → отказ под полем. Контроллер раздела:

```bsl
&ТочкаМаршрута("<раздел>")      // GET — страница, POST — заведение
Процедура Раздел(Ответ, ЗаголовкиЗапроса, КукиЗапроса, МетодЗапроса, ТелоЗапроса, saved = "", окно = "") Экспорт
	// гвард; GET → ОтдатьРаздел(…, 200, Окна.ИзАдреса(окно, Витрина.ВидыОкон()), ЗначениеЗаполнено(saved))
	// POST → форма с принятым токеном → Завершить(…, Пульт.Создать(…), "новый", "", Форма)
КонецПроцедуры

&ТочкаМаршрута("<раздел>/{ключ}/delete")   // так же save, toggle и формы малых окон
Процедура Удаление(Ответ, ключ, …) Экспорт
	// пролог мутации: гвард → только POST → форма с принятым токеном
	// НЕ Окна.Подтверждено(Форма) → Окна.СпроситьПодтверждение(Ответ, АдресРаздела, ключ)
	// иначе Завершить(…, Пульт.Удалить(…), "удалить", ключ, Форма)
КонецПроцедуры

Процедура Завершить(Ответ, Запрос, Исход, ВидОкна, Ключ, Форма)
	// Исход.Успех → Окна.ВернутьВРаздел(Ответ, АдресРаздела)
	// Окно = Окна.Отбитое(ВидОкна, Ключ, Форма, Исход.Отказы, <Сообщение, если отказов у полей нет>)
	// ВидОкна и Витрина.ЕстьОкно(Окно) → ОтдатьРаздел(…, Исход.Код, Окно)
	// иначе ОтдатьРаздел(…, Исход.Код, Неопределено, Ошибка = Исход.Сообщение) — тост раздела
КонецПроцедуры
```

- `ОтдатьРаздел` собирает `Ответы.МодельДома(Дом, Объект, Дом.Разделы(Ключ), Уведомления, Секции,
  Защита.ТокенСессии(Вердикт.Сессия))`: токен — параметр модели дома, формы, окна
  и подтверждения внутри дома берут его и адрес раздела у дома. Вкладку браузера называет
  `Ответы.ОтдатьДом` сам — «Раздел · Заголовок дома · Объект» по текущему разделу модели; дом,
  чей объект один на все разделы (`ДомХаба` — инсталляция), отдаёт его функцией `Объект()`, и
  вкладка у всех его разделов одна по форме.
- Двери страниц (`Ответы.ОтдатьДом`, `ОтдатьСтраницу`, отказы 403/404/405, ворота
  `СтраницаДоступа.Отдать`) получают принципал целиком — вердикт гварда, контекст пульта или
  принципал стража с полями `Пользователь` и `Сессия`; разбирает его одно место
  (`общее/ПринципалСтраницы`), и пользователь вместо принципала — исключение, а не гостевая
  страница. Пользователь уходит в шапку и меню, сессия — в контекст страницы
  (`КонтекстСтраницы(…, Сессия)`). Форма «Выйти» единого меню
  (`ОбрамлениеХаба`, слот `Выход` — узлом) берёт токен у этой сессии; второй раз по куке сессию
  не читает никто — страница вошедшего читает её один раз, гвардом.
- `Окна.ИзАдреса(окно, Виды)` разбирает параметр `окно`: вид — до первого дефиса, ключ — после,
  с дефисами. Неизвестный вид — страница без окна, 200.
- Пульт формы окна отвечает исходом `ИсходОкна`: `Удача()`, `Отбито(…)` и `ОтбитоПолем(…)` —
  отказ над разделом, `ВОкне(Отказ, Вид, Ключ, Набранное)` — отказ в окне своей формы,
  `Спросить(Вид, Ключ)` — неподтверждённая опасная форма. Контроллер переводит исход в ответ.
- Удача формы окна — `Окна.ВернутьВРаздел`: 303 на раздел с отметкой «сохранено»; со скриптом
  окно закроется и список встанет на место. Отказ — та же страница с кодом отказа и окном,
  открытым на набранном, пока окно на странице есть, иначе причиной над разделом. Удаление без поля подтверждения — 303 на `?окно=удалить-<ключ>`, запись
  не трогается; несовпавшее эхо — 400 с открытым подтверждением.
- Адрес окна строит только `Окна.Адрес(АдресРаздела, Вид, Ключ)`: он кодирует имя и значение
  параметра целиком.

### Сторожа и выдача кита

Набор экрана — контроллер поверх настоящей службы домена (`ГвардХабаЗаглушка` впускает с
принципалом, страницу печатает каркас из `СборкаUI`). Он стережёт инварианты механизма, а не
разметку:
- GET `?окно=изменить-X` — `<dialog open>` с полями X; GET `?окно=новый` — окно заведения открыто;
- неизвестное окно — страница без окна;
- окно и подтверждение по адресу закрываются ссылками на раздел без `?окно` (`data-closes`), команды
  движка «закрыть» в них нет;
- POST с ошибкой — 4xx, окно открыто, поле `aria-invalid`, набранное на месте;
- отказ без окна (запись удалена, тумблер) — 4xx и причина на странице;
- удаление без подтверждения — 303 на окно подтверждения, запись цела;
- неверное эхо — 400, запись цела; верное — записи нет;
- тумблер меняет состояние в домене.

Узлы, которыми экран начинает печатать, добавляют тем же заходом в фикстуру
`tests/интерфейс/фикстуры/ВыдачаКита.os` (раздел «экран списка»): по ней сторожа имён полей,
работы без скрипта и мёртвого CSS видят новые узлы. Сменился адрес или форма раздела —
тем же заходом правится наполнитель демо-стенда `tools/демо/ЗаполнитьЧерезAPI.os`.

## Страницы-ворота

Вход, регистрация, восстановление и установка пароля, подтверждения адреса и входа из CLI,
мастер первого запуска и `/whoami` — экраны одной задачи. Их собирает `СтраницаДоступа` узкой
колонкой кита (`Кит.УзкаяСтраница`, как вход GitHub): знак хаба (загруженный логотип, иначе
знак поставки) и заголовок сверху, дальше — содержимое по порядку. Вокруг узкой страницы каркас
кита печатает только знак и переключатель темы: дорог, «Войти» и единого меню нет.

```bsl
Колонка = Страница.Колонка(Страница.ЗаголовокВхода(),   // «Вход в <название хаба>»
	Страница.Уведомление(Ошибка, "err"),                // отказ — в колонке над формой
	ФормаПароля(АдресВозврата),                         // «Забыли пароль?» — СсылкаРядом у поля
	Кит.Разделитель("или").Когда(ЕстьПровайдеры),
	КнопкиПровайдеров(Провайдеры, АдресВозврата),       // Область «столбик», кнопки вторичные
	СтрокаРегистрации(АдресВозврата));                  // Примечание вида «рамка»
Колонка.Добавить(Атрибуция.Сноска());                   // DB-IP — при правиле по стране
Страница.Отдать(Ответ, Статус, "Вход", Колонка, КукиЗапроса, Неопределено, ПутьВозврата);
```

- Одна колонка — один заголовок (`<h1>` шапки колонки) и одна форма; уведомления и отказы —
  внутри колонки, подсказка пароля — под полем. Вводный абзац ворот («Назовите логин…», мастер
  первого запуска, подтверждения) — подписью шапки колонки: `Страница.КолонкаСЛидом(Заголовок, Лид, д…)`.
- На ворота, куда приходят и вошедшим (`/cli/login`, `/confirm-email`, отказ выхода), колонка та
  же, а принципал запроса уходит в `Страница.Отдать(…, Принципал, Путь)`: вошедшему каркас кита
  печатает в шапке его учётку и единое меню без дорог (учётка, дела, настройки, «Выйти»), гостю —
  только знак и тему. Знак колонки и шапки — одно правило `ОбрамлениеХаба.АдресЗнака`.
- Форма «Выйти» в меню несёт токен сессии — той, что прочитал страж запроса (контекст страницы,
  `Сессия`); дверь `POST /logout` гасит живую сессию только с токеном этой сессии
  (`ГейтФормы.ТокенПринят`), иначе — 403 с причиной на воротах вошедшего, сессия цела; без живой
  сессии она только стирает куку. Сессию выключенной учётки (страж её не признаёт, меню с «Выйти»
  у человека нет) дверь гасит без токена: она ничего не открывает, подделывать её выход нечего.
- Значок кнопки провайдера — `общее/ЗначокПровайдера.Имя(Провайдер)`: поле «Значок» (имя значка
  кита — `бренд:<ключ>` или глиф; прежний ключ приводит домен, см. «Инварианты»), иначе бренд по издателю,
  пресету и типу (github, gitlab, google, authentik, keycloak, gitea, okta, discord, mattermost),
  иначе глиф «ключ». Общий ключ кита — служебный значок, не бренд: прежде выбранный `бренд:key`
  печатается тем же глифом «ключ»; им же нарисована пустая ячейка «По издателю» в окне провайдера.
- Атрибуция базы стран на воротах — `АтрибуцияБазыСтран.Сноска()` (примечание вида «сноска»): тихая строка внизу колонки
  при том же условии, что и примечание (`Печатается()`: есть правило по стране и индекс по базе).
- Сторож — `tests/интерфейс/ЭкранВхода_Тесты.os`: настоящие контроллеры ворот на каркасе и
  обрамлении хаба поверх окружения `фикстуры/ОкружениеЭкрановВхода`.
