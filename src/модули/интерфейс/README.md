# интерфейс

Всё, что человек видит в браузере: страницы хаба, их контроллеры и модели экранов, разделы
настроек, каркас страницы и словарь текстов. Правил предметов здесь нет — экран спрашивает
службы модулей; кнопки, таблицы, поля, тему и корень страницы даёт библиотека компонентов
`oscript-ui` (кит), которая о пакетах и пулах ничего не знает.

## Публичный интерфейс

По имени классы модуля не зовёт никто: наружу он отдаёт маршруты winow и реализации контрактов.

| Класс | Для чего | Методы |
| --- | --- | --- |
| `СтраницаСбояХаба` (контракт `основа/СбойХабаСловами`) | сбой запроса словами хаба: фраза в ответ машине, страница человеку | `Фраза(КодСбоя)`, `Страница(КодСбоя, Статус, КодЗапроса, КукиЗапроса)` |
| `СтраницаНеизвестногоАдреса` (контракт `основа/НеизвестныйАдресСловами`) | адрес без маршрута | `Фраза()`, `Страница(ЗаголовкиЗапроса, КукиЗапроса, ПутьЗапроса)` |
| `СловарьТекстов` (контракт кита `СловарьИнтерфейса`, `&Верховный`) | тексты экранов по ключам; его читает `ТекстыИнтерфейса` кита | `НайтиТекст(Ключ)`, `Ключи()` |
| `ОбрамлениеХаба` (контракт кита `ОбрамлениеИнсталляции`, `&Верховный`) | шапка с единым меню и подвал вокруг страницы кита | `Обрамление(Контекст)` |
| `ОформлениеХаба` (контракт кита `ОформлениеИнсталляции`, `&Верховный`) | тема и акцент инсталляции | `Оформление()`, `ИмяCookieОформления()` |
| `КлючиНастроекИнтерфейса` (контракт `настройки/КлючиНастроек`) | ключи оформления, хаба по умолчанию для opm и страницы журнала аудита | `Объявления()` |

Всё остальное — внутреннее.

## Зависимости

Использует: `основа`, `вход`, `права`, `реестр`, `настройки`, `публикация`, `зеркала`,
`подписки`, `кабинет`, `прокси`, `аудит`, `статистика`, `происшествия`, `хранилище`, `поиск`,
`описания`, `протоколAPI`, `гео`, `почта`, `уведомления` (и внешние библиотеки:
`oscript-ui`, `oscript-md`, `winow`, `autumn`, `url`).
Используется: `вход` — через контракты `основа/СбойХабаСловами`, `основа/НеизвестныйАдресСловами`;
`настройки` — ключи собирает `РеестрНастроек`.

## Настройки

| Ключ | Умолчание | Что делает |
| --- | --- | --- |
| `oshub.instance.opm_default_hub` | `false` | хаб — тот, которым opm пользуется без настройки: команды установки на страницах короче |
| `oshub.ui.theme` | `тёмная` | тема инсталляции по умолчанию; посетитель выбирает свою |
| `oshub.ui.accent` | пусто | цвет акцента `#rrggbb`; пусто — акцент темы |
| `oshub.ui.brand` | пусто | название хаба в шапке, заголовке вкладки и подвале |
| `oshub.ui.tagline` | пусто | подпись в подвале |
| `oshub.ui.show_name` | `true` | печатать ли название рядом со знаком |
| `oshub.ui.audit_page_size` | `20` | записей на странице журнала аудита |

## Где что лежит

Сверху — каркас, общий для всех страниц; панели, которые одинаково показывают один предмет
на разных экранах; и четыре района экранов. Районы между собой связаны только адресами
и домами настроек (`ДомПула`, `ДомПакета`, `ДомАккаунта`, `ДомГруппы`, `ДомХаба`).
Тексты района или панели лежат в его корне (`СловарьКабинета`, `СловарьПодписок`…) и реализуют
контракт `общее/ЧастьСловаряТекстов`; общий `общее/СловарьТекстов` держит тексты каркаса и получает
части от контейнера массивом.

| Каталог | Что внутри | Где видно |
| --- | --- | --- |
| `общее/` | каркас страницы: шапка с единым меню, подвал, бренд, тема, статика; страницы сбоя и «адрес не найден»; разбор и гейт формы, даты, примечания, отметка сохранения, ячейки таблиц; адреса каталога и кабинета; гварды приватной и публичной частей; словарь текстов; ключи настроек интерфейса | `POST /ui/theme` · `/static/{файл}` · `/brand/{файл}` · любой адрес без маршрута |
| `общее/настройки/` | каркас разделов настроек, одинаковый у всех пяти домов: бланк раздела, дерево разделов, окно формы, итог пульта, ответы и отказы | `…/settings/*` |
| `панели/подписки/` | раздел «Подписки на события»: карточка подписки — сводкой (название, состояние, способ доставки, события, теги, получатели, сужение снизу), форма разделами (куда, о чём, кому, текст) и действия одним рядом, галки отбора по тегам пула или пакета, кто её сузил, дерево получателей подписки хаба и пула (`?recipients={id}`, поиск `find`, галки — `…/webhooks/{id}/recipients`, `ПравилоДереваПолучателей` — правило галки пула и перевод галок в исключения), проверка до сохранения (`ПроверкаПодпискиДоСохранения`): предпросмотр уведомления у поля шаблона на лету и проба настройками формы с итогом у кнопки — `…/webhooks/preview`, `…/webhooks/{id}/preview`, `…/webhooks/test`, `…/webhooks/{id}/test`, скрипту — кусочком (`?fragment=1`), без скрипта — формой в новую вкладку; раздел «Подписки сверху» — подписки хаба и пула и поправка к ним, у пула — его пакеты в поправке к подписке хаба (то же дерево одним уровнем, `?recipients={id}`, галки — `…/webhooks/inherited/{id}/recipients`, пакет, снятый хозяином подписки, — закрытой галкой) | настройки пула, пакета и хаба |
| `панели/зеркала/` | поля зеркала, заведение и переключение, прогоны и происшествия | настройки пула, кабинет, `/office/mirrors` |
| `панели/права/` | таблица прав и выдача роли | настройки пула, пакета и группы |
| `панели/пакет/` | карточка и витрина пакетов (плашка «резерв» у имени без версий и кнопка его снятия), плашки тега и пула, значки меты и версии, команды opm | главная, каталог, страницы пула и пакета, кабинет |
| `панели/страна/` | посетитель запроса для гейта страны, отказ по стране, атрибуция базы стран | вход, привязки аккаунта, провайдеры входа |

## Инварианты

- Текст для человека — ключ словаря, а не литерал в экране.
- Экран спрашивает службу модуля-хозяина, а не его `Хранилище*`.
- Контроллер обслуживает один дом настроек.
- Формы списка пакетов пула печатаются мейнтейнеру пула и только по сессии; порог формы
  сервер проверяет сам, до разбора. Снятие резерва — всегда отдельным шагом подтверждения,
  который повторяет имя; вопрос задаётся только о пакете без единой версии.
- Гвард экрана печатает отказ сам и лежит рядом со своим экраном.
- Опасная зона пакета пустой не бывает: раздел есть в дереве и открывается по адресу, только когда
  у смотрящего есть необратимое действие — удаление пакета без версий мейнтейнером пула;
  иначе адрес раздела отвечает 404. Удавшееся удаление уводит на страницу пула.
- Карточку ссылки (`og:*`) несёт только страница пакета публичного пула. Страница с версией
  в запросе (`?version=`) — страница версии: показ тот же, карточка называет версию и ведёт
  на свой адрес; неизвестная версия даёт карточку пакета. Адреса карточки абсолютные,
  от внешнего адреса хаба: без него нет ни `og:url`, ни знака хаба картинкой. Картинка —
  социальная карточка репозитория на GitHub, иначе растровый знак хаба; загруженная SVG-иконка
  оставляет карточку без картинки.
- Блоки кода README с языком раскрашивает в браузере тег подсветки `oscript-md`
  (`MarkdownПодсветка.ТегСкрипта()`): он стоит в карточке описания один раз и только когда
  такие блоки есть, движок подсветки грузит с `esm.sh` — единственный внешний адрес страниц
  хаба; страница описания API `/swagger-ui.html` — страница winow, не хаба. Цвета обеих тем выбирает браузер по `color-scheme` темы хаба; фон блока — хабовый.
- Дерево получателей подписки печатается только в карточке, открытой ссылкой (`?recipients=`):
  пулы свёрнуты, в пуле — исключённые пакеты все и не больше сотни включённых, остальные
  находит поиск. Галка пула трёхпозиционная и выводится из пакетов: «снят» — пул исключён
  целиком (с будущими пакетами) или сняты все его пакеты, «частично» — снята часть, иначе
  «включён»; печатает её сервер, без скрипта тоже. Форма галок несёт перечень показанных узлов
  и меняет только их; за пул решает `ПравилоДереваПолучателей` по виду экрана — галке пула,
  галкам показанных пакетов и напечатанному состоянию: сняты все — пул снят целиком; снятый
  пул отмечен со всеми показанными — включён со всеми пакетами; иначе пул включён, пакеты —
  по галкам. Со скриптом и без одна и та же картинка сохраняется одинаково.
  Пакет, появившийся после отрисовки, у включённого пула остаётся включённым.
- Предпросмотр и проба формы подписки работают и без скрипта: место предпросмотра скрыто,
  кнопки шлют форму в новую вкладку. Скрипт шлёт поля формы на адрес из `data-sub-preview`
  и `data-sub-trial` и вставляет узел `[data-sub-result]` ответа; секретные поля
  (`data-sub-omit`) в предпросмотр не уходят, сообщение собирает только сервер.
- Поле текста уведомления печатается по декларации канала (`ПоляПодписки`): пустое поле
  показывает готовый текст декларации — у Telegram шаблон по умолчанию, — а под полем свёрнут
  перечень вставок списком «`{имя}` — что подставится» из той же декларации.
