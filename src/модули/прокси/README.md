# Прокси

Модуль отвечает за одно: **как хаб ходит к чужим хабам** — к источникам пула (апстримам)
и к источнику зеркала. Здесь живут поход наружу, кэш изменяемых ресурсов, объединение
чужих версий со своими и память о том, жив ли источник. Своих экранов и своих ручек API
у модуля нет: разметку печатает `интерфейс`, JSON — `api`.

| Класс | Что делает |
| --- | --- |
| `КлиентАпстрима` | один поход наружу: заголовки, таймауты, тело |
| `ПробникИсточника` | пробное подключение по контракту opm |
| `ПричинаМолчания` | почему источник не ответил — одной фразой: слово плюс корневая причина |
| `АдресаИсточников` | где у записи источника адрес и каким он ключом |
| `СтражАпстримов` | память процесса о живости адреса и об отказе доступа |
| `ЛетописьИсточников` | письменный двойник этой памяти: происшествия подсистемы «источник» |
| `СостояниеИсточников` | состояние источника одним словом для экрана и карточки API |
| `ОбходЗдоровьяИсточников` | регулярная проверка всех включённых источников |
| `СервисПрокси`, `РезолверВыдачи`, `ИндексВерсийИсточника`, `ОбъединённыйНаборВерсий` | выдача: свой пул → источники по порядку → кэш → 404 |
| `КэшИзменяемыхРесурсов`, `СборщикКэшаПрокси`, `СверкаETag` | срок жизни привезённого и его уборка |
| `СекретИсточника`, `ЗаведениеИсточника`, `РазборВерсийПакета`, `НаблюдательКоллизийИмён` | токен доступа, заведение источника, разбор чужих перечней |

## Память о живости и её письменный двойник

**Вердикт живёт в памяти процесса** (`СтражАпстримов`), ключом — адрес без учёта регистра:
один адрес, заведённый и пулом, и зеркалом, помнится один раз. Отметка протухает по
`oshub.proxy.upstream.recheck.ttl.sec`, и протухшая означает «неизвестно» — источник
получает свой честный запрос. Пополняют её двое: регулярный обход здоровья и любой боевой
запрос выдачи или синка.

**Диагностика транспорта фразой не является.** Клиент отдаёт наружу блоб со служебной
обёрткой платформы, путями внутрь контейнера и номерами строк чужой библиотеки, и приходит
он не только из пробы, но и с горячего пути выдачи. Поэтому причину нормализует **граница
стража** — `ОтметитьЛежащим` зовёт `ПричинаМолчания.Словами` до того, как причина попадёт
хоть куда-нибудь: и в память, и в письменный двойник, и на экран уходит одна и та же фраза.
Правило одно на модуль, второго разборщика нет: `ПробникИсточника` зовёт его же.

**Тот же вердикт пишется в базу происшествием** (`ЛетописьИсточников` поверх `помехи/ЛетописьПомех`,
подсистема `источник`, объект `источник/<обезличенный адрес>`) — затем, чтобы причина
молчания пережила перезапуск хаба. Страж зовётся на КАЖДОМ боевом запросе, поэтому в базу
двойник ходит редко:

- **пишет** немедленно на смене КОДА состояния (жив → лежит, лежит → не пустил) и,
  если код держится, не чаще раза в срок перепроверки — но не чаще раза в минуту, даже
  если срок перепроверки выключен нулём. Смена одного лишь текста причины срока не
  отменяет: флапающий источник иначе диктовал бы запись на каждый неудачный запрос,
  а без повторов по сроку «когда в последний раз» застыло бы на моменте перехода;
- **снимает** при возврате источника в работу — и только если за адресом что-то числится.
  Признак «числится» тоже живёт в памяти процесса, поэтому тысяча удачных запросов к живому
  источнику стоит **ноль** обращений к базе; один раз после старта хаба страж всё же сверяет
  базу — иначе прошлая причина осталась бы висеть на поднявшемся источнике.

**Складывает одно с другим `СостояниеИсточников`** — одна доменная функция на экран
(`интерфейс/настройки/пул/ВитринаАпстримов`) и на карточку API (`api/КонтроллерАпстримовAPI`).
Она отвечает словом `alive` · `down` · `denied` · `unknown` и отдельно — прошлой неудачей
из письменной памяти. После перезапуска источник честно числится **непроверенным**, а
причина, по которой он молчал, названа отдельной строкой: прошлое наблюдение за нынешний
вердикт не выдаётся. Первая же проверка либо снимет происшествие, либо подтвердит его.

Слово `disabled` в словаре тоже есть, но говорит его не эта функция: живость — свойство
адреса, тумблер — свойство записи источника, и складывает их тот, у кого запись в руках.

## Мины этого слоя

- **Письменная память не бросает наружу, читатель — бросает.** `ЛетописьПомех` молчит
  по построению: выдача не имеет права упасть из-за объяснения неудачи. `ЧитательПомех`
  наоборот бросает, поэтому `СостояниеИсточников` ловит его сам: на лежащей базе экран
  источников нужен больше всего, и вердикт памяти он показывает и без письменной части.
- **Карты стража правятся copy-on-write.** В них пишут и фоновый обход здоровья, и потоки
  запросов выдачи; структурная правка `Соответствие` из двух потоков портит её
  (ЗНАНИЕ §1.8). То же правило — у `ЛетописьИсточников`.
- **«Не пустил» — свойство ДОСТУПА, а не адреса.** Отказ помнится по паре «адрес +
  отпечаток токена»: соседний источник с тем же адресом от чужого отказа не страдает.
  Письменная причина при этом одна на адрес — у неё свой код, `upstream_denied`.
- **Токен в память не попадает.** В ключах отказа живёт отпечаток, в адресе объекта происшествия —
  обезличенный адрес, а значение токена уезжает в `Записать` отдельным параметром `Секрет`,
  чтобы его вычеркнули из причины.
