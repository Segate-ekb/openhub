# описания

Что показать на вкладке «Описание» у пакета: README версии в безопасном HTML и откуда он взят.
Текст снимается с `.ospx` один раз и лежит файлом рядом с артефактом; если README в пакете нет,
его ищут в репозитории пакета на GitHub. Относительные ссылки и картинки README ведут в репозиторий
пакета: самих файлов на хабе нет. Какую версию показывать и когда писать файл, решает
`реестр`; байты хранит `хранилище`; разметку страницы печатают `интерфейс` и `api`.

## Публичный интерфейс

| Класс | Для чего | Методы |
| --- | --- | --- |
| `СлужбаREADME` | описание версии для показа (безопасный HTML с относительными адресами, разрешёнными от репозитория пакета, есть ли в нём блоки кода с языком, источник — пакет или тег либо ветка на GitHub) и для ночной актуализации: диск, при промахе — артефакт | `ПредставлениеREADME(Пул, Пакет, Версия)`, `ОбеспечитьОписаниеНаДиске(Пул, Пакет, Версия)` |
| `СлужбаREADMEРепозитория` | README из репозитория пакета на GitHub для версии с пустым описанием: настройка, адрес на github.com, не чаще раза в сутки на версию (смена адреса — новый вопрос), отказ GitHub — строка журнала | `Дополнить(Пул, Пакет, Версия)` |
| `ХранилищеREADME` | файл описания версии и справка о репозитории рядом с ним (найденный README лежит в справке): запись при приёме версии, снятие при уборке пакета | `Записать(ИмяПула, ИмяПакета, Версия, Текст)`, `Снять(ИмяПула, ИмяПакета, Версия)` |
| `ИменаКэшейОписаний` (контракт `наблюдаемость/ИменаКэшей`) | кэш модуля для приборов кэшей | `Имена()` |

Только то, что зовут другие модули. Всё остальное — внутреннее.

## Зависимости

Использует: `основа`, `сеть`, `настройки`, `хранилище`, `наблюдаемость`; библиотеки `oscript-md`, `ospx-tools`,
`errors`, `autumn-cache` (без неё в контейнере представление собирается на каждый показ).
Используется: `реестр`, `api`, `интерфейс`.

## Настройки

Ключи объявляет `КлючиНастроекОписаний`.

| Ключ | Умолчание | Что делает |
| --- | --- | --- |
| `oshub.readme.repository.enabled` | `true` | искать README в репозитории пакета на GitHub, если в пакете его нет; `false` — хаб за ним наружу не ходит |
| `oshub.readme.repository.raw.url` | `https://raw.githubusercontent.com` | откуда берутся файлы репозиториев GitHub |

Готовые представления лежат в кэше autumn-cache `представленияREADME` — в общем бюджете памяти
`cache.ПределПамяти`, без срока жизни; свой предел и срок задают ключи `cache.представленияREADME.*`.

## Где что лежит

| Каталог | Что внутри |
| --- | --- |
| `Классы/` | `СлужбаREADME` — путь до описания; `ХранилищеREADME` — файлы описания и справки на диске; `ИсточникREADME` — README из `.ospx`; `СлужбаREADMEРепозитория` — когда спрашивать репозиторий; `ИсточникREADMEGitHub` — README с тега версии либо из ветки по умолчанию; `КоординатыREADME` — имена `{пакет}-{версия}.readme.md` и `{пакет}-{версия}.readme.json`; `ПамятьПредставленийREADME` — готовые представления в кэше (`&Кэшируемый`, сброс `&СбрасываетКэш`); `РендерерREADME` — Markdown в безопасный HTML по пресету GitHub, повторная санитизация и признак блоков кода с языком; `СсылкиREADME` — относительные `href` и `src` отрисованного README в адреса репозитория; `АдресаРепозитория` — репозиторий по адресу из карточки (GitHub, GitLab, Gitea и Forgejo, Bitbucket, похожие на GitHub), страница файла и сам файл в нём; `КлючиНастроекОписаний` — ключи модуля; `ИменаКэшейОписаний` — кэш модуля |

## Инварианты

- Пустой текст — законный ответ «README в пакете нет» и запоминается наравне с непустым; пустой файл узнаётся по размеру и не скачивается, а лежащее описание ночной обход узнаёт по размеру, не читая.
- Файлы описания и справки адресуются именем пакета и версией из реестра: версия, присланная с именем в другом регистре, ложится туда же, откуда её описание читают и снимают.
- Недоступный артефакт на диске не запоминается: описание соберётся при следующем показе.
- README из пакета главнее: непустое описание в репозиторий не ведёт и показывается мимо справки; справка ложится, только пока описание пусто, запись описания из пакета её снимает.
- Показ в сеть не ходит: README из репозитория кладут на диск фон публикации и ночной обход `реестр`.
- Готовое представление версии собирается один раз: ключ — имена пула и пакета без учёта регистра и версия, адрес репозитория хранится рядом и при расхождении с карточкой даёт сборку заново. Запись, пришедшая во время сборки, собранное не даёт запомнить. Запись описания или справки и снятие описания проходят через `ХранилищеREADME` и забывают представление этой версии. Ответ, собранный при недоступном артефакте или без справки, не запоминается.
- Описание не роняет ни приём версии, ни страницу пакета: сбой пишется в журнал и даёт пустой ответ.
- Недоверенный Markdown — из пакета и из репозитория — всегда проходит санитизацию; разметка, где относительный адрес заменён адресом репозитория, проходит её ещё раз.
- Относительный адрес README на хаб не ведёт: он становится адресом файла в репозитории пакета (путь — от каталога README, «..» выше корня репозитория не выводит) либо снимается — ссылка остаётся текстом, картинка подписью. Разрешение идёт без сети, а смена адреса репозитория в карточке сразу меняет ссылки всех версий.
