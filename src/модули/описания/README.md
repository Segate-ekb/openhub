# Описания

Модуль отвечает на один вопрос: что показать на вкладке «Описание» у пакета. README лежит
внутри `.ospx`, распаковывать который на каждый показ страницы дорого, поэтому текст
снимается один раз — при приёме версии — и кладётся файлом рядом с артефактом. Страница
пакета и `GET /api/v1/pools/{пул}/packages/{имя}/readme` читают уже этот файл.

Показывается описание не любой версии, а той, которую отдаёт установка без тега и номера.
Такая версия меняется и без публикаций — отзывом версии, сменой канала по умолчанию, —
поэтому ночная задача `переиндексация-readme` обходит пакеты и дописывает недостающие
описания. Старт хаба её не ждёт: промах на странице не ошибка, описание соберётся при
первом же показе.

| Класс | За что отвечает |
| --- | --- |
| `КоординатыREADME` | имя файла описания в хранилище — `{пакет}-{версия}.readme.md` |
| `ХранилищеREADME` | описание на диске: запись, чтение, снятие |
| `ИсточникREADME` | снять README с `.ospx`; отличает «README в пакете нет» от «артефакт недоступен» |
| `РендерерREADME` | недоверенный Markdown в безопасный HTML: библиотека `oscript-md`, пресет в стиле GitHub |
| `СлужбаREADME` | то, что видит потребитель: диск, при промахе — артефакт, запись на диск, рендер |
| `АктуализаторОписаний` | ночной обход: у каждого пакета описание его версии по умолчанию оказывается на диске |

![Описание пакета на его странице](../../../docs/screenshots/package.png)

*README пакета, отрисованный в HTML, — это и есть вся видимая работа модуля.*

Записывает описание не этот модуль, а приём версии в `реестр`: пакет там уже прочитан,
и текст README приезжает туда параметром. Какая версия «нужная», тоже решает `реестр` —
одним правилом на весь хаб, чтобы обход и страница не разошлись. Байты берутся из
`хранилище`. Разметку модуль не печатает: он отдаёт готовый безопасный HTML, а вставляют
его страница пакета из `интерфейс` и `api`.

Чем пакет отличается от версии и что такое пул — в [корневом README](../../../README.md).
