# описания

Что показать на вкладке «Описание» у пакета: README версии в безопасном HTML. Текст снимается
с `.ospx` один раз и лежит файлом рядом с артефактом. Какую версию показывать и когда писать
файл, решает `реестр`; байты хранит `хранилище`; разметку страницы печатают `интерфейс` и `api`.

## Публичный интерфейс

| Класс | Для чего | Методы |
| --- | --- | --- |
| `СлужбаREADME` | описание версии для показа и для ночной актуализации: диск, при промахе — артефакт | `ПредставлениеREADME(Пул, Пакет, Версия)`, `ОбеспечитьОписаниеНаДиске(Пул, Пакет, Версия)` |
| `ХранилищеREADME` | файл описания версии: запись при приёме версии, снятие при уборке пакета | `Записать(ИмяПула, ИмяПакета, Версия, Текст)`, `Снять(ИмяПула, ИмяПакета, Версия)` |

Только то, что зовут другие модули. Всё остальное — внутреннее.

## Зависимости

Использует: `основа`, `хранилище`; библиотеки `oscript-md`, `ospx-tools`.
Используется: `реестр`, `api`, `интерфейс`.

## Где что лежит

| Каталог | Что внутри |
| --- | --- |
| `Классы/` | `СлужбаREADME` — путь до описания; `ХранилищеREADME` — файл описания на диске; `ИсточникREADME` — README из `.ospx`; `КоординатыREADME` — имя файла `{пакет}-{версия}.readme.md`; `РендерерREADME` — Markdown в безопасный HTML по пресету GitHub |

## Инварианты

- Пустой текст — законный ответ «README в пакете нет» и запоминается наравне с непустым.
- Недоступный артефакт на диске не запоминается: описание соберётся при следующем показе.
- Описание не роняет ни приём версии, ни страницу пакета: сбой пишется в журнал и даёт пустой ответ.
- Недоверенный Markdown всегда проходит санитизацию.
