# src/модули/описания — README пакета на витрине

Модуль отвечает на один вопрос: **что показать на вкладке «Описание»**. README живёт
внутри `.ospx`, распаковывать который на каждый показ страницы дорого, поэтому текст
снимается один раз — **при приёме версии** — и кладётся файлом рядом с артефактом.
Страница и `GET …/readme` читают этот файл. Рестарт хаба на это не влияет: **стартового
прогрева в хабе нет**, диск переживает перезапуск сам.

Показывается описание не любой версии, а **той, которую отдаёт установка без тега
и версии**, — а она меняется и без публикаций: отзывом версии и сменой канала
по умолчанию. Поэтому у диска есть ночная актуализация: задача планировщика
`переиндексация-readme` обходит пакеты и обеспечивает описание нынешней версии
по умолчанию. Это не прогрев старта — гейт готовности хаба её не ждёт.

## Карта классов

| Класс | Ответственность |
| --- | --- |
| `КоординатыREADME` | имя файла описания в хранилище — `{пакет}-{версия}.readme.md`, единственное место этого знания |
| `ХранилищеREADME` | описание на диске: запись, чтение, снятие; наружу не бросает ничего |
| `ИсточникREADME` | снять README с `.ospx` (распаковка); отличает «README в пакете нет» от «артефакт недоступен» |
| `РендерерREADME` | недоверенный Markdown → HTML → санитизация (oscript-md, пресет GitHub-like) |
| `СлужбаREADME` | то, что видит потребитель: диск → (промах) артефакт → диск → рендер; тот же путь без рендера — ответ «описание на диске есть» |
| `АктуализаторОписаний` | ночной обход: у каждого пакета описание его версии по умолчанию оказывается на диске |

## Границы

- **Записывает описание приём версии, а не этот модуль.** `реестр/ПриёмВерсии` — общее ядро
  push, зеркала и прокси: у всех трёх пакет уже прочитан, и текст README приезжает туда
  параметром. Своей точки входа «закэшируй мне» модуль не предлагает.
- **О пулах, пакетах и версиях как о сущностях знает ровно один класс — `АктуализаторОписаний`**:
  чтобы обойти пакеты, ему нужны `СервисПакетов`, `СервисПулов` и `РезолверСпецификации`.
  Остальным хватает имён и строк, которыми адресуется файл, а из чужого — только
  `ХранилищеАртефактов`.
- **Какая версия «нужная» — решает не этот модуль.** Правило одно на весь хаб и живёт
  в `реестр/РезолверСпецификации.ВерсияПоУмолчанию`; им же живёт страница пакета. Второй
  копии правила быть не должно: обход дозаполнял бы диск не тем, что показывает страница.
- **Разметку модуль не печатает.** `СлужбаREADME` отдаёт санитизированный HTML чужого
  документа; вставляет его в страницу `интерфейс/пакет/КонтроллерПакета`, в JSON — `api`.
- **Промах диска — не ошибка, а версия, чьё описание на диск ещё не попало** (принята
  до появления кэша либо стала версией по умолчанию после смены канала). `СлужбаREADME`
  снимет её описание с `.ospx` и тут же положит на диск; ночной обход идёт тем же путём —
  своего способа записи у него нет.

## Мины этого слоя

- **Файл описания лежит в области пула и входит в его объём честно** — килобайты рядом
  с мегабайтными артефактами. Приём версии учитывает эти байты в счётчике пула сам
  (`ЗаписьЗанятогоМеста`), уборка пакета их же возвращает. Единственное место, где счётчик
  расходится с диском, — дозапись на промахе чтения: её учитывает уже плановая
  `СверкаОбъёмовПулов`.
- **Гейт квоты описание не спрашивает**: решение «влезет ли» принимается по размеру
  артефакта, и пул вправе перевалить квоту на размер README. Следующая публикация будет
  отвергнута — это и есть починка.
- **Имя `{пакет}-{версия}.readme.md` выбрано так, чтобы НЕ читаться как `{пакет}-{версия}.ospx`**:
  сборщик кэша прокси разбирает имена файлов и вытесняет только артефакты. Переименование
  файла описания меняет поведение GC — это не косметика.
- **Вытеснение артефакта из кэша прокси описание не уносит**: страница проксированного
  пакета продолжает показывать README, когда самого `.ospx` под пулом уже нет. Файл
  вернётся на место при следующей закачке, а уборка пула сносит область целиком.
- **Пустой файл — это ответ, а не сбой.** Ноль байт означает «у версии README нет»;
  без такой записи страница пакета без README распаковывала бы `.ospx` на каждый показ.
  А вот «артефакт недоступен» ответом не считается и на диск не попадает: моргнувшее
  хранилище иначе оставило бы версию без описания навсегда.
- **Имя описания на пять символов длиннее имени артефакта**, а сегмент пути ограничен
  сотней символов. У пакета, чьё `{пакет}-{версия}` попало в узкую полосу 91–95 символов,
  артефакт адресуется, а описание — уже нет: такой пакет живёт без дискового кэша и
  распаковывает `.ospx` на каждый показ. Принято как есть; в журнале это `Отладка`,
  а не предупреждение, — свойство имени, а не сбой, и повторяется оно на каждый показ.
- **Single-flight нет сознательно.** Одновременные читатели версии, чьё описание ещё
  не на диске, распакуют её каждый и запишут одно и то же.
- **Обход опережает читателя, а не заменяет ему источник.** Задача `переиндексация-readme`
  best-effort: пакет без пула, без версии по умолчанию и с недоступным артефактом она
  просто считает пропущенным. Страница такого пакета соберёт описание сама на первом показе.
