# api

Машинные ворота хаба: маршруты `/api/v1`, выдача пакетов для `opm` (`list.txt`, `.ospx`, короткие
адреса `/download`, `/dev-channel`), срез изменений для зеркал и паспорт описания API. Контроллер
пускает запрос через ворота и отдаёт ответ; правила домена живут в модулях предметов, а соглашения
протокола — чтение тела, отказы маршрута, страницы, адрес артефакта — в `протоколAPI`.

## Публичный интерфейс

| Класс | Для чего | Методы |
| --- | --- | --- |
| `ПаспортОписанияAPI` | раздел `info` описания API (заголовок, сводка, шапка, лицензия) и шаблон описываемых путей; его ставит загрузка настроек до контейнера | `Заголовок()`, `Сводка()`, `Шапка()`, `ИмяЛицензии()`, `ИдентификаторЛицензии()`, `ШаблонПутей()` |

Маршруты winow собирает из `&Контроллер` сам; остальные классы — внутренние.

## Зависимости

Использует: `основа`, `протоколAPI`, `настройки`, `события`, `вход`, `права`, `реестр`,
`описания`, `статистика`, `поиск`, `прокси`, `публикация`, `подписки`, `зеркала`, `кабинет`,
`состояние`; библиотеки `winow`, `errors`.
Используется: `запуск` (`ПаспортОписанияAPI`).

## Где что лежит

| Каталог | Что внутри |
| --- | --- |
| `общее/` | ворота: кто пришёл (`ДопускAPI`), вправе ли менять (`ГейтМутацииAPI`), двери в пул и пакет — 404 (`ДвериAPI`), пороги права — 403 (`ПорогиПравAPI`), пролог правки пакета и администрирования пула (`ПрологПравкиAPI`), общие схемы описания: итог удаления и снятия, тело без полей |
| `хаб/` | настройки хаба, живость и числа по адресу API, паспорт описания; адреса: `hub/settings`, `health`, `metrics` |
| `пулы/` | пулы, их настройки (с галкой `pool_tags`) и квота, теги пула, пул в JSON; адреса: `pools`, `pools/{пул}`, `…/default`, `…/settings`, `pools/{пул}/tags` |
| `пакеты/` | пакеты пула, версии и публикация, теги пакета с унаследованными от пула и выключение тега пула у пакета, поиск, форма пакета и версии (`СборщикКарточкиПакета`); адреса: `…/packages`, `…/versions`, `…/tags`, `…/tags/{тег}/disabled`, `tags/preview`, `search` |
| `выдача/` | выдача для `opm` и вечные короткие адреса, разбор имени файла, срез изменений пула; адреса: `…/download/…`, `/download/…`, `/dev-channel/…`, `…/changes` |
| `публикация/` | «входящие» и доверенные конвейеры; адреса: `inbox`, `…/inbox/…`, `…/trusted-workflows` |
| `источники/` | апстримы и зеркала пула; адреса: `…/upstreams`, `…/mirrors` |
| `доступ/` | регистрация, группы и сопоставления клеймов, права на пул и пакет; адреса: `users`, `groups`, `oidc-mappings`, `…/grants` |
| `подписки/` | подписки хаба, пула и пакета и их справочник, дерево получателей подписки хаба и пула с исключениями, подписки сверху с поправками нижестоящего объекта, пакеты пула в его поправке к подписке хаба; адреса: `webhooks`, `…/webhooks`, `…/webhooks/{id}/recipients`, `webhook-meta`, `…/inherited-webhooks`, `…/inherited-webhooks/{id}/recipients` |

Классы `…JSON` в каталоге предмета — схемы описания API: тело ответа (`&Возвращает(…, Тип = …)`) и тело запроса
(`&Тип` на параметре `ТелоЗапросаОбъект`). Ответ собирает представление предмета, класс его только описывает: поле
`&Сериализуемое("имя")`; есть всегда — `&Заполнено`; есть всегда и бывает null — `Обязательное = Истина`; бывает не
всегда — без них. У адреса с несколькими глаголами одна схема на код — объединение полей глаголов.

## Инварианты

- Закрытый пул или пакет неотличим от отсутствующего: оба дают 404.
- Мутация проходит гейт: сессия — CSRF-токен, ключ доступа — скоуп записи и привязку к пулу.
- Отказ — JSON `{error: {code, message}}`; текст исключения домена наружу не уходит.
- Ответы API не ставят сессионную куку.
- Файлы ходят потоком: `.ospx` выдачи уходит `Ответ.ТелоПоток` из хранилища, а на промахе кэша
  удалённого хранилища — `Ответ.УстановитьТелоИзФайла(Путь, Размер)` из файла, который ещё качается;
  тело публикации принимается параметром `ТелоЗапросаПоток` и в память целиком не читается.

- Схема ответа совпадает с ответом: поле, которого нет в классе, — расхождение.

## Тесты

`scripts/тесты.sh api` — наборы `tests/api/`; `--e2e` добавляет `tests/e2e/api/`. Схемы стерегут
`tests/api/РазметкаСхемAPI_Тесты.os` (у каждого ответа и JSON-тела точки под `/api/` назван тип) и
`tests/e2e/api/СхемыОписанияAPI_Тесты.os` (каждая операция вызывается, каждый ответ сверяется со схемой).
