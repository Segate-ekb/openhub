# публикация

Как пакет попадает в пул: push ключом доступа, заявка во «входящие» пула, когда права нет,
доверенный конвейер CI и раздача прав по доступу к GitHub-репозиторию. Модуль решает, пустить
ли пакет, и отдаёт его дальше: версию заводит `реестр`, байты `.ospx` кладёт `хранилище`,
исход заявки заявителю сообщают `уведомления`.

## Путь публикации

1. Адреса `/push`, `/pools/{пул}/push` и `/api/v1/pools/{пул}/push` принимает
   `КонтроллерПубликации`; всё остальное делает `СервисПубликации`.
2. Размер тела и пул; рамки ключа доступа — до чтения тела.
3. Разбор `.ospx`: манифест, имя пакета, `FILE-NAME` против манифеста — отказ 400.
4. Допуск: право в хабе, легаси-токен GitHub в основном пуле либо доверенный конвейер
   (`доверие/`) — клеймы id-token, вернувшиеся вместе с подтверждённой подписью.
5. Права нет, имя свободно, пул виден человеку — заявка ложится во «входящие» (`202`).
   Мейнтейнер пула одобряет её (`РассмотрениеВходящих.Одобрить`): версия публикуется
   от имени заявителя, заявитель становится мейнтейнером пакета. Отказ снимает артефакт.
6. Право есть — правила приёма, адрес репозитория у первой версии, квота пула, укладка
   артефакта и версии; затем владелец пакета, занятое место, метка канала и событие
   «версия опубликована».

## Публичный интерфейс

| Класс | Для чего | Методы |
| --- | --- | --- |
| `СервисПубликации` | приём push из `api` | `Опубликовать(ИмяПула, Данные, ИмяФайла, Канал, Пользователь, Токен, Принципал, Форсировать)`, `ЭтоФорс(Значение)` |
| `РассмотрениеВходящих` | заявки для экранов и API: кому видны, решение по заявке | `СтрокиПула`, `ОжидающиеПринципала`, `СколькоЖдётРешения`, `ЗаявкаКРассмотрению`, `Одобрить`, `Отклонить` |
| `СервисРезервированияИмён` | пакет-плейсхолдер под будущего издателя | `Зарезервировать`, `СнятьРезерв`, `Резервы` |
| `СервисДоверияCI` | записи доверенных конвейеров пакета | `КонвейерыПакета`, `СтрокиПакета`, `ДопустимыеПровайдеры`, `ПровайдерGitLab`, `МожетНастраивать`, `Доверить`, `ОтозватьДоверие`, `ОжидаемаяАудитория`, `ОписаниеЗаписи` |
| `КороткаяФормаДоверия` | поля формы доверия: короткие значения, ссылка на файл конвейера | `ЗначениеДляФормы`, `РазобратьСсылку`, `АдресаЗаписи` |
| `СтражИздателейCI` | издатели id-token, которым хаб доверяет | `Нормализовать`, `РазрешённыеИздатели`, `ИздательПоУмолчанию` |
| `МаскаРефа` | широта маски рефа для предупреждения на форме | `СлишкомШирокая` |
| `ВидРефаДоверия` | словарь «ветка / тег» формы и API | `Ветка`, `Тег`, `ПоЗначению` |

## Зависимости

Использует: `основа`, `сеть`, `данные`, `наблюдаемость`, `фоновыеЗадания`, `события`, `аудит`,
`настройки`, `хранилище`, `уведомления`, `реестр`, `права`, `вход`; библиотеки `autumn-data`,
`entity`, `ospx-tools`, `jwt-verify`, `url`, `errors`.
Используется: `api`, `интерфейс`, `вход` (контракт `АвтовыдачаПравGitHub`), `реестр`
(последствия удаления), `настройки`, `подписки` (объявления).

## Настройки

| Ключ | Умолчание | Что делает |
| --- | --- | --- |
| `oshub.publish.max_upload_bytes` | `26214400` | предел тела push в байтах |
| `oshub.publish.max_unpacked_bytes` | `67108864` | предел распакованного `.ospx` |
| `oshub.publish.max_files` | `5000` | предел числа файлов в `.ospx` |
| `oshub.publish.max_manifest_bytes` | `524288` | предел размера манифеста |
| `oshub.publish.github_legacy` | `false` | принимать легаси-токен GitHub в основном пуле |
| `oshub.publish.github.org` | `oscript-library` | организация GitHub для легаси-токена и раздачи прав |
| `oshub.publish.ci.audience` | пусто | ожидаемый `aud` id-token; пусто — `oshub.instance.url` |
| `oshub.publish.ci.issuers` | пусто | издатели id-token сверх GitHub и GitLab, через запятую |
| `oshub.publish.inbox.max_pending_per_pool` | `50` | ожидающих заявок в пуле; `0` выключает приём заявок |
| `oshub.publish.inbox.max_pending_per_user` | `5` | ожидающих заявок у автора; `0` выключает приём заявок |

Адрес GitHub REST для раздачи прав — деталька `oshub.publish.github.api` (по умолчанию
`api.github.com`): задаётся конфигурацией инсталляции, на экране настроек её нет; её же читает
`права`.

## Где что лежит

| Каталог | Что внутри |
| --- | --- |
| `push/` | контроллер маршрутов push и `СервисПубликации` |
| `входящие/` | очередь заявок и решение по ней; таблицы заявок и снимков манифеста; снятие заявок удаляемого пула |
| `резерв-имён/` | `СервисРезервированияИмён` |
| `доверие/запись/` | записи доверия и их сверка: короткие формы полей, маска и вид рефа, имя записи, страж издателей; таблица доверия; снятие доверия удаляемого пакета |
| `доверие/токен/` | проверка id-token: подпись по JWKS (контракт `ПроверяющийПодписиCI`), транспорт и кэш ключей, аудитория, срок |
| `github/` | раздача прав по доступу на запись в репозиторий: контракт `КаталогРепозиториевGitHub` и его HTTP-реализация, фоновое задание раздачи |
| `общее/` | ключи настроек и описания событий публикации |

## Инварианты

- Отказ по правилу назван раньше первой записи: отклонённый push не оставляет ни файла, ни строки каталога, ни занятого места.
- Во «входящие» уходит только аутентифицированный человек со свободным именем в видимом ему пуле; остальное — 403.
- Доверенный конвейер публикует только существующий пакет и решается по клеймам подтверждённой подписи; каждое заполненное поле записи обязано совпасть.
- За ключами JWKS хаб ходит только к издателям из закрытого списка и только по https.
- Раздача прав по GitHub не роняет вход: её сбой уходит в журнал.
