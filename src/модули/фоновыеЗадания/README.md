# фоновыеЗадания

Движок фоновой работы хаба: регулярные задачи по расписанию, запуск работы в фоне без ожидания
и каркас вечного цикла для фоновых рабочих. Какие задачи бывают и что они делают, объявляют
модули-хозяева; модуль о предметах хаба не знает.

## Публичный интерфейс

| Класс | Для чего | Методы |
| --- | --- | --- |
| `ЗадачаПланировщика` (контракт) | регулярная задача; реализуют `вход`, `гео`, `зеркала`, `происшествия`, `прокси`, `реестр`, `статистика`, `хранилище` и сам модуль, планировщик собирает их массивом | `Зарегистрировать(Регистрации)`, `Исполнить()` |
| `РегистрацииЗадачи` | имя и срок регистрации задачи: интервал, ежедневно в час, однократно после старта | `КаждыеСекунд(Имя, Секунд)`, `ЕжедневноВ(Имя, Час)`, `ОднократноЧерез(Имя, Секунд)`, `Состав()` |
| `ЗапускВФоне` (контракт) | «запустить и не ждать»; реализация — `ЗапускВФонеЗаданием` | `Запустить(Обработчик)` |
| `ФоновыйЦикл` | вечный цикл фонового рабочего: гейт готовности до входа, защищённый шаг, остановка по просьбе | `Крутить(Владелец, ИмяЗадачи)`, `Остановить()` |
| `РеестрЗаданийПлатформы` | реестр фоновых заданий платформы: размер и уборка | `Размер()`, `Очистить()` |

Задача живёт у своего модуля; спан задачи заводит она сама аннотацией на `Исполнить()`:

```bsl
Процедура Зарегистрировать(Регистрации) Экспорт
	Регистрации.КаждыеСекунд("чистка-чего-то", Интервал);
КонецПроцедуры

&Наблюдаемый("job.something_gc")
Процедура Исполнить() Экспорт
	Служба.Почистить();
КонецПроцедуры

&Прозвище("ЗадачаПланировщика")
&Желудь
Процедура ПриСозданииОбъекта(&Пластилин(Значение = "СлужбаЧегоТо") _Служба,
	&Деталька(Значение = "oshub.jobs.something_gc_interval_sec", ЗначениеПоУмолчанию = 3600) _Интервал = Неопределено)
	Служба = _Служба;
	Интервал = Новый ПриведениеЧисел().ЧислоИлиДефолт(_Интервал, 3600);
КонецПроцедуры
```

Ключ интервала объявляет модуль задачи в своих ключах настроек (`КлючиНастроек<Предмет>`), а не `настройки`.

## Зависимости

Использует: `основа`, `наблюдаемость`; библиотека `os-scheduler`.
Используется: модули с регулярными задачами (см. контракт), `гео`, `почта`, `публикация`, `статистика` (`ЗапускВФоне`),
`зеркала`, `подписки` (`ФоновыйЦикл`), `зеркала` и `состояние` (`РеестрЗаданийПлатформы`).

## Настройки

Ключи объявляет `запуск/КлючиНастроекФоновыхЗаданий`: модуль реестра настроек не зовёт.

| Ключ | Умолчание | Что делает |
| --- | --- | --- |
| `oshub.jobs.enabled` | `true` | включает планировщик |
| `oshub.jobs.tick_interval_ms` | `1000` | шаг опроса расписания |
| `oshub.jobs.registry_gc_interval_sec` | `60` | интервал уборки реестра заданий платформы |

## Где что лежит

| Каталог | Что внутри |
| --- | --- |
| `Классы/` | планировщик (`ПланировщикПриложения` — стартовая рогатка), контракт задачи и её регистрации, журнал задач (`ЖурналФоновыхЗадач`, `ЗадачаПодЖурналом`), запуск в фоне, фоновый цикл, реестр заданий и задача его уборки |

## Инварианты

- Имя регистрации уникально: два одинаковых имени os-scheduler не примет.
- Сбой `Исполнить()` перебрасывается планировщику: статус и повторы ведёт он, строку об ошибке пишет `ЖурналФоновыхЗадач`.
- Задачи регистрируются в порядке имён; состав виден в журнале старта строкой на регистрацию.
- Исход работы, запущенной `ЗапускВФоне`, не смотрит никто: исключение обработчик ловит сам.
