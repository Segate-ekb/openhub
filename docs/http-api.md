# HTTP API

Машинный интерфейс хаба — `/api/v1`: всё, что есть в веб-интерфейсе. Здесь — где взять его
описание, как устроены списки и как выбрать версию под установленный OneScript.

---

## Описание API

Описание в формате OpenAPI 3.1 собирает веб-сервер winow. По умолчанию оно выключено;
включает его `OSHUB_OPENAPI_ENABLED=true` или ключ `winow.openapi.Включено` файла настроек.

| Адрес | Что отдаёт |
| --- | --- |
| `/swagger-ui.html` | страница для человека |
| `/v3/api-docs` | описание в JSON |
| `/v3/api-docs.yaml` | то же в YAML |

- В документе — только адреса под `/api/`. Экраны веб-интерфейса, беспрефиксные адреса
  выдачи и пробы в него не попадают: путь отбирает регулярное выражение ключа
  `winow.openapi.ШаблонПутей`, умолчание хаба — `^/api/`.
- Страница загружает Swagger UI с `cdn.jsdelivr.net`: без выхода в интернет она пустая,
  JSON и YAML отдаются.
- Пробный запрос со страницы идёт с кукой сессии: чтение работает, изменение отклоняется
  с `csrf_failed`. Запросу с токеном доступа в заголовке `Authorization: Bearer <токен>`
  CSRF не нужен.

## Форма страницы

Все списковые ручки `/api/v1/*` отдают страницу — один конверт, одни параметры, один потолок
выдачи.

```json
{
  "items": [ ... ],
  "page": 1,
  "pageSize": 200,
  "total": 37,
  "has_more": false
}
```

| Поле | Что значит |
| --- | --- |
| `items` | элементы этой страницы |
| `page` | номер отданной страницы, с единицы |
| `pageSize` | размер страницы, которым хаб воспользовался |
| `total` | сколько элементов во всём списке, а не на странице |
| `has_more` | за этой страницей есть ещё |

Три ручки кладут элементы в поле со своим именем, остальные поля страницы у них те же:
`GET /api/v1/pools/{pool}/packages/{name}/versions` — `versions`,
`GET /api/v1/pools/{pool}/packages/{name}/tags` — `tags`, `GET /api/v1/tokens` — `tokens`.

## Как листать

Два необязательных параметра запроса: `page` — номер страницы с единицы, `pageSize` —
сколько элементов взять.

```bash
curl -H "Authorization: Bearer $TOKEN" \
  "$HUB/api/v1/pools/corp/mirrors?pageSize=20&page=2"
```

- Номер за краем списка — не ошибка: страница пустая, `total` называет весь список.
  Исключение — поиск `/api/v1/search`: номер за краем он приводит к последней странице.
- Непонятное значение параметра — не отказ: номером становится первая страница, размером —
  умолчание ручки.

## Потолок выдачи

В одном ответе — не больше потолка, по умолчанию 200 элементов. На `pageSize=100000` хаб
отдаёт потолок, и `pageSize` в ответе называет его.

| Ключ | Переменная | Умолчание | Что задаёт |
| --- | --- | --- | --- |
| `oshub.api.page_max` | `OSHUB_API_PAGE__MAX` | `200` | потолок выдачи |
| `oshub.api.page_size` | `OSHUB_API_PAGE__SIZE` | `20` | размер страницы по умолчанию у листающихся ручек |

## Запрос без параметров

- **Листающиеся ручки** — `/api/v1/pools`, `/api/v1/pools/{pool}/packages`, `/api/v1/search`,
  `/api/v1/groups` — отдают первую страницу размером `oshub.api.page_size`.
- **Остальные списковые ручки** отдают список целиком, в пределах потолка. Список длиннее
  потолка обрезается, и `has_more` равен `true`. Скрипту, который не знает о страницах,
  достаточно проверить `has_more`.

## Что страницами не отдаётся

- **Выдача для `opm`** — `/pools/{pool}/download/list.txt` и адреса артефактов: контракт
  клиента `opm`. `list.txt` — плоский список имён в `text/plain`.
- **Срез изменений** `/api/v1/pools/{pool}/changes` — курсорная порционность: `since`,
  `cursor`, `limit` в запросе, `as_of`, `next_cursor`, `has_more` в ответе. Им зеркало
  соседнего хаба идёт инкрементом — [кэширующий прокси](кэширующий-прокси.md#5-реплицировать-набор-заранее-зеркало).

## Поиск по всем доступным пулам

Два адреса без пула выбирают версию по всем пулам, которые запросу позволено читать: с ключом —
и приватные, и личный, без ключа — только публичные. Ключ, привязанный к пулам, открывает только
их, как и у адресов с пулом.

```bash
curl -H "Authorization: Bearer $TOKEN" "$HUB/api/v1/packages/veles-core/resolve?spec=^1.0&engine=2.2.1"
curl -LO "$HUB/api/v1/download/veles-core/veles-core.ospx?spec=^1.0"
```

- В каждом пуле версия выбирается как у пулового `resolve`: тег пула, отозванные, `engine`,
  источники пула-прокси. Из найденных отвечает старшая; при равных — из основного пула, иначе из
  первого по имени.
- `GET /api/v1/packages/{name}/resolve?spec=&engine=` отвечает как пуловый `resolve` и добавляет
  поле `pool` — пул выбранной версии; `url` ведёт на точную версию в этом пуле.
- `GET|HEAD /api/v1/download/{name}/{file}.ospx?spec=&engine=` отдаёт файл той же версии из того
  же пула; с источника привозит только этот пул. Ответ не кладётся в кэш
  (`Cache-Control: private, no-store`): выбор зависит от того, кто спросил.
- Нет ни в одном пуле — 404: у `resolve` с кодом пулового (`package_not_found`,
  `version_not_found`, `tag_not_found`), у файла — `text/plain` с перечнем опрошенных пулов.
  Ни одного читаемого пула — тоже 404.
- Негодный `engine` — 422 у обоих адресов; негодный `spec` — 422 у `resolve` и 404 у файла, как у
  пуловых. Пакета нет ни в одном пуле — `package_not_found` раньше разбора `spec`.

## Версия под установленный OneScript

Адреса артефактов `.ospx` (включая короткие `/download/…` и `/dev-channel/…`) и
`GET /api/v1/pools/{pool}/packages/{name}/resolve` принимают необязательный параметр `engine` —
версию OneScript клиента, например `2.2.1` или `1.0.21.5`.

```bash
curl "$HUB/api/v1/pools/corp/packages/veles-core/resolve?spec=stable&engine=2.2.1"
```

- Где версию выбирает хаб — без спецификации, по имени тега, по выражению версии, — он берёт
  старшую из версий, чей `engine-version` в манифесте не новее `engine`. Версия без
  `engine-version` или с неразбираемым значением подходит любому движку.
- Точная версия (`{имя}-1.2.3.ospx`, `spec=1.2.3`) отдаётся при любом `engine`.
- Пустой или отсутствующий `engine` — выбор без учёта движка.
- Ответ `resolve` содержит поле `engine_version` — требование выбранной версии, пустая строка,
  если манифест его не называет.
- `engine` не разбирается как версия: `resolve` — 422 `invalid_engine`, выдача файла — 422
  `text/plain` с телом `bad request: …`.
- Ни одна подходящая под условие версия не подходит движку: `resolve` — 404 `version_not_found`,
  выдача файла — 404; текст отказа называет причину — версии требуют OneScript новее.
- В пуле-прокси под тот же отбор попадают версии источника, уже известные хабу; версия, которую
  хаб выбрал и привёз с источника, сверяется с `engine` перед ответом.
