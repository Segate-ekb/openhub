# Настройки и переменные окружения

Справочник для того, кто разворачивает хаб: откуда берутся значения, как назвать переменную
окружения, что задаётся до подключения к базе. Пошаговая установка —
[«Развёртывание»](развёртывание.md).

---

## Источники значений

| Источник | Что в нём |
| --- | --- |
| переменные окружения | любая настройка; секреты — только здесь или файлом-секретом |
| `autumn-properties.json` в каталоге запуска | то, что нужно до подключения к базе: порт, база, хранилище, телеметрия |
| база | всё, что правится в веб-интерфейсе, **Настройки хаба** |
| умолчания хаба | всё остальное |

Порядок один для всех ключей: **переменная окружения → файл → значение из интерфейса →
умолчание**. Значение, пришедшее из переменной или файла, в интерфейсе показано как «задано
конфигурацией» и не редактируется. Правка файла и переменных действует после перезапуска.

- Ключ, записанный в файле, переменную не отменяет — даже пустой.
- Пустая переменная (`OSHUB_POOLS_DEFAULT=`) не задаёт ничего и значение из файла не гасит.
  Чтобы сбросить настройку, её убирают из файла.
- Прикладную настройку (ту, что правится в интерфейсе) в файл не кладут: любое непустое
  значение закрепит её и заблокирует поле формы.

Настройки хаба видны карточками на `/hub/settings` вместе с именами переменных окружения.
То же машинно: `GET /api/v1/hub/settings`, поле `env`.

## Имя переменной

Имя выводится из ключа: подчёркивание внутри слова удваивается, точка становится
подчёркиванием, буквы — заглавными.

| Ключ | Переменная |
| --- | --- |
| `oshub.storage.root` | `OSHUB_STORAGE_ROOT` |
| `oshub.pools.default` | `OSHUB_POOLS_DEFAULT` |
| `oshub.admin.password_file` | `OSHUB_ADMIN_PASSWORD__FILE` |
| `oshub.instance.trusted_proxies` | `OSHUB_INSTANCE_TRUSTED__PROXIES` |
| `otel.exporter.otlp.endpoint` | `OTEL_EXPORTER_OTLP_ENDPOINT` |

Одинарное подчёркивание вместо двойного уводит значение в несуществующий ключ:
`OSHUB_ADMIN_PASSWORD_FILE` читается как `oshub.admin.password.file`.

## Псевдонимы

Ключи с кириллицей, дефисом или читаемые библиотекой целым узлом из оболочки не набрать.
Для них — и только для них — есть короткие имена:

| Переменная | Что задаёт |
| --- | --- |
| `OSHUB_PORT` | `winow.Порт` — порт HTTP-сервера, умолчание `3333` |
| `OSHUB_DB_CONNECTOR` | `data.ИсточникиДанных.ТипКоннектора` |
| `OSHUB_DB_CONNECTION` | `data.ИсточникиДанных.СтрокаСоединения` |
| `OSHUB_DB_POOL_SIZE` | `data.ИсточникиДанных.РазмерПула` — предел соединений с базой |
| `OSHUB_LOG_LEVEL` | уровень корневого журнала (`logos.logger`) |
| `OSHUB_LOG_LEVELS` | уровни отдельных журналов: `Имя=Уровень,Имя2=Уровень` |
| `OTEL_ENTITY_QUERY_TEXT` | `otel.entity.query-text` — текст запроса СУБД в спане |
| `OSHUB_CACHE_ARTIFACTS_DIR` | `cache.артефакты.Каталог` |
| `OSHUB_CACHE_ARTIFACTS_LIMIT__BYTES` | `cache.артефакты.Предел` |
| `OSHUB_CACHE_MEMORY_LIMIT__BYTES` | `cache.ПределПамяти` |
| `OSHUB_CACHE_MEMORY_TTL__SEC` | `cache.<кэш>.СрокЖизни` — одно значение на все кэши чтений из базы |
| `OSHUB_OPENAPI_ENABLED` | `winow.openapi.Включено` — описание API, `true` либо `false` |

Сначала решает источник, потом имя: переменная окружения сильнее файла, а внутри одного
источника родное имя сильнее псевдонима. `OSHUB_PORT` перебивает `winow.Порт` из файла;
`oshub.port` в файле действует, только если в файле нет `winow.Порт`. Docker и Kubernetes
передают и имена, которых не пропускает оболочка: `OTEL_ENTITY_QUERY-TEXT=true` — родная
форма ключа `otel.entity.query-text`.

## База данных

| Коннектор | Строка соединения | Для чего |
| --- | --- | --- |
| `КоннекторSQLite` | `Data Source=./data/openhub.db` | личный, командный и небольшой корпоративный хаб |
| `КоннекторPostgreSQL` | `Host=db;Username=openhub;Password=…;Database=openhub;` | нагруженная инсталляция |
| `КоннекторJSON` | `./data/entities` | каталог JSON-файлов без СУБД: разработка, пробы, демо |

MySQL не поддерживается. Схему хаб создаёт сам при первом старте.

Не заданы ни коннектор, ни строка — хаб берёт `КоннекторJSON` и каталог `entities` в корне
данных (`oshub.storage.root`).

**Узел `data.ИсточникиДанных` собирается по листьям.** Переменная окружения сильнее файла
по каждому листу отдельно: родные имена autumn-data (`data_ИсточникиДанных_ТипКоннектора`,
`data_ИсточникиДанных_РазмерПула` и любой другой лист) и псевдонимы `OSHUB_DB_*` ложатся
поверх одноимённых листьев файла, остальные листья файла остаются. Несекретное держат
в файле, строку соединения с паролем — в переменной:

```json
{ "data": { "ИсточникиДанных": { "ТипКоннектора": "КоннекторPostgreSQL" } } }
```

```bash
OSHUB_DB_CONNECTION='Host=db;Username=openhub;Password=…;Database=openhub;'
```

Пара «коннектор, строка соединения» названа родным именем хотя бы одним листом —
`OSHUB_DB_CONNECTOR` и `OSHUB_DB_CONNECTION` из окружения не берутся вовсе. `OSHUB_DB_POOL_SIZE`
от пары не зависит. Кириллические имена годятся для `environment:` в compose; оболочка
(`sh -c`) их выбрасывает, Kubernetes не допускает — там остаётся `OSHUB_DB_*`.

В контейнере коннектор и строку задают переменными: образ сам ставит `OSHUB_DB_*`
([docker/README.md](../docker/README.md#переменные-образа)), и пара из смонтированного
файла не действует, пока её не назвали родными именами.

**С узлом, на котором база не поднимется, хаб не стартует** и называет, откуда пришёл каждый
лист пары (переменная, ключ файла или умолчание), не повторяя строку соединения:

- коннектору СУБД (PostgreSQL, SQLite) не досталось строки соединения;
- строка похожа на строку СУБД (пары `ключ=значение` через `;` или известный ключ СУБД
  первым), а коннектор файловый либо не задан. Каталог файловой базы, в пути которого есть
  и `=`, и `;`, отвергается по тому же признаку;
- у коннектора СУБД строка без единой пары `ключ=значение`;
- узел `data.ИсточникиДанных` в файле записан значением, а не объектом.

Частый случай — запуск из корня репозитория: коннектор `КоннекторJSON` приходит из проектного
`autumn-properties.json`, а строка PostgreSQL — из переменной. Коннектор задают той же
переменной: `OSHUB_DB_CONNECTOR=КоннекторPostgreSQL`.

Коннектор и строка пришли из разных источников — хаб пишет об этом строку уровня
ИНФОРМАЦИЯ, без значения строки.

## Секреты

У настройки-секрета есть парная `…_file` — путь к файлу, который монтируют Docker
и Kubernetes. Значение сильнее файла; перевод строки в конце файла отбрасывается.

| Значение | Файл |
| --- | --- |
| `OSHUB_ADMIN_PASSWORD` | `OSHUB_ADMIN_PASSWORD__FILE` |
| `OSHUB_STORAGE_S3_ACCESS__KEY` | `OSHUB_STORAGE_S3_ACCESS__KEY__FILE` |
| `OSHUB_STORAGE_S3_SECRET__KEY` | `OSHUB_STORAGE_S3_SECRET__KEY__FILE` |

Пароль базы живёт в строке соединения — её передают переменной `OSHUB_DB_CONNECTION`.

## Хранилище пакетов

| Ключ | Умолчание | Что задаёт |
| --- | --- | --- |
| `oshub.storage.backend` | `file` | `file` либо `s3` |
| `oshub.storage.root` | `./data` | корень данных: файлы пакетов при `file`, `аудит.log`, кэш артефактов |
| `oshub.storage.s3.endpoint` | — | адрес S3, любой порт: `http://minio:9000` |
| `oshub.storage.s3.bucket` | — | бакет; хаб его не создаёт |
| `oshub.storage.s3.region` | `us-east-1` | регион подписи |
| `oshub.storage.s3.prefix` | — | префикс ключей внутри бакета |
| `oshub.storage.s3.force_path_style` | `true` | адрес бакета путём, а не поддоменом |
| `oshub.storage.s3.access_key`, `secret_key` | — | ключи доступа, см. [секреты](#секреты) |

При `s3` часто скачиваемые артефакты хаб держит рядом с собой, в файловом кэше
`<oshub.storage.root>/кэш/артефакты` с пределом 1 ГиБ (`OSHUB_CACHE_ARTIFACTS_DIR`,
`OSHUB_CACHE_ARTIFACTS_LIMIT__BYTES`), и отдаёт их из файла кэша потоком, не поднимая в память.
Первое скачивание версии не ждёт корзины: объект качается фоном во временный файл, клиент получает
его по ходу загрузки, а готовый файл со сверенной суммой ложится в кэш. Артефакт тяжелее десятой
доли предела в кэш не ложится и качается так на каждом скачивании. Файл, переставший расти дольше
`winow.ТаймаутОжиданияФайла` (мс, умолчание `30000`), обрывает отдачу. Кэш не переживает
перезапуск: каталог можно держать на временном томе с запасом над пределом.

## Приём пакетов

| Ключ | Умолчание | Что задаёт |
| --- | --- | --- |
| `oshub.publish.max_upload_bytes` | `26214400` | предел тела push, байты |

Предел тела запроса сервера (`winow.МаксимальныйРазмерТелаЗапроса`) хаб поднимает до предела
загрузки с четвертью сверху, чтобы тело сверх предела получало ответ 413 хаба, но не опускает
ниже действующего: переменной `Kestrel__Limits__MaxRequestBodySize`, если её задал оператор,
иначе 30 МБ веб-сервера. Явно заданная `winow.МаксимальныйРазмерТелаЗапроса` сильнее всего.
Предел сервера общий для всех адресов: точки, которые берут тело не потоком (JSON, формы),
читают его в память вплоть до этого предела.

Тело push хаб пишет порциями во временный каталог процесса (`TMPDIR`) и убирает после
публикации: каталогу нужен запас в предел загрузки на каждую одновременную публикацию.
Остальные пределы приёма — в [README модуля `публикация`](../src/модули/публикация/README.md#настройки).

## Кэш чтений из базы

Частые чтения — пулы, источники пулов, наличие учётки, витрину, пакет с версиями, каналами
и счётчиками — хаб держит в памяти в общем бюджете `OSHUB_CACHE_MEMORY_LIMIT__BYTES`
(128 МиБ). Запись через хаб видна следующему запросу; запись мимо процесса хаба (`admin-cli`,
второй процесс) — не позже `OSHUB_CACHE_MEMORY_TTL__SEC` (30 с).

## Журнал

```bash
OSHUB_LOG_LEVEL=DEBUG
OSHUB_LOG_LEVELS=КэшАртефактов=DEBUG,РезолверВыдачи=DEBUG,oscript.lib.autumn-cache=DEBUG
```

Уровень корня задаёт `OSHUB_LOG_LEVEL`, отдельных журналов — `OSHUB_LOG_LEVELS`. Вторая строка
примера включает отладку только кэшей выдачи: промахи, попадания и решения кэша.

## Почта

Письма подтверждения адреса и восстановления пароля хаб шлёт по SMTP. Сервер, порт (587),
пользователь, пароль и отправитель правятся в интерфейсе: **Настройки хаба → Почта**
(ключи `oshub.mail.*`).

## Телеметрия

Ключи — стандартные OpenTelemetry, их читает SDK.

| Переменная | Умолчание | Что задаёт |
| --- | --- | --- |
| `OTEL_ENABLED` | `false` | включает трассы, метрики и логи |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `http://localhost:4318` | адрес коллектора, один на все сигналы |
| `OTEL_EXPORTER_OTLP_PROTOCOL` | `http/protobuf` | протокол экспорта |
| `OTEL_EXPORTER_OTLP_HEADERS` | — | заголовки к коллектору, например `Authorization=Bearer …` |
| `OTEL_SERVICE_NAME` | `openhub` | имя службы |
| `OTEL_TRACES_SAMPLER`, `OTEL_TRACES_SAMPLER_ARG` | `parentbased_traceidratio`, `1.0` | отбор трасс |
| `OTEL_METRIC_EXPORT_INTERVAL` | `60000` | интервал выгрузки метрик, мс |
| `OTEL_TRACES_EXPORTER`, `OTEL_METRICS_EXPORTER`, `OTEL_LOGS_EXPORTER` | `otlp` | `none` выключает один сигнал |

Что хаб шлёт и как это читать — [стенд наблюдаемости](../docker/наблюдаемость/README.md).
