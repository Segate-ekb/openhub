# Разработка

Как поднять хаб из исходников и прогнать тесты.

## Собрать и запустить

```bash
opm install opm       # нужен opm 1.6+
opm install -l --dev  # зависимости из packagedef в ./oscript_modules
oscript src/main.os   # хаб на http://localhost:3333
```

## Тесты

Тесты — [OneUnit](https://github.com/oscript-library/oneunit), лежат в `./tests`.

```bash
opm install oneunit@0.4.1     # один раз
scripts/смоук.sh              # минимум по назначению хаба, ~1 минута
oneunit execute -T внешние    # всё дерево, кроме наборов с внешними системами
oneunit execute               # включая внешние: нужны поднятые MinIO и PostgreSQL
```

Уровни прогона размечены тегами: `хаб` — наборы, поднимающие живой экземпляр,
`внешние` — требующие внешней системы, `смоук` — доказывающие, что хаб работает
по назначению, включая полный цикл `opm push` → `opm install`.

`-T` — это **исключение** набора, а не отбор: `oneunit execute -T внешние` гонит всё,
кроме внешних.

## Демо-стенд

```bash
oscript tools/demo.os                 # поднять наполненный хаб на localhost:3380
oscript tools/demo.os --port 8080     # другой порт
oscript tools/demo.os --keep          # не пересоздавать данные, просто поднять
```

Скрипт поднимает пустой хаб и наполняет его **через тот же HTTP API и те же формы**,
что доступны человеку: пулы, пользователи, права, пакеты, зеркало публичного хаба.
Данные и памятка с учётками — в `./demo` (каталог под `.gitignore`, пересоздаётся
скриптом сколько угодно раз).

Скриншоты в документации сняты с этого стенда.

## Образ

Сборка и запуск контейнера — [docker/README.md](../docker/README.md). Версия живёт
**только** в `packagedef`: ею помечается `.ospx`, ею помечаются тег и метки OCI.

## Что не входит в репозиторий

Каталог требований и процессные документы разработки в поставку не входят и в индексе
git не лежат: описание системы, статусы работ, черновики ишузов в чужие репозитории
и спайки-исследования живут на машине разработчика.
