# Эксплуатация

Работающий хаб: как выставить его наружу, что спрашивать оркестратору, как определяется
страна посетителя, как уведомления выходят через прокси, где журнал аудита и подписки.
Ключи и переменные — [справочник настроек](настройки.md).

---

## Обратный прокси

Хаб принимает соединения по открытому HTTP, настроек TLS у него нет. Наружу его выставляют
только за обратным прокси, который терминирует TLS; там же настраиваются сжатие
и ограничение темпа. Порт самого хаба слушает локальный адрес или сеть контейнеров.

За прокси каждое соединение приходит с адреса прокси. Пока хаб не знает сетей своих прокси,
всё, что он считает по адресу клиента, собирается в одно ведро: ограничитель попыток входа
запирает вход всем разом, в журнале аудита «откуда» — адрес прокси, страна посетителя
не определяется. Сети прокси называет `OSHUB_INSTANCE_TRUSTED__PROXIES`:

```yaml
services:
  openhub:
    environment:
      # сети обратных прокси через запятую, IPv4 и IPv6 вперемешку;
      # пусто (умолчание) — заголовок X-Forwarded-For не читается
      OSHUB_INSTANCE_TRUSTED__PROXIES: "10.0.0.0/8, 2001:db8::/32"
```

- Хаб читает только `X-Forwarded-For`; `Forwarded` и `X-Real-IP` не читаются. Прокси обязан
  дописывать в него адрес, с которого получил запрос: у nginx —
  `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`.
- Адрес клиента — первая справа запись цепочки, не принадлежащая названным сетям. Записи
  своих прокси в хвосте пропускаются, всё левее найденной не читается.
- Сеть записывается и от знакомого адреса: `10.1.2.3/8` — это `10.0.0.0/8`.
- `0.0.0.0/0` делает доверенной всю цепочку: клиента в ней не найдётся, и заголовок
  перестанет читаться.
- Негодная запись списка отвергается при чтении конфигурации с названной причиной.
  Нечитаемая запись в цепочке оставляет адресом клиента адрес соединения; причина — в журнале
  на уровне ОТЛАДКА.

## Пробы

| Адрес | Что значит |
| --- | --- |
| `GET /health` | живость: процесс жив. Отвечает `200` и при недоступной базе |
| `GET /ready` | готовность принимать трафик: `503` до конца старта (`starting`) и при недоступной базе (`database_unavailable`) |

```bash
curl http://localhost:3333/health
# {"status": "ok", "version": "<версия хаба>", "uptime_seconds": 5,
#  "database": {"status": "ok",
#               "pool": {"busy": 0, "free": 1, "waiting": 0, "created": 1, "limit": 10}}}

curl -i http://localhost:3333/ready
# 200 {"status": "ready", "ready": true, "pending": [], "database": {...}}
# 503 {"status": "starting", "ready": false, "pending": ["mirror.синхронизация"], "database": {...}}
# 503 {"status": "database_unavailable", "ready": false, "pending": [],
#      "database": {"status": "unavailable", "pool": {...}, "reason": "…"}}
```

- `pending` — незакрытые стартовые задачи: по нему видно, чего хаб ждёт.
- Раздел `database`: `status` (`ok` либо `unavailable`), снимок пула соединений и `reason`
  у отказа. Снимок — `busy` (соединения у потоков), `free`, `waiting` (очередь), `created`
  (занятые места в пуле, с ним пул сравнивает свой размер) и `limit` (размер пула, `0` —
  без предела). Снимка нет, только когда источник данных закрыт.
- Проба не встаёт в очередь за соединением: исчерпанный пул она видит по снимку и отвечает
  сразу.
- Порт открывается последним, после строки журнала `Стартовые задачи завершены — открываю
  порт`; до неё соединение отклоняется.

Готовность вешают на `/ready`, живость — на `/health`. `/ready` уводит инстанс из ротации,
пока база не отвечает; `/health` перезапуска не просит — перезапуск базу не лечит, а идущий
обход зеркала прерывает. Хаб, поднятый при недоступной базе, `/ready` не проходит
и перезапускается оркестратором по кругу, пока база не вернётся; уже работающий хаб простой
СУБД переживает.

В образ зашит `HEALTHCHECK` на `/ready` ([docker/README.md](../docker/README.md#пробы)).

## Страна посетителя

Хаб определяет страну запроса встроенной базой диапазонов адресов и в момент запроса никуда
не ходит. Пока на хабе нет правила «закрыт в странах» у провайдера входа, база не читается
вовсе. Правило описано в статье [«Вход через провайдера»](вход-через-провайдера.md#4-закрыть-провайдера-для-посетителей-из-страны).

> ⚠ **Файл базы кладут до правила.** Посетитель, чью страну хаб не определил, считается
> пришедшим из закрытой страны. Без базы правило закрывает провайдера всем.
>
> ⚠ **За обратным прокси нужен `OSHUB_INSTANCE_TRUSTED__PROXIES`** ([обратный прокси](#обратный-прокси)).
> Без него адрес клиента — адрес прокси, страна не определяется, и правило закрывает
> провайдера всем. Окно «Страны и доступ» печатает строку «Страна вашего запроса»: «не
> определена» там — повод проверить список сетей.

### Файл базы

База — **DB-IP Lite Country** под лицензией [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/),
без учётной записи. Выпуск — раз в месяц, файл `dbip-country-lite-<ГГГГ>-<ММ>.csv.gz`;
в первые дни месяца выпуска текущего месяца может ещё не быть.

```bash
mkdir -p /var/lib/openhub/гео
curl -sSfL https://download.db-ip.com/free/dbip-country-lite-<ГГГГ>-<ММ>.csv.gz \
  | gunzip -c > /var/lib/openhub/гео/dbip-country-lite.csv
```

Путь по умолчанию — `<oshub.storage.root>/гео/dbip-country-lite.csv`, в образе
`/var/lib/openhub/гео/dbip-country-lite.csv`. Каталог при выключенном обновлении не создаётся —
его заводят руками. Новый файл хаб замечает по размеру и времени изменения и перечитывает
на ближайшем заходе задачи, без перезапуска.

Состояние базы — путь, дата выпуска, возраст, ход сборки индекса — показывает окно
«Страны и доступ» у провайдера входа. Неудачное обновление имеющуюся базу не трогает
и объясняется происшествием на экране администратора: «базы нет», «база не обновилась»,
«база устарела».

### Ключи

| Переменная | Умолчание | Что делает |
| --- | --- | --- |
| `OSHUB_GEO_DB__PATH` | пусто — каталог `гео` в корне данных | путь к файлу базы |
| `OSHUB_GEO_UPDATE_ENABLED` | `false` | разрешает ходить за новым выпуском в сеть |
| `OSHUB_GEO_UPDATE_URL` | `https://download.db-ip.com/free/dbip-country-lite-{ГОД}-{МЕСЯЦ}.csv.gz` | шаблон адреса выпуска |
| `OSHUB_JOBS_GEO__UPDATE__INTERVAL__SEC` | `86400` | интервал захода задачи, не меньше 60 |
| `OSHUB_GEO_HEADER` | `CF-IPCountry` | заголовок страны от обратного прокси; пусто — не читать |
| `OSHUB_GEO_SOURCE__ORDER` | `база-прокси` | кого спрашивать первым: `база-прокси` либо `прокси-база` |

Заголовку страны хаб верит только с соединения из сетей `OSHUB_INSTANCE_TRUSTED__PROXIES`;
с любого другого адреса заголовок снимается с запроса.

Порядок источников — приоритет. Ответ базы «адрес публичный, страна не из наблюдаемых» —
это ответ, поэтому при `база-прокси` заголовок спрашивается, только когда базе сказать
нечего: файла нет, индекс не построен. Чтобы решал заголовок прокси (например, Cloudflare),
а база была запасом, — `прокси-база`.

Страна неизвестна и там, где адрес не публичный: петля, частная сеть, адрес за прокси,
которому хаб не верит.

### Память

Около 2 КБ на диапазон адресов наблюдаемых стран, на время перестройки индекса — вдвое
больше. Россия — около 16 тысяч диапазонов, ~31 МБ, на пике ~62 МБ; пять стран (RU, BY, KZ,
DE, US) — около 145 тысяч диапазонов, ~345 МБ, на пике ~666 МБ. Лимит памяти контейнера
поднимают соответственно.

### Атрибуция

Лицензия CC BY 4.0 требует указать источник: страницы, которые пользуются результатом, —
вход, привязка в кабинете, раздел «Провайдеры входа» — несут ссылку
`IP Geolocation by DB-IP` на <https://db-ip.com>. Ссылка появляется вместе с первым правилом
и загруженной базой.

### Проверка посетителем

Страница `/whoami` показывает посетителю его адрес и страну такими, какими их видит хаб.
Ссылки на неё в интерфейсе нет — адрес дают человеку прямо.

## Уведомления Telegram через прокси

Настройки хаба → «Подписки на события» → блок «Доставка уведомлений»: сервер, порт,
пользователь и пароль прокси для обращений к `api.telegram.org`. Пустой сервер — ходить
напрямую. Правка действует сразу.

- Прокси — **HTTP с методом `CONNECT`** (squid, 3proxy, tinyproxy). SOCKS не поддерживается.
- Прокси действует только на уведомления Telegram. Вебхуки, источники пулов, зеркала, почта
  и объектное хранилище ходят напрямую.
- Ожидание ответа одной отправки — `oshub.webhooks.delivery_timeout_sec` (10 с,
  конфигурацией).
- Пароль прокси — секрет: поле открывается пустым, значение не показывается ни на экране,
  ни в API, ни в журнале. Пустое поле — оставить как есть; стирает значение кнопка сброса.
- Недоступный прокси — обычный отказ доставки: причина в карточке подписки и в журнале,
  задание повторяется по общим правилам подписок.

## Журнал аудита и подписки

Журнал аудита — файл `<oshub.storage.root>/аудит.log`, экран — **Настройки хаба → Аудит**.
Подписки на события (вебхуки, Telegram) заводятся в разделе «Подписки на события» настроек
хаба, пула и пакета.
