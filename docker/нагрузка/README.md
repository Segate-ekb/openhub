# Нагрузочный стенд OpenHub

Комплект, которым хаб доводят до падения и снимают улики. Собран под вопрос владельца
«хаб под нагрузкой неконтролируемо падает — ресурсы или библиотека»; результат разбора —
в `АНАЛИЗ-нагрузка-2026-09-23.md` (файл рабочий, в git не входит).

Стенд — **хаб + PostgreSQL в общем котле памяти на 2 ГиБ**, рядом лёгкий коллектор OTLP
вне котла. Генератор нагрузки живёт на **другой машине**: два ядра стенда делить с ним
нельзя, иначе замер меряет генератор.

## Что нужно на машинах

| Где | Что нужно |
| --- | --- |
| Сервер стенда | docker + compose, **passwordless sudo** (слайс памяти, `journalctl -k`, чтение `/proc/<pid>/fd` чужого процесса) |
| Генератор | **docker** (тянет образ `oha`) и **zip** (сборка `.ospx` для публикаций) |

Без sudo стенд поднимется, но общего котла не будет, колонка `fds_oscript` в замерах
станет `-1`, а строки ядра про OOM-killer не снимутся.

## Из чего состоит

| Файл | Где запускается | Что делает |
| --- | --- | --- |

| [`настроить.sh`](настроить.sh) | сервер стенда | `/setup`, токен, пул, зеркало; шаги `синк`, `состояние`, `пакеты` |

| [`собрать-улики.sh`](собрать-улики.sh) | сервер стенда | **до рестарта**: код выхода, OOMKilled, журналы, котёл, ядро, трассы |

## Адреса и учётка

**Адрес стенда нигде не зашит.** На сервере стенда скрипты ходят на `127.0.0.1:3333`
(меняется `HUB_URL`). На генераторе адрес **обязателен** — скрипт откажется работать
без него, чтобы не бить по чужому серверу:

```bash
echo 'HUB=http://<адрес-стенда>:3333' > ~/openhub-load/цель.env   # один раз
```

Публичный адрес самого хаба (он идёт в сниппеты `opm.cfg`) задаётся переменной `HUB_URL`
для `compose.yaml`; умолчание — `http://localhost:3333`.

**Учётка стенда заводится скриптом:** `настроить.sh` создаёт администратора
`root` / `LoadStand2026` (меняется переменными `ADMIN` и `PASS`) и кладёт **живой токен
доступа** в `стенд.env` рядом с собой, правами `600`. Оттуда его и берут для публикаций:

```bash
ssh <сервер-стенда> 'grep ^TOKEN= ~/openhub-load/стенд.env'
```

⚠ Пароль известен заранее, токен лежит файлом — комплект годится только для одноразового
стенда в закрытой сети, не для инсталляции, до которой кто-то может дотянуться.

## Как поднять

```bash
scp -r docker/нагрузка/* service@<сервер>:~/openhub-load/
ssh service@<сервер> 'chmod +x ~/openhub-load/*.sh'   # если scp потерял бит
ssh service@<сервер> '~/openhub-load/поднять.sh && ~/openhub-load/настроить.sh'
```

⚠ systemd вкладывает слайс по дефису в имени, поэтому котёл живёт по пути
`/sys/fs/cgroup/openhub.slice/openhub-load.slice`, а не там, где его ищут по имени.

## Как нагрузить

```bash
scp docker/нагрузка/нагрузить.sh docker/нагрузка/пул-базы.sh <генератор>:~/openhub-load/

# одна ручка, замер пропускной способности и задержек
ssh <генератор> '~/openhub-load/нагрузить.sh один /health 50 120 проба'

# смесь маршрутов: цели собираются из живого хаба, а не прибиты гвоздями
ssh <генератор> '~/openhub-load/нагрузить.sh маршруты && ~/openhub-load/нагрузить.sh смесь 25 300 C-25'

# порог пула соединений к базе
ssh <генератор> '~/openhub-load/пул-базы.sh / 20 40 60 80 100 120'

# публикации: токен берётся со стенда (см. выше)
ssh <генератор> 'TOKEN=<pat> ~/openhub-load/нагрузить.sh публикации 10 20 F-10x20'
```

Самплер включается сам при `перезапустить.sh <сценарий>`; вручную —
`setsid nohup ./самплер.sh <сценарий> 5 </dev/null >/dev/null 2>&1 & echo $! > логи/самплер-<сценарий>.pid`.

## Как менять режим хаба

`перезапустить.sh <сценарий> КЛЮЧ=значение …` кладёт переменные в `режим-ступени.yaml`
и пересоздаёт только контейнер хаба; файл подставляется вторым `-f` и держится до
следующего запуска. Имена переменных — ровно те, что читает продукт:

```bash
./перезапустить.sh без-телеметрии OTEL_OFF=1
./перезапустить.sh сэмплинг OTEL_TRACES_SAMPLER=traceidratio OTEL_TRACES_SAMPLER_ARG=0.01
./перезапустить.sh чёрная-дыра OTEL_EXPORTER_OTLP_ENDPOINT=http://10.255.255.1:4318
./перезапустить.sh предел-кучи DOTNET_GCHeapHardLimit=40000000
```

`OTEL_OFF` — единственное сокращение комплекта; всё остальное уходит в контейнер под тем
именем, под которым написано, а незнакомый префикс скрипт называет вслух: опечатка
в имени переменной иначе превратила бы опыт в контроль незаметно.

## Где какие числа

| Что | Где смотреть |
| --- | --- |
| память, потоки, дескрипторы, `/ready`, соединения базы, события котла | `замеры/<сценарий>.csv` |
| сводка одного прогона, включая КБ на запрос | `./итог-опыта.sh <сценарий>` |
| улики падения (код выхода, OOMKilled, журналы, ядро, трассы) | `улики/<метка>/` |
| отчёты генератора (rps, p50/p95/p99, коды) | `итоги/<метка>/` на генераторе |
| метрики, доехавшие до коллектора | `curl 127.0.0.1:8889/metrics` на сервере стенда |

Колонка `pg_connections` — «всего/активных» бэкендов базы хаба, без самого самплера.
`10/0` значит «пул выбран, а СУБД простаивает»: слоты держит хаб, а не база, и это
улика, а не норма.

## Чего не делать

- **Не снимать улики после рестарта.** Журнал мёртвого контейнера, код выхода и признак
  `OOMKilled` живут до первого `up -d --force-recreate`. Сначала `собрать-улики.sh`.
- **Не гонять генератор на сервере стенда.** Два ядра там уже заняты испытуемым.
- **Не трогать чужие контейнеры.** На серверах живут посторонние стеки; всё своё носит
  префикс `openhub-load`, и останавливать надо по имени, а не `docker stop $(docker ps -q)`.
