# OpenHub — правила для AI-сессий

Открытый хаб пакетов OneScript. Стек: чистый OneScript + ОСень (autumn) + winow.

Здесь — правила для всех агентов. Правила управляющего (оркестрация, гейты, ревью, STATUS) —
`docs/процесс/ПРОЦЕСС.md`. История — `git log`; живое состояние — `docs/процесс/STATUS.md`;
невосстановимое из кода — `docs/процесс/ЗНАНИЕ.md`; раскладка модулей — `docs/процесс/РАСКЛАДКА.md`;
выкатка — `docs/процесс/ДЕПЛОЙ.md`; ручные правки чужих библиотек — `docs/процесс/ПАТЧИ-БИБЛИОТЕК.md`.
Дат, замеров и хроники сюда не пишут.

⛔ **Рабочая кухня — вне git:** `docs/требования/`, `docs/процесс/`, `issues/`, `spikes/`,
`АНАЛИЗ-*.md`, `scripts/обзор-требований.sh`, `docker/нагрузка/`. В worktree их нет: читают по
абсолютному пути основного чекаута и только те места, которые назвала постановка. Копия одна — беречь.

## Две полосы

| Полоса | Что | Как |
| --- | --- | --- |
| **Микро** | ≤5 файлов, один модуль; интерфейс модуля, желуди, схема данных не меняются | управляющий сам в своём worktree или один агент одним шагом; наборы модуля + смоук; ревью — `/code-review` по дифу; требование и README тем же заходом; сквош в `main` |
| **Трек** | всё остальное | шаги-агенты (реализация → тесты и логи → документы), ревьюер по патчу и отчёту автора; регрессия одна на волну |

## Дисциплина агента

- **Шаг ≤ 100 ходов.** К 80-му ходу — коммит, отчёт файлом, стоп; следующий шаг — новый агент с путём к отчёту.
- **Контекст.** `git diff --stat` и точечный diff; `grep -n … | head`; файлы — диапазонами; логи прогонов —
  `grep`/`tail`. ЗНАНИЕ.md, STATUS.md и РАСКЛАДКА.md целиком не читают — постановка даёт якоря.
- **Прогоны — как можно меньше.** По ходу правки — один файл `oneunit execute -f`; перед коммитом — наборы
  модуля без сквозных; сквозные — один раз в конце шага; смоук — в конце шага, если менялся `src/`. Каждый
  прогон скриптом в свой лог; перед прогоном `pgrep -fl "oneunit execute"`, второй свой прогон в том же дереве
  не стартуют. `--параллельно` и `--время` агенты не используют: при параллельных агентах это умножает нагрузку.
- **Worktree.** Только свой (`isolation: worktree`); бутстрап `cp -a <основной чекаут>/oscript_modules ./`
  (симлинк запрещён: закоммиченный симлинк снёс зависимости в `main`); коммит каждые 5–10 минут; отчёт
  файлом по ходу в scratchpad. После мержа с новой или поднятой `.ЗависитОт` — `opm install -l`.
- ⛔ `pkill` в любом виде запрещён: стенды гасят по PID и поднимают на своём порту. `git stash` в общем
  чекауте не используют.
- ⛔ В `main` — только сквош, сообщение по-русски о сути, без trailers (`Co-Authored-By`, подписи модели)
  ни в каких коммитах. В библиотеках одна правка — один коммит. Запушенную историю без владельца не переписывают.
- Требования меняет только владелец. Названный владельцем способ («средствами X») не подменяют:
  заблокирован — короткий вопрос первой строкой, альтернатива — только предложением.

## Модули

`src/модули` — шесть слоёв. Граница модуля — соглашение (имена классов глобальны), держит её ревью.

| Слой | Модули |
| --- | --- |
| L0 платформа, о хабе не знает | `основа`, `сеть`, `данные`, `наблюдаемость`, `фоновыеЗадания` |
| L1 службы инсталляции | `события`, `аудит`, `настройки`, `происшествия`, `хранилище`, `почта`, `гео`, `уведомления`, `статистика`, `описания`, `протоколAPI` |
| L2 предметы | `реестр`, `права`, `вход`, `прокси`, `зеркала`, `публикация`, `подписки`, `поиск` |
| L3 сценарии | `кабинет`, `состояние` |
| L4 ворота | `api`, `интерфейс` |
| L5 запуск | `запуск` |

- **Ребро только вниз** (вбок в слое — без цикла). `основа` не знает хаба, `данные` — техника доступа к базе без таблиц.
- **Нижнему нужно знание верхнего — контракт-желудь:** класс без `&Желудь` у нижнего; реализация у верхнего —
  `&Желудь` + `&Прозвище("<Контракт>")` (+ `&Порядок(N)`); потребитель — `&Пластилин(Значение = "<Контракт>")`
  или `…, Тип = "Массив")`; без реализации, если теряет смысл, отказывает громко. Нижний сам умеет нужное —
  верхний зовёт его напрямую.
- **Таблица у предмета:** `&Сущность` и `Хранилище*` — в модуле-хозяине; чужое `Хранилище*` — не дверь, соседи зовут службу.
- **Реестры-перечни — из объявлений** модулей-владельцев: `КлючиНастроек<Предмет>`, `КодыПроисшествий<Подсистема>`,
  `ОписанияСобытий<Предмет>`, `Задача<Что>`; шаблон имени обязателен — фикстуры ищут объявления по префиксу.
- **Публичный интерфейс** — то, что зовут соседи: желуди по имени или прозвищу, контракты, службы и сигнатуры. Остальное — внутренность.
- **Имя класса уникально во всём дереве:** одинаковые базовые имена роняют старт; контракт занимает имя, реализация называется по-своему.
- **README модуля** по шаблону: назначение; публичный интерфейс; зависимости; настройки; где что лежит; инварианты; тесты.
- **Сменился интерфейс** (метод, сигнатура, желудь, прозвище, параметр конструктора) — прогон `--с-потребителями`.
- Раскладку проверяют глазами по дифу (РАСКЛАДКА.md). Чаще всего нарушают: каталог называет предмет, а не вид
  класса; подкаталог — по сюжету; в корне `Классы/` разрезанного модуля файлов нет, общее — в `общее/`; разметку
  печатают только кит и `интерфейс`; кит не знает хаба (ни доменных классов, ни слов `пакет`, `пул`, `версия`,
  `тег`); в `интерфейс` — только видимое пользователю; у экрана настроек один хозяин; новый модуль получает
  `tests/<модуль>/` и попадает в обвязки, перечисляющие модули руками.

## ⛔ Правила слоя данных — нарушение отменяет работу

**1. База — только через autumn-data.** Коннекторы не подменяют и не оборачивают, `oscript_modules` не трогают,
сырого entity нет. Одна таблица — один `Хранилище*` с `&ХранилищеСущностей`: заглушки `&МетодЗапроса` и доменные
методы рядом. Выборки строк и страницы — только деривацией; доменный метод зовёт её через Табакерку с собой:
`&Табакерка &Пластилин(Значение = "<своё имя>") _Сам` в конструкторе, `Сам.Достать().ПолучитьПо…(…)` в теле
(прямой самовызов вернёт `Неопределено`, ЗНАНИЕ §5.2). `&Родитель`, `МенеджерСущностей`,
`ХранилищеСущностей.Получить(ОпцииПоиска)`, ручные `ОпцииПоиска` для выборки — нет; выборка, которую имя метода
не выражает, — вопрос владельцу. **SQL — только агрегаты** (COUNT, SUM, EXISTS, группировка) через
`ВычислитьСКоннектором` одной дверью `АгрегатыБазы` (НФТ-ЭКСП-015): текст — из имён `ОбъектМодели`, значения —
одной дверью, фильтр — `ОпцииПоиска`, у каждого агрегата фолбэк на выборку для бэкендов без SQL (`КоннекторJSON`,
`КоннекторInMemory`). `SELECT *`, `UPDATE`, `DELETE` руками — нет. Дефект entity или autumn-data — issue в апстрим.

**2. Дефект доказывают воспроизведением в реальной работе** с описанием «как это увидит пользователь хаба».
Синтетический тест библиотеки в отрыве от продукта — не доказательство и в дерево не берётся.

**3. Миграций нет.** Схему строит авто-DDL entity; изменение модели — правка сущностей. Долг данных одной
инсталляции чинят разово (admin-cli, скрипт), не механизмом в продукте. Индексы не заводят.

**4. Уникальность держит приложение, а не база:** проверка в сервисном слое на любом бэкенде и негативный тест на
дубль. Объявляет уникальность её требование, называя набор-сторож в «Реализации» (`ИСТ-ДОСТ-029` — почта учётки,
`ИСТ-ПУЛ-002` — имя пакета в пуле, `ИСТ-ПУЛ-003` — имя пула).

## Общие правила

- Нейминг — родной осенний (`&Желудь`, `&Пластилин`, `&Рогатка`, `&Напильник`), не killjoy-flavour.
- Markdown — библиотека oscript-md (автор — владелец), свою не писать.
- Среда — OneScript с сайта как есть. В рантайме (`src/`, образ, `docker/`, скрипты запуска) Python нет без
  согласования; в тестах и командах агента — можно.
- Дефект чужой библиотеки не обходят: issue автору с воспроизведением, следствие — пропуском в
  `tests/сквозные/ДефектыБиблиотек_Тесты.os`; обёрток «пока не починят» нет.
- **Публичные тексты** (README корня и модулей, `docs/*.md`, `docker/README.md`, шапки скриптов и workflow,
  `packagedef`) — только текущее состояние: куда смотреть, что делать. Без хроники, дат, решений владельца, чисел
  тестов, рассказов о дефектах и ссылок на кухню. Поведение изменилось — текст тем же коммитом.
- **Код — лучший комментарий.** Шапка модуля — 1–2 строки. Экспортные методы — по стандарту 1С (назначение,
  `Параметры:`, `Возвращаемое значение:`), только контракт. `ПриСозданииОбъекта` не документируют. Неэкспортному —
  максимум строка о неочевидном. Дефекты, риски, питфолы — в ЗНАНИЕ.md; код о требовании не знает.

## Тесты

OneUnit (+asserts). Готово = код + тесты + зелёный CI. Раскладка и фикстуры — `docs/разработка.md`, «Тесты».

| Уровень | Команда | Когда |
| --- | --- | --- |
| один файл | `oneunit execute -f <набор>` | по ходу правки |
| модуль | `scripts/тесты.sh <модуль>` — наборы модуля, без сквозных | перед коммитом шага |
| сквозные | `scripts/тесты.sh <модуль> --сквозные` — плюс линты `tests/сквозные/` | один раз в конце шага |
| смоук | `scripts/смоук.sh` | в конце шага, если менялся `src/` |
| потребители | `scripts/тесты.sh <модуль> --с-потребителями` | сменился интерфейс модуля |
| живые модуля | `scripts/тесты.sh <модуль> --e2e` | шаг меняет экраны или ответы адресов |
| инфраструктура | `scripts/тесты.sh --инфраструктура` | правка `scripts/` или `tests/инфраструктура/` |
| плавающие | `scripts/тесты.sh --плавающие` | управляющий, отдельно, по подозрению |
| регрессия | `scripts/тесты.sh --всё --параллельно N` | одна на волну, управляющий на свободной машине, когда агенты волны остановлены |
| внешние | `scripts/тесты.sh --внешние` + `OSHUB_S3_SMOKE`, `OSHUB_TEST_PG_DSN`, `OSHUB_MIRROR_LIVE` | руками |

Каждый прогон — скриптом в свой лог: шапка `== прогон.*`, итог `== прогон.итог: код 0, коммит <хэш>, дерево
чистое и не менялось`. Ревьюер сверяет лог, а не перегоняет. `<модуль> --список` — что попадёт в прогон.
`--параллельно N` и `--время` — инструменты управляющего на свободной машине, без чужих `oneunit execute`:
корзины выравниваются по таблице `scripts/время-наборов.tsv`, обновляет её управляющий
`scripts/тесты.sh --всё --время --таблица-времени scripts/время-наборов.tsv`.

- Наборы отбирают скрипты файлами: фильтр тегов не доходит до наборов с `&Изолированный(Уровень = "Процесс")`.
  Тег вешается на набор целиком: живому тесту — отдельный набор с `&Тег("хаб")` в `tests/e2e/<модуль>/`,
  offline-проверки — без тега. `смоук` пополняют тегом на существующих методах, своих тестов не заводят.
- Плавающие под нагрузкой — в наборах `*_Плавающие_Тесты.os` (гонка домена зеркал, профиль под нагрузкой):
  из обычных прогонов исключены, гоняются `--плавающие`; перечень и причины — ЗНАНИЕ §6. Красный в батарее —
  перепроверь набор поодиночке; новое имя — находка.
- Фикстуры — через реестр: `#Использовать "../фикстуры"` (из `tests/e2e/<модуль>/` — `"../../фикстуры"`),
  `РеестрФикстур.Подключить("Имя")`. Продуктовые классы — `КлассыСлоя`, корни — `КаталогиПроекта`; набор контракта
  подключает реализации (`КлассыСлоя.ПодключитьРеализации`). Голого `ПодключитьСценарий` в наборе общего процесса
  нет (ЗНАНИЕ §2.1). Имя файла набора и фикстуры уникально в дереве. Ключи настроек едут за классами
  (`РеестрНастроекХаба.ПодключитьКлассы`), чужие объявления — `ПодключитьКлючиМодулей("<модуль>")`.
- Линты `tests/сквозные/` входят в прогон модуля (`СловарьТекстов_Тесты` — русские литералы и ключи словаря,
  слова журнала — литералом первым аргументом `Лог.*`; `ЖурналРасследования_Тесты`; `КаталогСобытий_Тесты`).
  Сменился контракт службы с фейками в `фикстуры/` — набор каждого фейка.
- Сторожа стерегут инвариант, а не форму записи; сканер исходников снимает комментарии и литералы и имеет самотест
  «литерал — не директива»; тест — на то, что ломается у пользователя (страница, форма, ответ адреса), состав дерева
  проверяет ревью по дифу; размер файла не проверяется ничем.
- Регрессия не ходит к чужим серверам: живой тест — в `tests/внешние/`, правило — одной копией в фикстуре
  (`ДоступностьАпстрима`), её сторож — в `tests/инфраструктура/`.
